== Use the published application

Open https://apws.github.io/261007-RunCPM-7xtgv-terminal/[7xtgv-terminal in your
browser]. No compiler, checkout or external terminal is needed. The
link:../../../guides/02-UG-user-guide.adoc#browser-session[User Guide] covers
first commands, display controls and card ZIPs. Save in the guest, Stop, then
download the card before closing or refreshing the page.

RunCPM and 7xtgv-terminal execute locally as C/C++ compiled to WebAssembly.
One shared build supports ES3_35, ES3_5, EP4_10, EC6_147, RP2_147 and RP2_2.
Linux Chromium integration checks cover all six. We report successful
publication on 261012 after an approximately two-minute build, and earlier
standalone use in Chromium, Chrome and Edge.

macOS remains unqualified: our limited Intel MacBook Air check found some
kbd:[Fn] combinations working, kbd:[Alt+Space] unsuccessful and application exit working
only with kbd:[Alt+Esc] rather than kbd:[Alt+Q]. Browser/macOS versions and exact kbd:[Fn]
combinations were not recorded. See the
link:../../../guides/02-UG-user-guide.adoc#browser-compatibility[compatibility notes].
Native Linux/Windows desktop launchers remain a separate route.

The rest of this document is for building, hosting and maintaining the browser
application. Its default local launcher opens the same standalone page; the
retained native-mirror proof is explicitly optional.

== Setup, rebuild and launch

Building requires Bash, Git, Python 3 with venv/pip, CMake, Make and Arduino_GFX
1.6.4 at `~/Arduino/libraries/GFX_Library_for_Arduino`, or an explicit
`XTGV_GFX_SOURCE` library directory. Use a current pthread-capable browser.
Guide printing also requires Asciidoctor 2.x, Poppler (`pdfinfo` and
`pdftotext`), Fontconfig, Liberation Sans/Mono and FontAwesome icon fonts.
The printer embeds the icon font for offline admonition rendering. On Debian/Ubuntu:

[source,bash]
----
sudo apt-get install asciidoctor poppler-utils fontconfig fonts-liberation fonts-font-awesome
----

From `tools-web/`:

[source,bash]
----
./setup.sh
./desktop-rebuild.sh
./desktop-local.sh
----

These are the common entry points for every display: build once, launch once,
then choose targets inside the page. `desktop-local.sh` initially selects ES3_35
at 2x; optional `--target DISPLAY_ID` and `--window-scale N` override those defaults.
No board-specific web build or launcher folder is needed; use these shared
scripts for all six displays.

Rebuild and launch remain separate; neither builds nor uploads MCU firmware.
Launch snapshots the source card without writing it.

`setup.sh` installs Emscripten 6.0.12 and a Python environment under
`build/RunCPM_7xtgv-terminal/desktop-web/_deps/`, not globally. Its aiohttp and
Playwright packages support guide printing, the retained bridge proof and automated checks;
they are not dependencies of the standalone page. The local standalone launcher
uses Python's standard-library static HTTP server only.
Setup also downloads Playwright Chromium. Printing prefers installed
`chromium` or `google-chrome`; set `XTGV_PDF_BROWSER` to an executable path to
select it explicitly, or to an empty string to use Playwright Chromium.

`desktop-rebuild.sh` builds the existing C++ sketch, terminal, storage and real
Arduino_GFX into `desktop-web/shared/`, then packages a static bundle in
`desktop-web/site/`. The console shows build percentages and brief stage/status
messages. Full configure, compiler, linker and packaging output goes to
`tools-web/desktop-rebuild.log`, beside the shortcut.

=== Saved guide PDFs

Local application builds do not print PDFs. After a batch of guide edits, run
`./reprint.sh` from `tools-web/` (or ask for `reprint` in the working session).
It checks the six numbered guides and updates stale prints in `guides/pdf/`.
Console output is brief; detailed output goes to adjacent `reprint.log`. The mobile PDF (mpdf) profile uses
Legal portrait, 140% scale, zero left/right margins and 0.1-inch top/bottom
margins, background graphics and no browser headers/footers. It is optimized
for phone/monitor reading. For physical paper, render the AsciiDoc manually
with A4/Letter, suitable printer margins and a smaller scale.
The editable settings live in link:guide-print-profile.json[guide-print-profile.json];
the JSON manifest below records generated results, not user configuration. Embedded AsciiDoc uses the same content wrapper,
root CSS and keycap/heading JavaScript as Live Preview. Fonts and images are
local; relative document links point to the public repository and TOC links
remain internal. Code listings retain the shared monospace styling without
fetching a syntax-highlighting CDN.

Commit `guides/pdf/print-manifest.json` with the PDFs. It records source and
PDF hashes, print settings and renderer versions. A changed guide refreshes
its PDF; the print profile, shared CSS, JS, guide images or printer code refresh all six.
Missing/edited PDFs are regenerated too. Unchanged reprint runs preserve PDF bytes
and timestamps and need no running browser. Upgrading Chromium alone does
not invalidate reviewed prints; use `--force` when adopting a new renderer.
Pagination can vary slightly between browser/converter versions.

All pending PDFs must pass image, profile paper-size, readable-text and local-link checks
before any saved print is replaced. Printing failure leaves the saved PDFs
intact; details are in `reprint.log`. Every run of the manually dispatched
GitHub Pages workflow explicitly runs `reprint.sh` before building/packaging,
and checks freshness before publication. A printing failure stops that workflow.
Local web rebuilds, normal launch, native desktop/MCU builds and direct site
packaging use the saved files without printing or installing print dependencies.
Thus local packages contain the last saved PDFs until an explicit reprint.

For a refresh, optional preview or freshness check, from the repository root:

[source,bash]
----
src/RunCPM_7xtgv-terminal/tools-web/reprint.sh
src/RunCPM_7xtgv-terminal/tools-web/reprint.sh --output-dir /tmp/guide-preview
src/RunCPM_7xtgv-terminal/tools-web/reprint.sh --check
----

`--check` returns 1 when printing is needed and writes nothing. `--force`
reprints all guides. Saved PDFs remain versioned, so readers can download
them without installing any rendering tools.
Readable frontend sources live in `tools-web/web/`; generated Emscripten glue
and generated key IDs live in build output. Do not edit generated JS.
The ZIP dependency is a pinned local, unminified fflate module with its license.

`desktop-local.sh` packages an isolated site in a `standalone-*` session folder,
opens the default browser and prints its URL. The process serves static files;
it does not relay keys, own guest execution or receive exported card contents.
kbd:[Ctrl+C] in its console ends hosting. Stop/download in the page before closing
if guest changes should be retained. Keep the page visible while using it;
background-tab throttling is not qualified.

To open the same local session on a phone on the same trusted Wi-Fi, run
`++./desktop-mobile-lan.sh++`. Its LAN URL opens the `ES3_35` 480×320 display at 1×,
which fits the phone layout well and leaves room for the touch pad.
The console prints a *LAN URL* containing this machine's detected network
address and port `36341` (to keep the firewall rule stable). Pass `--target`
or `--window-scale` after the script to override the mobile defaults. It uses
HTTPS because mobile browsers require a secure context for the threaded
RunCPM worker; the COOP/COEP isolation headers alone are not enough for an
ordinary HTTP LAN address. The desktop-only `desktop-local.sh --lan` remains
HTTP; use `127.0.0.1` on that same computer for its secure localhost context.

The first mobile launch creates a private local certificate authority under
`~/.local/state/7xtgv-web/lan-certificate/` and prints its certificate path and
SHA-256 fingerprint. Transfer `ca.crt` to the phone, install it as a user CA
certificate in Android's security settings, then open the printed HTTPS LAN
URL. If you use the page's `/lan-ca.crt` download before trusting the server,
compare its fingerprint with the one printed in the terminal before
installation. Android menu wording varies by version. Trust is needed once per
phone; the temporary server certificate is renewed for the current LAN IP on
each launch. Do not share the CA private key (`ca.key`).

LAN mode serves the static site and included starting card without
authentication; stop it with kbd:[Ctrl+C] when finished. The default desktop
launcher remains loopback-only.

== Using the page

On wide windows the 364-pixel controls column sits on the left, a compact
*Guides* column in the middle, and the native-sized display on the right.
*Hide guides* / *Show guides* in Controls toggles the middle column; it starts
visible each time the page loads. Narrow windows stack display, controls and
guides. Screen text expands below the workspace; the canvas is never stretched
to fit. A 1280-pixel window is not a minimum for the page.

The page heading and browser tab identify *RunCPM 7xtgv-terminal*. Guides lists
the six guides in their established order, without visible numbering: PDF opens the packaged print, while ADOC opens the rendered
GitHub guide on `main`. GitHub Raw pages can be rendered with the linked
Asciidoctor.js extension; the note below the list links our shared CSS and JS.
The quickstart starts with clear/exit, backlight and profile shortcuts, followed
by prefix history with Up/Down, the linked named prompt,
`ll /`, `ll ..`, `ll`, `ls`, and `cd /x` / `cd /x/area`.
Packaging copies the six numbered AsciiDoc guides and the available prints
from `guides/pdf/`; a missing PDF has an
unavailable badge instead of a broken link. All six guides now have saved PDFs;
the web rebuild maintains them as described above. Private source
directories are not packaged. Keycap CSS is extracted at build time from
`asciidoctorjs-crx-mixworx.css`, including the lighter modifier backgrounds.

Choose *Target*, then *Switch target*. This saves the current memory card and
restarts RunCPM with that board configuration; save guest application work first.
No rebuild or page reload is needed. The selected board uses its own INI section,
geometry and backlight table. Display scale stays as selected; use 1x for EP4_10.
`--target` also selects the initial display ID or board identifier. Unknown
identifiers are reported instead of silently selecting a different board.

[loweralpha]
. Keyboard capture starts automatically after boot, restart and target switching.
  Click the display or *Keyboard -> display* to return from page controls; repeated
  clicks keep capture active. The green outline means keyboard capture. Click or tap a page control to
  leave display input; kbd:[Ctrl+&#93;] is ordinary guest input. Page buttons/settings and the
  snapshot panel do not send input to the guest.
. Use familiar bank, glyph zoom and brightness chords. kbd:[Alt+Q] exits the
  guest application; it does not close the emulator. Use *Stop* for that.
  Browser/OS-reserved chords may remain unavailable; kbd:[F11] remains browser-controlled; macOS may reserve it.
. Select display scale 1x through 9x. This changes only integer CSS presentation,
  with smoothing off; it does not change panel resolution or terminal glyph zoom.
  Page resizing scrolls/clips rather than stretching. No fractional OS/browser
  scale compensation is applied.
. Open *Screen text* for a frozen snapshot of the complete logical text grid.
  *Refresh snapshot* updates it explicitly. Select/copy text or download `.txt`.
  This is current screen text, not scrollback; pixel graphics belong in PNG.
. Use *Copy image* or *Download PNG* for the published display at its native resolution,
  including graphics and the displayed brightness. Clipboard support/permissions
  depend on the browser; selectable text and downloads remain fallbacks.

The keyboard module sends existing bytes/CSI into the emulated serial input.
C++ retains application/profile/history/INI behavior. Screen copying uses a
small read-only C++ accessor and never changes cells or consumes mirror flags.
No second ANSI terminal implementation is embedded in JavaScript.

The optional number-row conversion starts from `XTGV_HACK_TOPROW` in the shared
host configuration at packaging time. *Keyboard settings* can change it for
this page session; empty disables conversion. It does not edit terminal.conf
or the guest INI. Ordinary text/paste accepts ASCII, Tab and newlines; unsupported
composed text is reported rather than silently transliterated. Existing mapped
key events retain their original byte fallback. Paste is limited to 4096
characters and rejects embedded control/escape sequences. Use kbd:[Alt] for chords;
kbd:[AltGr] stays with text input. Real national-keyboard testing remains necessary.

== Card lifetime

The launcher reads a copy of repository `cpmcard/`, excluding private directories,
symlinks and desktop ownership locks. It never writes or locks the source card.
Take the copy while other writers are idle if a consistent starting image is
important. A host path may be selected with `--card-root /path/to/card`.

The page unpacks the archive into `/card` in MEMFS. All guest file operations,
INI/history saves and new files affect that memory copy. No FAT image, SdFat
block layer, host filesystem passthrough or automatic persistence is involved.

[loweralpha]
. Click *Stop* or use guest `EXIT`, then wait for *Stopped cleanly*.
. Click *Download card ZIP*. The browser downloads it directly; the static
  server does not keep a second copy of the export.
. *Restart current card* starts a fresh runtime with the stopped card.
  *Load card ZIP* replaces it and starts the selected card after stopping.
. To start from an earlier export directly, use the command below.

[source,bash]
----
./desktop-local.sh --card-zip /path/to/cpmcard-web.zip
----

Downloaded ZIPs contain one top-level `cpmcard/` folder, with `A/0/` and the
other card contents inside it. Upload accepts this layout and earlier ZIPs
with `A/0/` directly at the archive root. Mixed roots are rejected. The
browser limits compressed and expanded cards to 32 MiB and 10,000 entries;
invalid paths, duplicate entries and file/directory conflicts are rejected.
Browser ZIP entries are materialized as regular files/directories, not symlinks.

Guest `REBOOT` creates a fresh Wasm instance while preserving MEMFS contents.
Closing/reloading the page discards unexported changes; a browser warning is
best effort, not persistence. Stop is cooperative and finishes pending saves.
A busy guest can also be stopped through the page control.

== Static hosting and deployment boundary

`desktop-web/site/` contains the page, readable frontend modules, pinned local
ZIP module, generated protocol IDs/defaults, shared keycap CSS, numbered guide
sources/available PDFs, Wasm/glue and preload `card.zip`.
It may be served by another static host supporting these response headers:

[source,text]
----
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
----

Use HTTPS, or localhost for local development. The worker needs cross-origin
isolation/SharedArrayBuffer; double-clicking `index.html` with `file://` is not
supported. Clipboard access also requires a suitable secure context.

No SDK, Python guest bridge or native terminal is needed by a deployed page.
The local Python launcher is just a convenient packager/server. Package only a
card whose contents you intend to serve; no site is published by these scripts.
Input, snapshots and ZIP export work without the server after assets have
loaded. A fresh runtime/reload may fetch Wasm/glue again, so this is not an
installed offline application or a service-worker cache.

=== GitHub Pages package

After the normal setup and shared rebuild, run from `tools-web/`:

[source,bash]
----
./pages-package.sh
./pages-preview.sh
----

The deployable files are in
`build/RunCPM_7xtgv-terminal/desktop-web/pages/`, outside Git. Packaging replaces
that generated folder. Preview serves its own immutable copy under `/preview/`
and deliberately omits isolation headers, to exercise the Pages startup path.
Use `--no-open` to print the URL without opening a browser.

The preload ZIP comes from *committed* `cpmcard/` at Git `HEAD`, including its
committed INI/history; uncommitted card changes are not published. All drive/user
directories A–P/0–F are created in the ZIP, including empty ones Git cannot
store. Directories named `private` and runtime card locks are excluded.
`package.json` records the card commit and every packaged file's SHA-256.
Local packaging uses the current frontend and previously built Wasm; rebuild
first after C++ changes. CI builds everything from its selected checkout.

Pages cannot set our required response headers. A small, readable service
worker adds them to responses within this site's path. On the first visit,
the page installs it and reloads once *before* loading Wasm or creating the
guest card. Returning visits normally boot directly. A worker update waits
for existing tabs to close; it never forces a running guest to reload.
HTTPS and service-worker/SharedArrayBuffer support are required. Browser modes
that block these facilities show a startup error. There is no service-worker
asset cache, automatic card persistence or upload to the server: download a
changed card before closing or refreshing the page.

==== Deployment

The repository workflow `.github/workflows/pages.yml` is manual-only:

. Commit and push the intended source/card revision.
. Once, in GitHub *Settings → Pages → Build and deployment*, choose
  *GitHub Actions* as the source.
. In *Actions → Browser emulator Pages → Run workflow*, select `main` (or
  another revision permitted by the `github-pages` environment).
. The workflow checks Pages configuration first, then installs the pinned SDK and verified Arduino_GFX 1.6.4,
  rebuilds the shared runtime, packages the card and runs the headerless
  Chromium proof. Only a successful build/test proceeds to deployment.

Only `desktop-web/pages/` is uploaded as the Pages artifact. The SDK, build
logs, test sessions, local files and the rest of the repository are not part of
the deployed site. Generated binaries stay out of Git; no `gh-pages` branch
or generated site in the repository's `docs/` is needed. The public download
does include all committed card files, alongside runtime/frontend assets and
license notices. Loading a private ZIP in the page remains browser-local.

The published entrance is
https://apws.github.io/261007-RunCPM-7xtgv-terminal/[7xtgv-terminal].
The deployment job reports its final URL, including any custom-domain change. Local packaging/preview never enables Pages or publishes anything.
The first GitHub run passed compilation and the browser proof but failed at
Pages configuration because the build job lacked `pages: read`. The corrected
workflow grants that read permission and checks configuration before building;
the deployment job alone has `pages: write`. We subsequently confirmed
successful publication on 261012 after an approximately two-minute build.
This is a deployment report, not full browser/OS or keyboard qualification. Rerunning an old failed run uses its old workflow: after a fix is
pushed, use *Run workflow* on the updated `main` instead.

See GitHub's https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages[custom Pages workflow documentation]
and the link:../../../docs/261012-1812%20DONE%20GitHub%20Pages%20package%20and%20manual%20deployment.adoc[implementation checkpoint].

== Retained native-mirror proof

[source,bash]
----
./desktop-local.sh --native-mirror --window-scale 2
./desktop-local.sh --native-mirror --mirror kitty
----

This explicitly selects the original Konsole/Kitty + Python TCP/WebSocket
bridge. It needs the normal native mirror prerequisites and the setup venv.
Here the browser is passive, mirror quit uses kbd:[Ctrl+&#93;] then unshifted kbd:[q],
and the bridge retains raw input/output and exported ZIP evidence. Closing
its page releases that bridge. These are properties of the retained proof,
not the default standalone route.

== Logs and automated checks

`desktop-local.sh` shows preparation, the ready URL and shutdown status. Full
launcher output, HTTP requests and browser-launch diagnostics go to
`tools-web/desktop-local.log`, beside the shortcut; the optional native-mirror
route uses the same log. Both shortcut logs are replaced on each invocation.
Failures return a nonzero status and point to the log without dumping it.
Standalone session folders contain
the static site/card copy and URL metadata. Guest output is accessed through
screen snapshots; there is no continuous raw terminal log by default.
