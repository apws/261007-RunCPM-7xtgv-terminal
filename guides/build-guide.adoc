= RunCPM 7xtgv-terminal: Build Guide
:leveloffset: +1
:source-highlighter: highlight.js
:toc:
:toclevels: 2

Start on Linux with the desktop emulator; no physical board is needed.
It runs the integrated RunCPM/terminal and real Arduino_GFX drawing code using
your chosen board's display definition. The current terminal is a development
testbed for *7xtgv-native*, not the completed native engine.

The scripts work without Codex or any AI service. Arduino IDE is optional.
The workflow below follows the current setup and launcher tools; remaining
fresh-machine and hardware qualification limits are listed separately.

[[quick-start]]
== First desktop run

=== 1. Clone

You need Git and repository access before running its setup script.
From the directory where you keep projects:

[source,sh]
----
git clone https://github.com/apws/261007-RunCPM-7xtgv-terminal.git
cd 261007-RunCPM-7xtgv-terminal
----

* Use a new destination if that directory already exists; do not overwrite a checkout.
* A clone includes committed `cpmcard/` files, not another machine's
  uncommitted settings or physical SD card.
* RunCPM-derived sources are already included. Do not clone upstream RunCPM
  over them; no RunCPM submodule step is needed.
* Generated binaries are not included: build before the first launch.

=== 2. Run explicit setup

From the repository root, as your *normal user*, not through sudo:

[source,sh]
----
./src/RunCPM_7xtgv-terminal/tools/setup.sh --dry-run
./src/RunCPM_7xtgv-terminal/tools/setup.sh
----

The first command only previews; the second asks before installing.

* Detects Arch-family distributions, Debian/Ubuntu or Fedora.
* Installs system tools, desktop C++/CMake/SDL2 support, Arduino CLI,
  and pinned cores/libraries for all six boards. There is no desktop-only setup mode.
* Uses sudo for system packages, but installs Arduino components as your user.
  If sudo is absent, have an administrator install/configure it first.
* Does not upgrade the whole system, build, flash or populate a card.
* Offers USB serial-group access separately; desktop-only use does not need it.
* Konsole and Kitty are optional and are not installed by setup. With neither,
  the mirror uses your current terminal through tmux.

Arch-family use has been exercised. Debian/Fedora package selection has offline
tests, but real fresh-machine installation remains unverified. The complete
clean-clone gate is still pending; see <<clean-clone-acceptance>>.
Windows, macOS and WSL are not validated launcher paths.

=== 3. Open a board folder

The full launcher parent path, relative to the repository root, is
`src/RunCPM_7xtgv-terminal/tools/targets/`.
Choose a display ID, even for desktop use:

[cols="1,1,3",options="header"]
|===
|Vendor |Display ID |Folder under that path
|WAVESHARE |`EC6_147` |`++EC6_147 -- esp32c6-lcd-1-47++`
|GUITION |`EP4_10` |`++EP4_10 -- jc8012p4a1c++`
|GUITION |`ES3_35` |`++ES3_35 -- jc8048w535++`
|GUITION |`ES3_5` |`++ES3_5 -- jc8048w550++`
|WAVESHARE |`RP2_147` |`++RP2_147 -- rp2350-lcd-1-47-a++`
|WAVESHARE |`RP2_2` |`++RP2_2 -- rp2350-touch-lcd-2++`
|===

For example, from the repository root:

[source,sh]
----
cd "src/RunCPM_7xtgv-terminal/tools/targets/EP4_10 -- jc8012p4a1c"
----

Each shortcut already selects its board; no `terminal.conf` edit is needed
to choose the target for these shortcuts.

[cols="1,3",options="header"]
|===
|Script |Action
|`desktop-rebuild.sh` |Build this board's Linux desktop executable; no MCU access.
|`desktop-local.sh` |Launch its last desktop build with repository `cpmcard/` and a mirror.
|`desktop-card.sh` |Launch its last desktop build with an explicitly selected mounted SD/USB card and a mirror.
|`rebuild.sh` |Build and stage fresh firmware for the physical board; no upload.
|`reflash.sh` |Upload staged firmware and restore the mirror; no build.
|`mirror.sh` |Attach to the physical board; no build or upload.
|===

In *Midnight Commander*, execute the script normally. In *Double Commander*,
use *Shift+Enter* to launch with a terminal. Keep folder spaces quoted in shell paths.

=== 4. Build, then launch

From the chosen board folder, execute these separately:

[source,sh]
----
./desktop-rebuild.sh
./desktop-local.sh
----

* Wait for the build to finish successfully before launching.
* The SDL window is the board-sized display; *type into the mirror*.
  The mirror shows the complete logical terminal, even when the panel is panned.
* `VTINFO` at the CP/M prompt reports the running module, build and geometry.
* After changing source, rebuild again. Launch never silently recompiles.

IMPORTANT: A normal desktop run is *read/write*. Guest applications and
INI/history autosaves can modify versioned files in `cpmcard/`.
For experiments, use a prepared copy via `--card-root`; see <<card-selection>>.

For everyday controls and examples, continue with the
link:user-guide.adoc[User Guide]. For automation and headless tests, use the
link:../src/RunCPM_7xtgv-terminal/desktop/README.adoc[developer desktop guide].

[[card-selection]]
== Select the card and close the desktop safely

=== Local working card or disposable copy

`desktop-local.sh` defaults to repository `cpmcard/`, independent of the shell's
current directory. `XTGV_CARD_ROOT` overrides that default; an explicit
`--card-root PATH` takes precedence. For a separately prepared copy:

[source,sh]
----
./desktop-local.sh --card-root /absolute/path/to/my-cpm-test-card
----

The directory must already contain `A/0`. The
link:../cpmcard/README.adoc[card guide] describes an export helper which copies
the complete working card to a new destination. Stop writers before copying.
No launch copies, synchronizes or normalizes card content automatically.
Use uppercase guest filenames on case-sensitive host filesystems.

=== Mounted SD/USB card

From the board folder, run `./desktop-card.sh` and enter the mount path,
or pass it explicitly:

[source,sh]
----
./desktop-card.sh --card-root "/run/media/$USER/RunCPM"
----

That is an example mount path, not an automatically detected reader.
Selection order is `--card-root`, then `XTGV_DESKTOP_CARD_ROOT`, then an
interactive prompt. The path must be an actual mounted filesystem root
containing `A/0`; an ordinary directory or stale unmounted path is rejected.
Without an interactive terminal, supply the path explicitly.

=== Session ownership and shutdown

* Do not run two writers against the same card tree. Local and physical cards
  are independent copies; there is no automatic synchronization.
* Close the owning mirror or SDL window, or use guest `EXIT`, to stop the
  desktop session. Wait for shutdown before unmounting/removing the card.
* Guest `REBOOT` restarts the desktop process and mirror; `REFLASH` cannot
  invoke a hardware uploader from a desktop session.
* Desktop mirrors use isolated sessions, separate from hardware `7xtgv-cpm`.
* SDL requests always-on-top but can be minimized. Clicking it or using
  Alt+Tab can take keyboard focus: reselect the mirror to type.
* SDL backlight is a compensated brightness simulation. It does not establish
  physical luminance, MCU speed, SPI bandwidth, panel timing or electrical behavior.

Before pulling updates into a used checkout, close its desktop session and
inspect `git status --short`. Preserve wanted local card changes; do not reset
them merely to make Git accept a pull.

[[hardware-workflow]]
== Build and flash physical hardware

Choose the folder for the *connected physical module*. From that folder:

[source,sh]
----
./rebuild.sh
./reflash.sh
----

* Rebuild needs no device. It stages a fresh candidate under that target's `new/`.
* Reflash uploads existing `new/`, falling back to `current/` only if `new/`
  is absent. An old `new/` is still old firmware: check the embedded build stamp.
* Upload stops the shared hardware mirror, restarts CP/M and loses running
  application state. The workflow attempts to restore the visible mirror afterward.
* Neither command promotes the candidate to `current/` or changes `terminal.conf`.
* Confirm boot `Build`, module identity, storage and the CP/M prompt; use
  `VTINFO` if needed. Upload success alone is not a hardware test.

=== Connection prompts and target guards

[cols="1,3",options="header"]
|===
|Family |What to do
|ESP32 |Normally upload over the running serial connection. If no serial device is found, the script asks you to connect the named module and press Enter.
|RP2350 |Connect in BOOTSEL mode. One eligible BOOTSEL disk already present skips the prompt; otherwise the script asks you to connect it in BOOTSEL and press Enter.
|===

* ESP32 firmware identity mismatches block upload. Resolve board/target
  selection; never bypass a known mismatch.
* Only intentional first installation or recovery of unidentified ESP firmware
  uses `--allow-unidentified-target TARGET`, with the exact long target ID.
  Normal launchers do not supply it automatically.
* RP2350 checks the chip family and staged UF2 target. The ROM cannot identify
  which display is attached: verify the physical module yourself.
  More than one eligible disk needs an explicit `--chip-id HEX16` selector.
* EC6_147 does not normally need BOOTSEL. If upload reset leaves its panel
  blank, press hardware RESET; this recovery note is also in the upload log.

For ambiguous serial selection, specify the actual device, for example
`./reflash.sh --port /dev/serial/by-id/YOUR-DEVICE`.
Do not assume `/dev/ttyUSB0` identifies the board: some target defaults
use generic port names. Never open two readers on the same serial port.

=== Mirror without reflashing

From the same board folder:

[source,sh]
----
./mirror.sh
----

This attaches without rebuilding, uploading or deliberately resetting CP/M.
Unlike reflash's missing-device prompt, mirror-only discovery can stop with
an error: connect the module or specify `--port DEVICE`, then retry.
The shared hardware session is `7xtgv-cpm`; do not reuse a stale session
from a different board. Ending a hardware mirror does not itself stop CP/M;
ending the owning *desktop* mirror stops that emulator.

=== USB permissions

From the repository root, with the device connected:

[source,sh]
----
./src/RunCPM_7xtgv-terminal/tools/setup.sh --serial-only
----

This skips dependency installation and offers device-group access separately.
Use a fresh login after group changes so all applications see the membership.
The mirror can enter already-configured group membership through `newgrp`,
or request a temporary user ACL when needed. An ACL may disappear
when USB recreates the device node. None of this is needed for desktop PTYs.

=== Firmware is not the card

Flashing does not install CP/M programs or copy `cpmcard/` onto an SD card.
Use RunCPM's FAT layout: drive A/user 0 is `A/0`; user directories are
hexadecimal `0`--`F`, under drives `A`--`P`. See the
link:../cpmcard/README.adoc[working-card guide] before preparing a card.
Do not overwrite a working card's INI/history with an older repository copy.

VTPUT/VTGET transfer requires the helpers already on the card; it is not a
blank-card bootstrap. Building firmware does not require reassembling guest
COM files. Changed guest sources have separate build/install steps and assembler
dialects; see the link:reference-guide.adoc[Reference Guide].

== Quiet output, logs and optional switches

* Rebuild/reflash and desktop shortcuts show concise steps. Full compiler,
  uploader, image/card paths and section delimiters are in same-named `.log`
  files beside those scripts, replaced each run. Save a log before rerunning
  if you need earlier evidence. `mirror.sh` does not create a matching log.
* Failures report a short reason. If upload was blocked, the existing firmware
  remains; a newly opened mirror is not proof that new firmware was flashed.
* Rebuild/reflash and desktop shortcuts accept `--dry-run` for a read-only
  workflow preview. Desktop launch previews still validate the chosen card path.
  `mirror.sh` has no dry-run option; use `--help` without opening a connection.
* Hardware `--verbose` exposes live compiler/uploader output. Desktop shortcuts
  stay quiet; use their log or the developer CLI for diagnostics.
* Reflash, mirror and desktop launch accept `--mirror terminal`,
  `--mirror konsole` or `--mirror kitty`. Automatic selection prefers Konsole,
  then Kitty when a GUI session is available, otherwise the current terminal.
* Missing tools are reported, not installed behind your back. Run explicit setup
  for dependencies; investigate source errors separately.

[[optimization]]
== Optional optimization selection

Defaults are the starting point: desktop uses `-O2` with debug symbols;
hardware retains each profile's measured/default setting.
To experiment, from a board folder:

[source,sh]
----
./desktop-rebuild.sh -O2
# Separate hardware build, only if wanted:
./rebuild.sh -Os
----

* Accepted levels: `-O0`, `-Og`, `-O1`, `-O2`, `-O3`, `-Os`.
  The longer forms `--optimization O2` and `--optimization default` also work.
* Selection applies only to that build invocation. Omission restores defaults;
  reflash and launch use the existing artifact and reject optimization options.
* Hardware overrides affect compiled sources, not precompiled SDK archives.
  Unoptimized/debug firmware can exceed MCU memory; O3 is not always faster.
* Benchmark correctness and speed before adopting a hardware override.

== Prerequisites and manual setup details

Use `setup.sh` first. This inventory is for diagnosing missing components or
preparing a machine manually, not an extra sequence after setup.

[cols="1,2,3",options="header"]
|===
|Use |Requirements |Source/check
|Common host tools |Linux, bash, Git, Python 3; use Python 3.10+ for desktop |No project pip environment needed by basic build/mirror tools.
|Desktop compiler |C++17 compiler, CMake 3.19+, build tool (setup installs make), pthreads |SDL2 development headers/library or compatible SDL2 package.
|Desktop drawing |GFX Library for Arduino 1.6.4 |Default `$HOME/Arduino/libraries/GFX_Library_for_Arduino`; override build with `--gfx /path/to/library` if your sketchbook differs.
|Firmware compiler |Arduino CLI |`ARDUINO_CLI`, PATH, or `$HOME/.local/bin/arduino-cli`; board packages provide cross-compilers/SDKs.
|ESP32 firmware |Arduino-ESP32 3.1.0 |All four ESP32 profiles pin this version and package index in `sketch.yaml`.
|RP2350 firmware |Arduino-Pico 5.4.4 |Both RP2350 profiles pin this version and package index.
|Firmware libraries |GFX Library for Arduino 1.6.4; SdFat 2.3.0 |Pinned in each profile; global installation alone does not prove profile resolution.
|Mirror |tmux and an interactive terminal |Konsole/Kitty optional; desktop display additionally needs a graphical session.
|Hardware upload |USB data cable, serial permissions; board-package tools |RP2350 also uses findmnt/udisksctl for BOOTSEL discovery/mounting.
|Guest/helper development |Appropriate 8080/Z80 assembler or BASIC environment |Not needed to use supplied COM files or compile firmware.
|Manual rendering |AsciiDoc renderer or browser extension |Optional; see repository README for browser viewing.
|===

Native desktop builds do not use MCU cores, SdFat hardware drivers or USB
upload tools, even though combined setup installs them. They compile the real
GFX library plus the project's host storage adapter.

=== Setup behavior and versions

* `setup.sh` uses `/etc/os-release`: exact `ID`, then ordered `ID_LIKE` families.
  Arch uses pacman; Debian/Ubuntu uses apt-get; Fedora uses dnf.
  Unsupported families stop before installation.
* Debian refreshes package indexes; no branch performs a full system upgrade.
* Existing Arduino CLI is reused. If absent, setup downloads checksummed
  CLI 1.5.0 for Linux x86_64 or aarch64 into `$HOME/.local/bin`.
* The 261004 working-machine observation was CLI `1.5.2-rc.1`
  (`fef6e48df`), not a tested minimum or a reason to require a prerelease.
* `XTGV_ARDUINO_CONFIG` selects an explicit Arduino configuration file.
  A custom sketchbook may require desktop `--gfx` as above.
* `--yes` approves dependency setup, not USB group changes. With it, run
  `--serial-only` separately if hardware access is needed.
* `--with-desktop` remains a compatibility alias: desktop packages are now
  included by default.

Allow network access and several GB of working space. There is no measured
minimum disk/RAM requirement or universal first-build time estimate.
The first profile build may download isolated dependencies even after setup.
Use pinned versions before diagnosing a newer core's API/ABI differences.

For manual installation, the exact package list, indexes and commands are in
link:../src/RunCPM_7xtgv-terminal/tools/setup.sh[setup.sh]; versions/board
options are in link:../src/RunCPM_7xtgv-terminal/sketch.yaml[sketch.yaml].
Do not force-overwrite an existing Arduino configuration.
Useful read-only checks are `arduino-cli version`, `arduino-cli config dump`,
`arduino-cli core list` and `arduino-cli lib list`.
No separate hand-installed ESP-IDF or Pico SDK is part of the normal build path.

[[artifacts-and-low-level-build]]
== Artifacts and low-level build entry points

All paths below are relative to the repository root:

[cols="2,3",options="header"]
|===
|Path |Meaning
|`build/RunCPM_7xtgv-terminal/TARGET/new/` |Successfully staged MCU candidate; `.ino.bin` for ESP32, `.ino.uf2` for RP2350.
|`build/RunCPM_7xtgv-terminal/TARGET/current/` |Separately promoted hardware-accepted image, if one exists.
|`build/RunCPM_7xtgv-terminal/desktop/TARGET/xtgv_desktop` |Native executable for that board; never an MCU upload image.
|===

Here `TARGET` is the long ID after `--` in the folder table, without spaces.
Successful rebuild leaves hardware `current/` untouched. Promotion and archive
recovery are separate developer operations; some low-level recovery options
also upload, so do not treat them as harmless file management.

The hardware shortcut wraps this command, from the repository root:

[source,sh]
----
python3 src/RunCPM_7xtgv-terminal/tools/reflash.py --target jc8012p4a1c --build-only
----

The wrapper reads `tools/targets/*.json` and `sketch.yaml`, preserves platform
flags and supplies target/product/SPI flags plus a fresh `YYMMDD-HHMM` stamp.
A bare `arduino-cli compile --profile ...` omits wrapper-supplied metadata and
is not the supported build recipe. Do not replace the bundled product fork
with upstream HEAD, mix target binaries, or build as root.

For upload, prefer the target `reflash.sh`: it manages the mirror and RP2350
BOOTSEL path. Bare `tools/reflash.py` upload is not an RP2350 recipe.
Developer tests and direct mirror entry points are in the
link:technical-reference-guide.adoc#_build_upload_and_test_boundary[Technical Reference Guide].

== Troubleshooting

[cols="2,3",options="header"]
|===
|Symptom |Check/remedy
|No executable / no staged firmware |Run the matching desktop or hardware rebuild first; clone does not contain build artifacts.
|Old build still running |Rebuild is separate from launch/reflash. Check embedded stamp and running `VTINFO`; a blocked upload did not install the candidate.
|Missing compiler, CMake, SDL2 or Arduino CLI |Run explicit setup; check PATH/`ARDUINO_CLI`. For GFX, verify version/path or use build `--gfx`.
|Core/library download failure |Check network/proxy/CA certificates and disk space; keep pinned versions. Do not change HAL code to fix a download.
|Mounted-card path rejected |Use the mount root containing `A/0`; mount the card first. For an ordinary directory use `desktop-local.sh --card-root PATH`.
|SDL ignores typing |Focus the mirror. SDL is output-only even when its title bar or Alt+Tab gives it focus.
|SDL too large / too dark |Resize the window or choose another board; resizing does not alter logical geometry. Use terminal backlight controls, not mirror colors.
|Missing serial device / permission denied |Check cable, actual port, permissions and competing readers. Use setup's `--serial-only` for group access.
|Wrong board or multiple candidates |Resolve selection explicitly. Do not bypass a firmware mismatch or guess among BOOTSEL disks.
|No graphical mirror launcher |Use `--mirror terminal` with tmux installed. Desktop SDL still needs a graphical session.
|SD failure / CPU halted |Check physical card format/layout, connection and power. Upload does not provision guest files.
|Mirror not restored after upload |Check device re-enumeration/reset, then use this board's `mirror.sh` with the correct port.
|===

[[clean-clone-acceptance]]
== Remaining fresh-machine acceptance

Existing-machine builds, offline installer tests and desktop rendering do
*not* complete this gate. Still required:

. Record a published commit and Linux/Python/CLI versions in a disposable clone.
. Test declared setup on the real distro with empty Arduino data/download/user
  directories and build caches, without private ZIPs or modified local libraries.
. Build all six hardware targets and desktop selections; retain dependency
  logs, effective flags, sizes and remediation steps.
. Confirm target identity and new stamp in artifacts; record download/disk needs.
. Separately check GUI/mirror lifecycle, USB permissions, physical upload and
  initial card preparation. Compiler-only success cannot establish those.

Offline launcher tests use fake installers/temporary fixtures. Native tests
are described in the Technical Reference Guide; skipped dependency tests are
not completed qualification. Physical panel/backlight/SPI/electrical acceptance
remains separate from desktop checks.

=== Dependency-isolation helper

For an intentional download/build test, from the repository root:

[source,sh]
----
# Published checkout and all hardware targets; substitute the desired commit:
./src/RunCPM_7xtgv-terminal/tools/fresh-build.sh --target all --ref COMMIT

# Alternative: current non-ignored working files, NOT published-clone proof:
./src/RunCPM_7xtgv-terminal/tools/fresh-build.sh --snapshot --target esp32c6-lcd-1-47
----

* Downloads checksummed Arduino CLI, installs baseline cores/libraries in empty
  temporary directories and runs the normal hardware build-only wrapper.
* Uses one explicit `XTGV_ARDUINO_CONFIG` for property resolution and compilation.
* `--use-cli PATH` reuses only the executable, not its installed packages/cache;
  `--source URL_OR_PATH` changes clone source. See `--help` for all options.
* Logs/artifacts remain in a new temporary directory. No flash, sudo, device
  access or automatic removal of that directory.
* Requires Linux, bash/coreutils, Git, Python, curl, tar, CA certificates and
  network access already present. It does not install missing OS tools, build
  SDL desktop or simulate an entirely fresh operating system.

A separate machine/VM/container check is still needed. Record test evidence,
not just the existence of this helper, before claiming reproducibility.
