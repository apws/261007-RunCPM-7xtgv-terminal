This is the exact user-visible behavior of the current RunCPM 7xtgv-terminal,
not the proposed native 7xtgv interface. For tasks start with the
link:02-UG-user-guide.adoc[User Guide]; for code and private protocols use the
link:04-TRG-technical-reference-guide.adoc[Technical Reference Guide]. Settings in the live
device INI may differ from compiled defaults and from the local copy.
The link:features_timeline.adoc[Features Timeline] tracks command and file
name changes; syntax below is the current reference.

CP/M commands, terminal profiles, INI settings and output escape sequences
are shared by the browser, physical boards and native Linux/Windows desktops.
Input delivery, host commands and card lifetime differ by route. For first use,
see the link:02-UG-user-guide.adoc#browser-session[browser introduction]; for
native setup, use the link:01-BG-build-guide.adoc#quick-start[Build Guide].

The saved PDF uses our *mobile PDF (mpdf)* profile: Legal portrait, 140% scale,
zero left/right margins and 0.1-inch top/bottom margins, with backgrounds.
It is intended for reading on phones and comfortably enlarged monitor text.
For physical printing, render the AsciiDoc with A4/Letter, normal printer
margins and a smaller scale. See the link:README.adoc#mobile-pdf-guides[guide
index] for the shared profile and regeneration workflow.

[[rg-terminal-operation]]
== 1. Terminal operation

[[starting-the-pc-mirror]]
=== Starting the PC mirror

For hardware on Linux, launch `mirror.sh` in the selected board folder:

[source,sh]
----
cd "src/RunCPM_7xtgv-terminal/tools/targets/EP4_10 -- jc8012p4a1c"
./mirror.sh
----

* Choose the folder matching the connected board; the example is EP4_10.
* This attaches the mirror without rebuilding or uploading firmware.
* For desktop on Linux, use `desktop-local.sh` or `desktop-card.sh` under
  `tools/targets/`. On Windows, use `desktop-local.cmd` or `desktop-card.cmd`
  under `tools-win/targets/`. Each launches the emulator with its own mirror;
  the Windows card launcher requires an explicit `--card-root PATH`.
  Do not attach a hardware mirror to that session.
* See the link:01-BG-build-guide.adoc[Build Guide] for setup, all board folders and
  launcher options.

The lower-level `tools/kon.sh` and `tools/kit.sh` launch the hardware mirror
in Konsole or Kitty. Both attach to the shared 7xtgv-terminal hardware mirror.
Its tmux session (`7xtgv-terminal`) owns the USB serial device.
Do not run a second serial reader beside it.

A USB reconnect can briefly blink the PC screen while a complete terminal
snapshot is redrawn. This mirror-only refresh preserves a retained xterm256
image on the TFT; it does not restart CP/M.

Paths such as `tools/terminal.conf` below are relative to
`src/RunCPM_7xtgv-terminal/`, the sketch directory. The launchers read that shell
configuration file; it is separate from the device INI. `XTGV_TARGET` selects
the hardware target, `XTGV_PORT` its serial node, and `XTGV_TRANSFER_ROOT` the
local transfer-folder root. No second serial reader should run during a transfer.

kbd:[Ctrl+&#93;] then kbd:[q] leaves the host bridge. kbd:[Ctrl+&#93;] followed by kbd:[Ctrl+&#93;] sends a literal kbd:[Ctrl+&#93;] byte to CP/M.

[cols="2,3",options="header"]
|===
|Host setting |Effect
|`++XTGV_TARGET++` |Exact named target selected in `++tools/terminal.conf++`; not inferred from USB identity.
|`++XTGV_PORT++` |Optional serial-port override; absent means target JSON default/discovery. Explicit CLI `++--port++` wins over it.
|`++XTGV_TRANSFER_ROOT++` |Optional local root for VTPUT/VTGET; defaults to `++XTGV_CARD_ROOT++` or this repository's `++cpmcard++`.
|`++XTGV_REFLASH_COMMAND++` |Optional host dispatcher for a guest REFLASH request. Leaving it unset disables automatic flashing.
|===

Host target metadata lives in `++tools/targets/<target>.json++`; the device
INI does not select an uploader target. Restart the mirror after changing
host target or port configuration.

[[_physical_chords_to_internal_controls]]
==== Physical chords to internal controls

`CSI` means ESC followed by `[`. These controls are not CP/M command
strings. Supplied host keymaps deliver them; desktop shortcuts may intercept them.
kbd:[Alt+Q] invokes configured application exit in Konsole, Kitty and Windows Mintty.
Konsole/Kitty retain kbd:[Alt+Esc] as an alias; Windows reserves it for window cycling.
The browser encoder also accepts both, subject to host delivery; the MacBook
observation above found only kbd:[Alt+Esc] working. Both encode `CSI >60v`.
kbd:[Pause] then kbd:[x] is a native prefix alternative, not a browser mapping.

|kbd:[Alt+0] through kbd:[Alt+9] |CSI >20v through >29v |Select profile 0 through 9.
|kbd:[Alt+Space] |CSI >14v |Show selected profile.

Intended kbd:[Alt] use does not imply Konsole can distinguish both kbd:[Alt] keys.

[[_profile_digits_and_reserved_controls]]
===== Profile digits and reserved controls

* kbd:[Alt+0] through kbd:[Alt+9] work with both the main row and numeric keypad.
  The host bridge also recognizes Czech `+ěščřžýáíé` as those row positions.
  Selection briefly displays the `#n name` label.
* kbd:[Alt+Q] and kbd:[Alt+Backspace] invoke the global exit/clear policy, configured as
  `exit_key=escape_alt` and `clear_key=backspace_alt`. Use Left kbd:[Alt]; Right kbd:[Alt]
  (kbd:[AltGr]) belongs to keyboard-layout character entry, not a required second kbd:[Alt].
* These controls and the kbd:[Ctrl+Shift] view controls precede profile bindings
  and are not saved in history.
* Backlight and palette selections persist. Ordinary zoom/pan neither changes
  the INI nor resizes the logical terminal.

[[_emergency_return_ctrlaltc]]
===== Emergency return: kbd:[Ctrl+Alt+C]

* Forces a warm return from an external COM, including in RAW input mode.
  It does not send guest kbd:[Ctrl+C].
* Cancels remaining `$$$.SUB` work and ends plotting without forcing a
  full-screen clear. Unsaved work is lost; open files may be incomplete.
* Does not wait for an application keyboard read, but waits for an active
  host SD operation. A stopped MCU, terminal task or SD driver needs reset.
* Konsole cannot distinguish kbd:[Alt] from kbd:[AltGr] here. If kbd:[AltGr+C] produces
  kbd:[Ctrl+Alt+C] on your layout, it is unsafe during a COM. Verify the chord on
  your host/target before relying on it.

[[rg-applications-and-input]]
== 2. Applications and input

[[application-profiles]]
=== Application profiles

Each of the ten slots starts with the same neutral profile: a `Bank N`
label, inactive navigation bindings, no application commands or input adapter,
no prompt prefixes and no history-clear sequence or retype delay. A slot number
never selects MBASIC, BBC BASIC, TE, Turbo or COMAL behavior.

Application names, key bindings, commands and editing settings belong in their
complete `[bankN]` section in `A0:7XTGVTRM.INI`. The working card currently assigns
0 CP/M, 1 MBASIC, 2 BBC BASIC, 3 COMAL, 4 Turbo Pascal, 5 FAND, 6 DDT, 7 TE,
8 ANSI APP and 9 GENERAL. These are card settings, not compiled assignments.

Move the whole section and change only its heading when renumbering. Define the
application's required keys (or an explicit `input` preset), commands and editing
behavior in that section; omitted settings keep the same neutral fallback in
every slot. A `name` or `on_select` value does not select an application adapter.
There is no bank-to-bank inheritance or application-profile lookup by name.

`[global] ccp_bank=0` explicitly assigns the CP/M shell profile on this card.
If moving that profile, update `ccp_bank` to its new slot as well. Omitted
`ccp_bank`, or `ccp_bank=none`, disables automatic CCP routing and native CCP
recall handling; it does not prevent ordinary typing at the CP/M prompt.

[[_ini_overrides_and_selection_commands]]
==== INI overrides and selection commands

* Every bank is configurable. Empty application commands remain inactive;
  define `on_select` explicitly when a profile should change the CP/M area.
* `on_select` is emitted only when switching at a live CCP prompt, never inside
  TE, Turbo or another application. For example, `cd /b/mbasic\r` selects
  `mbasic(B1)` because CCP executes it; bank numbers do not identify DUs.
* The temporary label restores its saved row and cursor without requiring an
  application redraw. Wait for it to disappear before normal input.
* kbd:[Alt+Space] only shows the label; it never emits `on_select`.

[[histories-banks-and-the-active-line]]
=== Histories, banks, and the active line

There are ten named FIFO histories, each retaining at most 100 entered lines.
Single-character submissions are ignored.

Each entry retains the first 79 text characters: its saved `>` marker makes
an 80-character record, excluding the line ending. This limit applies to every
bank and to loading older, longer entries. Active-line editing still tracks up
to 127 characters; only the retained history is shortened. A later history
save writes the shortened entries, so archive an older BUF separately if its
longer entries are needed.

* Up/Down normally recall entries; profiles may reserve them for the app and
  use kbd:[Alt+Up] / kbd:[Alt+Down] for history.
* Recall first matches the entire text before the cursor against history-entry
  prefixes, ignoring ASCII letter case and retaining spaces and parameters:
  `cd /` selects entries starting with `cd /`, and `cd ` includes the space.
  If no full-prefix match exists, a nonempty word immediately before the cursor
  is tried instead, preserving inline completion such as `10 pr` from `PRINT`.
  A query ending in whitespace stays a full-prefix query; no match leaves the
  line intact. At column zero, recall browses without a filter.
* Filtered recall wraps within the chosen matches and replaces the matched
  prefix or word, preserving the surrounding text and suffix after the cursor.
  It inserts the retained entry exactly, subject to the line-length limit:
  no space is appended or inserted. Spaces already in the entry or surrounding
  text are preserved.
* kbd:[Enter] stores the submitted line, including an unchanged filtered recall
  or a completion within a prefix such as `10 PR`. Merely browsing or
  cancelling a recall does not add an entry.
* An exact repeat of the newest entry in that bank is not appended again.
  This comparison is byte-for-byte, including spaces; it is not global
  deduplication. A recalled older command becomes recent again on submission.
* Spaces/tabs are literal in a full-prefix filter and delimit the word fallback;
  prefer spaces in authored CP/M text.
* kbd:[Ctrl+Shift+Backspace] deletes the selected recalled entry.
* Separate editable keyword lists remain planned, not implemented.

[[_persistence]]
==== Persistence

* Histories live in `++A0:7XTGVTRM.BUF++`; saves follow a quiet period or `++SYNC++`.
* Boot can recover from verified alternate generations.
* Do not edit checksummed history files as text. Preserve backups and use
  checksum-aware tooling for repairs.

Storage transactions and core ownership are described in the
link:04-TRG-technical-reference-guide.adoc#configuration-and-persistence[Technical Reference Guide].

[[_selected_profile_versus_effective_history_bank]]
==== Selected profile versus effective history bank

* Profile selection lasts for the running session; it is not persisted in the INI.
* A recognized RunCPM CCP prompt (`++A0>++`, `++AF>++`, `++A>++`, and similar)
  silently uses effective bank `++#0++` so shell commands stay out of application history.
* The selected bank is used again when the application prompt returns.
* Active-line and cursor colours follow the palette unless explicitly overridden
  by the profile. PAPER's pale-green/mid-green defaults are not fixed across themes.

[[editing-details]]
=== Editing details

The normal terminal is a line model, not a generic editor. It records a line when kbd:[Enter] completes it and can recall it into line-oriented interpreters.

[[_mbasic_two_adapter_choices]]
==== MBASIC: two adapter choices

* `++EDIT n++` enters MBASIC's modal editor; it needs application-specific handling.
* Select `input_adapter=mbasic_native` explicitly for native EDIT operations:
  rubout and kbd:[Space] movement, kbd:[L], kbd:[X] then kbd:[Esc], and kbd:[1] then kbd:[D].
* The working MBASIC profile selects `local_compose`: local kbd:[Left] / kbd:[Right], kbd:[Home] / kbd:[End],
  kbd:[Insert], kbd:[Delete], kbd:[Backspace] and line submission.
* The composer's line-buffer machinery could be reused, but its current
  adapter also recognizes `EDIT n` and bridges MBASIC's modal editor: issue kbd:[X],
  capture the displayed numbered line, then kbd:[Esc] and kbd:[Q] before local editing.
  It assumes compatible kbd:[Backspace]/echo/submission behavior; other applications
  are not qualified by that implementation. It is not a full-screen editor.
* Adapter-owned keys are consumed before their configured bytes are sent; see
  <<profile-loading-and-key-priority,loading order and key priority>>. Changing
  `input` does not disable an adapter. Use `input_adapter=none` for TE/FAND/Turbo
  byte mappings; keep MBASIC's chosen adapter paired with MBASIC.

[[_bbc_basic_visible_prompt_and_retyping]]
==== BBC BASIC: visible prompt and retyping

* Its visible `++>++` prompt identifies the active screen line.
* Ordinary edits are tracked; recalled history uses the configured clear/retype
  sequence. Its controls therefore differ from MBASIC's.

[[_raw_input]]
=== RAW input

* `++## RAW++` bypasses normal profile/history translation for direct application input.
* Use it for diagnostic tools or unusual full-screen programs; return to normal
  input for ordinary command work.
* Direct kbd:[Alt+0] through kbd:[Alt+9] selection leaves RAW mode; previous/next profile
  browsing does not. The RAW toggle can switch it off without selecting another bank.

[[rg-cpm-commands-and-files]]
== 3. CP/M commands and files

[#7xtgv-terminal-cpm-commands-and-user-areas]
=== 7XF shell and user areas

The original RunCPM `++VOL [drive]++` command reads the first printable line
of `++INFO.TXT++` in each existing user area on that drive. It does not read
the `++.7XF++` catalog files used by the extensions below.

This compact reference covers files added or adapted by this project. It does not repeat ordinary CP/M programs and imported language packages; use `++?++` at the CCP prompt for the internal CCP command list. An A0 command is found from other user areas by this RunCPM CCP, while files it creates normally belong to the current DU (for example `++C3>++`).

[[_7xf_prompt_style]]
==== 7XF prompt style

`7XF` is an internal CCP command; there is no `7XF.COM` to install.
The selected style lasts until RunCPM restarts.
`LS`, `LL` and `CD` work without running `7XF`; it changes prompt presentation,
not command availability. There is no dedicated prompt-style INI setting.
To select named prompts on boot, put the single command `7XF` in the card-root
`AUTOEXEC.TXT` (not inside A0). See <<boot-autoexec-and-pending-submit-work>>.

[cols="1,2",options="header"]
|===
|Command |Prompt
|`7XF DD` |Decimal user number, e.g. `A15>`; boot default.
|`7XF DH` |Hexadecimal user number, e.g. `AF>`.
|`7XF D` |Drive only, e.g. `A>`.
|`7XF` or `7XF DN` |Named area, e.g. `/b/mbasic>`; `/b/1>` without an alias. Names are at most eight characters.
|===

[[_listing_and_selecting_areas]]
==== Listing and selecting areas

Slash paths are names for *flat CP/M drive/user areas*, not subdirectories.
Lookup is case-insensitive; displayed names retain their catalog spelling.
`/` is only a drive overview, not a selectable root directory. `CD /B` selects
the remembered B-drive area; `CD /B/MBASIC` selects that named DU explicitly.

[cols="2,3",options="header"]
|===
|Command |Result
|`LS` |Short listing of the current DU.
|`LL` or `LS -L` |Long listing, including sizes and descriptions.
|`LS /` or `LL /` |Nonempty drives, totals and descriptions; LL adds record/DEXT counts.
|`LS ..` or `LL ..` |Populated user areas on the current drive, equivalent to `/A` when on A, `/C` when on C, etc. Does not change DU; empty/catalog-only areas are omitted.
|`LS /A` |Drive A description, then populated areas and their totals.
|`LS /B/MBASIC/*.BAS` or `LS B1:*.BAS` |Files matching CP/M `*` / `?` wildcards in `mbasic(B1)`.
|`LS -O PANE.7XF /B/MBASIC` |Replace `PANE.7XF` in the current DU with that listing; no terminal listing or PAGE pause for this invocation.
|`PAGE 0` |Disable ordinary pauses in LS, LL and `?`.
|`CD` |Report numeric DU and named view, e.g. `B1: /b/mbasic`.
|`CD MBASIC` or `CD /B/MBASIC` |Select a named area.
|`CD /A` |Return to the last selected area on drive A.
|===

* With no dot, a stem `*` spans the extension too: `LS *` lists every file;
  `LS VT*` includes `VTESTS.BAS` and `VTPAL.BAS`.
* This also applies after an area path or `B1:`. An explicit dot keeps normal
  8.3-field matching.
* Files always sort by extension, then filename (case-insensitive); names still
  display as lowercase `name.ext`, without renaming host files. Extensionless
  files come first. This also
  applies to filtered/path listings and `-O` output. Drives/areas retain drive
  letter/user-number order.
* All listing rows clip one column short of the logical terminal width to avoid
  wrapping; a wider logical screen shows more description text.
* `LS -O` captures only that listing, not CD, other built-ins or COM output.
* Area overviews (`LS /A`, `LL /A`, or `..` for the current drive) omit empty
  areas and those containing only `DIR.7XF` and hidden host placeholders.
  A zero-byte ordinary file counts as content. Omitted areas remain accessible
  by DU or catalog alias; direct file listings still show their catalog.

[[_listing_sizes_and_descriptions]]
===== Listing sizes and descriptions

* Short rows show comma-grouped KiB (`k`), rounded up. File descriptions are
  omitted; the current-area heading retains its description.
  Root drive overviews retain drive descriptions in both forms. In area
  overviews, LS omits individual area descriptions; LL includes them.
  A drive's area list starts with that drive's `A0:VOL.7XF` description at
  column 2, in both `LS /drive` and `LL /drive` (also their `..` aliases).
* Long rows show exact host-file bytes, 128-byte record counts, rounded-up
  32-KiB DEXT equivalents and per-file descriptions.
* Drive/area totals sum these values per file. DEXT is an estimate, not an
  actual CP/M directory-entry count; none of these is FAT-cluster allocation.
* Descriptions stay on the same row: file/path column, two-space separator,
  then description. When listing the current area, its heading contains only
  the description, starting at column 2; the prompt already gives its path.
  A different area's heading retains its path and description.
  Width affects clipping, not the choice of a one-line/two-line layout.
* CP/M record writes may already have rounded a host file to 128 bytes.
  Its host-file length is not necessarily the original payload length;
  text `Ctrl-Z` is not a reliable binary end marker.

[[_catalog_files]]
===== Catalog files

[cols="1,3",options="header"]
|===
|File |Format and use
|Each DU's `DIR.7XF` |12-character left-aligned area/file key, one space, description. The first key names the area.
|`A0:VOL.7XF` |Drive letter in column 1, space in column 2, description from column 3.
|`A0:DRV.7XF` |Last selected area per drive, one `/d/name` line per drive. CD reloads it before selection and saves after a new explicit selection.

They do not replace the original VOL command's `INFO.TXT` input.

[[vtterm-benchmark]]
==== VTTERM display benchmark

Run `VTTERM` from the CP/M prompt. The shared command lives in `cpm(A0)`;
its current source is link:../cpmcard/C/1/VTTERM.Z80[VTTERM.Z80] in
`7xtgv(C1)` (`cd /c/7xtgv`). The short assembly program is a launcher:
private port `79h` starts the native test, reports completion and requests
the result. Its small size and old source date do not imply an obsolete
benchmark. The workload is in `terminal_runtime.cpp`; the result formatting
is supplied by the host runtime. Formatting changes require rebuilding that
runtime, with no replacement COM.

Labels use NORMAL and ALT ink names, paired with their actual SGR colour.
ALT means the configured alternative ink, which need not be brighter.
Each item also chooses a random native paper slot 0..3.
The corrected labels and random papers change the workload, so compare runs using the
same benchmark revision.

The test resets the terminal, clears each frame and places 96 coloured text
items per terminal-loop pass, continuing for at least three seconds. Normal
render work between passes contributes to elapsed time. This is a combined
parser/render-loop benchmark, not isolated panel bandwidth, a Z80 benchmark
or USB serial throughput: the fixture feeds the native parser directly.
The last pass ends timing before its subsequent render completes.

Illustrative output:

[source,text]
----
VTTERM native: 27.029 kChars in 3086 ms
  = 8.757 kChars/s (20.591 kB/s)
VTTERM: PASS
----

* The total counts printable fixture characters, shown as `kChars` or
  `MChars` with three decimal places. `ms` is elapsed whole milliseconds,
  without fractional digits or thousands separators. Rates are still
  calculated from the original microsecond measurement.
* `kChars/s` counts those characters per second; `kB/s` also counts the
  fixture's colour, position and reset escape sequences. The per-frame clear
  and final result-position sequences are outside the byte counter.
* `k` means 1,000, not 1,024. Each rate switches independently to `MChars/s`
  or `MB/s` at 1,000,000 units/s. Rates retain exactly three decimal places
  (truncated); commas group thousands in the integer part. Older runtimes
  print microseconds and plain chars/s and B/s.
* `PASS` means the native workload completed. It does not check pixels or
  establish visual correctness. Compare identical geometry, zoom, target,
  mirror/output configuration and runtime build; inspect the display too.

[[boot-autoexec-and-pending-submit-work]]
=== Boot, AUTOEXEC, and pending SUBMIT work

`++AUTOEXEC.TXT++` is a RunCPM convenience, not a standard CP/M 2.2 CCP command. It is a short first-boot command line at the SD-card filesystem root (outside every A0--AF DU). For deliberate startup, it can contain `++SUBMIT STARTUP++`, with ordinary `++STARTUP.SUB++` held in the intended CP/M DU.

`++SUBMIT++` builds the internal `++$$$.SUB++` queue. On boot the CCP can find such a pending queue and resume it; that is useful after interruption but is not a safe way to turn ordinary text prefixed with `++$++` into autorun. If an abandoned queue causes surprising commands after boot, switch to its DU and run `++UNSUB++`. A pending queue takes precedence over `++AUTOEXEC.TXT++`.

=== VTPUT / VTGET from the mirror

[[_local_folder_and_filenames]]
==== Local folder and filenames

* Both directions ask for *DU*, *Source* and *Target*. Target initially copies
  Source and can be edited.
* `c2:` selects local `cpmcard/C/2` (`xterm256(C2)`);
  `AF:` and `A15:` both select `A/F`.
  Matching is case-insensitive. Missing or symlinked DU folders are rejected.
* *DU selects only the local folder.* The device remains in its current
  drive/user. To receive device A0 into local A3, leave CP/M at `A0>` and
  choose Receive with local DU `A3:`.
* Filenames must be supported 8.3 names, without paths. Lowercase input can
  match existing uppercase names; new receive names are uppercase.
* `XTGV_TRANSFER_ROOT` in `tools/terminal.conf` selects another local root.
  The older `XTGV_XMODEM_ROOT` remains a fallback.

[[_editing_and_overwrite_approval]]
==== Editing and overwrite approval

* Use kbd:[Left] / kbd:[Right], kbd:[Home] / kbd:[End], kbd:[Backspace] / kbd:[Delete] to edit; kbd:[Ctrl+U] clears the field.
  kbd:[Enter] submits it. Konsole's encoded editing keys are handled locally.
* Send always asks permission to create/replace the device target; it does
  not probe remote existence. Receive asks only if the local target exists.
* kbd:[Y] proceeds; kbd:[N] returns to Target; kbd:[C] or kbd:[Esc] cancels.
  *kbd:[Enter] is not overwrite consent.*
* A replacement is committed only after the complete download and temporary
  write. A changed destination invalidates earlier approval; new local files
  use exclusive creation.
* The result remains visible until kbd:[Enter] or kbd:[Esc].

[[_bytes_and_profile_recovery]]
==== Bytes and profile recovery

* Bytes, including CP/M record padding, are transferred unchanged. There is
  no automatic text conversion or compression. CLI `--cpm-text` is for
  deliberate external host-text imports.
* Transfers temporarily select profile #9 and RAW input. The profile query
  behind kbd:[Alt+Space] captures the original state first.
* Success and failure both restore the original profile and RAW state,
  without executing `on_select`. Unconfirmed restoration reports an error.
* If CP/M is still running a transfer helper after failure, reset before
  retrying.

[[_protocol_and_logical_width]]
==== Protocol and logical width

VTGET tags each hex row with its record number to reject stale mirrored rows.
The updated host also accepts the old clear-per-record format; old host clients
do not understand the new tagged format. The framing implementation is in the
link:04-TRG-technical-reference-guide.adoc#private-protocol-boundaries[Technical Reference Guide].

Use an 80-column *logical terminal* for transfers. At 40 logical columns,
VTGET's 69-character tagged rows wrap and the download can stall. A 26- or
40-column physical viewport onto an 80-column logical terminal is different
and does not impose that wrapping. RAW input also bypasses normal pan-command
interception; do not use interactive pan as a transfer recovery mechanism.

Before changing the device INI, fetch its current A0 copy with
`tools/fetch-7xtgvtrm-ini.sh` (explicit `--target`/`--port` if needed), edit the
fresh local mirror, then send it with overwrite approval. The helper archives
the previous local copy and replaces it only after a successful fetch. Stop
on fetch failure: an older local INI can overwrite unrelated on-device edits.
See link:../docs/260924-21%20live%20INI%20preservation%20and%20narrow%20transfer%20limitation.adoc[live INI and transfer-width notes].

Guest text in the local `cpmcard/` working tree is maintained as CRLF with a final
`Ctrl-Z`, ready for byte-preserving Send/Receive. No upload conversion is needed.
The CLI text-conversion option is only for deliberate external host-text imports.
Tokenized BASIC, binaries, disk images and checksummed history are not text;
host-only JSON metadata, Markdown readmes and Makefiles retain host format.

*XMODEM is not supported through this reconstructed-screen channel.* Its UI
entry was replaced; CONSOLE8 or RAW input alone does not make it binary-safe.

[[zip-transfer-and-extraction]]
=== ZIP transfer and extraction

Transfer ZIPs as binary, never with `--cpm-text`. The separately installed
`A0:UNZIP157.COM` supports Linux Deflate ZIPs; the old local UNZIP 1.8 does not.
Keep uppercase 8.3 member names. Linux packing example:

[source,sh]
----
zip -9 -j VTFILES.ZIP FILE.INI
----

After transferring the archive, CP/M extraction is:

[source,text]
----

----

The destination enables extraction; without it the program only lists/checks.
Use a disposable user area or nonconflicting names for initial tests.
Automatic compression in the mirror is not implemented. See
link:../docs/260923-20%20CP-M%20UNZIP%20compatibility%20and%20download.adoc[the compatibility test and download record].

[[ini-diagnostics-and-syntax-limits]]
==== INI diagnostics and syntax limits

Boot continues after recoverable line errors and reports
`LOADED WITH ERRORS (n)`. The first ten bad lines are listed in this form:

[source,text]
----
  42: [bank3]: unknown_setting=value
----

Line numbers are one-based and right-aligned in four positions. The report
contains the section and source line, not an elaborate error explanation.
ANSI boot highlights each detail row with red paper; VT52 uses a `***` prefix.
The total can exceed the ten retained details. The same report is written to
`A0:7XTGVTRM.ERR` when storage permits, with CRLF and trailing `Ctrl+Z` (0x1A). A clean
INI load removes a stale ERR file. If no INI is loaded, the banner reports
`COMPILED DEFAULTS`. Application banks are neutral in that case; no application
key map, launch/exit/clear command or BASIC adapter is enabled automatically.

Use one setting per line and comments on separate lines. The line buffer holds
191 characters excluding its terminator; longer lines are diagnosed, not
silently accepted. Physical line breaks count even in comments. `Ctrl+Z` (0x1A) ends
the logical INI, so anything after it is not parsed.

For Boolean settings prefer `true` / `false`. The parser also accepts lowercase
`yes` / `no` and `1` / `0`; it does *not* accept `on` / `off`.
Ordinary setting names and enum values are case-sensitive; use the lowercase
spellings below. Key-chord names are case-insensitive. Global, palette and
display section recognition is case-insensitive, but keep `[bankN]` lowercase.

Duplicate explicit key bindings are errors; ordinary scalar settings are not
covered by that duplicate check. This is syntax validation, not a complete
logical validator: it cannot prove an application understands configured bytes
or that host shortcuts will reach the firmware.

[[keyboard-overrides-in-7xtgvtrmini]]
=== Keyboard overrides in `++7XTGVTRM.INI++`

A profile translates host key events into bytes or terminal actions. The guest
application must understand those bytes. The profile does not install or discover
the application's key map: test the actual host keyboard/bridge and guest app.
Turbo's TINST-defined controls, TE's installed controls and the current FAND
mappings remain the reference for those specific installations.

[[profile-loading-and-key-priority]]
==== Loading order and key priority

Configuration loading proceeds as follows:

. Initialize every bank with the same neutral settings. Navigation bindings
  are inactive, `input=custom`, `input_adapter=none`, and application commands
  and prompt/retype settings are empty or disabled.
. Parse the INI. Record explicit global and bank bindings, including explicit
  `none`, and each bank's selected preset and editing settings.
. After the entire INI is parsed, expand each selected non-custom preset into
  that bank's navigation bindings. Explicit bank bindings are retained.
. Publish the completed configuration for runtime use.

Putting `input=ansi` before or after `left=send:...` makes no difference. A
preset fills missing bindings; it does not replace an explicit bank binding.
Duplicate explicit definitions of the same key in the same scope are diagnosed,
and the first accepted binding remains. Ordinary scalar settings such as `input`
use the last accepted value. Section ordering does not change binding priority.

For an ordinary profile key, look up the binding in this order:

. An explicit binding in the effective `[bankN]` section.
. An explicit binding under `[global]`.
. That bank's selected preset, or its neutral navigation binding.
. For keys outside the navigation table, normal terminal/host fallback handling
  when no binding exists. Ordinary kbd:[Backspace], text, kbd:[Enter], main-row digits and
  keypad decimal have their normal handling; a preset does not redefine them.

Explicit `none` wins the binding lookup just like `send:...`. For navigation
keys, an inactive binding suppresses the host's fallback sequence; it does not
silently pass an ANSI arrow to CP/M. `input=custom` does not mean RAW input.
Bank sections do not inherit one another, and names do not select presets.

*Binding lookup is separate from executing the key.* Reserved terminal controls
such as forced return and viewport pan have their own routing before ordinary
profile bindings. An enabled editing adapter can consume ordinary editing keys
before their resolved binding is sent. Thus `left=send:...`, or `left=none`, does
not disable a local composer's kbd:[Left] key handling. Use `input_adapter=none` when
ordinary key-to-byte routing is wanted. The explicitly assigned CCP profile also
uses native in-place kbd:[Home] / kbd:[End] handling for a send binding at a live CCP prompt;
an explicit `home=none` or `end=none` remains inactive there.

[[working-profile-preset-comparison]]
==== Presets versus the tested working profiles

At the 261009 review, all ten working INI banks omit `input`, so all use `custom`.
The earlier numbered application defaults were a separate mechanism, now removed.
An explicit binding equal to a preset is valid and useful as a tested, visible
mapping; it is simply redundant if that preset is later selected. Selecting a
preset alone leaves every explicit binding in place.

[cols="32,68",options="header"]
|===
|Working profile |Relationship to the shared presets
|CP/M and GENERAL |Keep CCP controls explicit; their kbd:[Ctrl] navigation differs from ANSI.
|MBASIC |Uses `input_adapter=local_compose`. Cursor/editing behavior is adapter-owned; an ANSI preset would not replace that adapter.
|BBC BASIC |ANSI can supply modifier fallbacks; preserve BBC cursor/edit controls and history clear/retype settings explicitly.
|COMAL |The current ANSI template matches `input=ansi`; actual COMAL installation and guest acceptance remain pending.
|Turbo Pascal |Keep the TINST-defined private 8-bit controls explicit. ANSI matches only shared fallback bindings; it does not configure TINST or replace its map. The current kbd:[Alt+Left] / kbd:[Alt+Right] fallbacks match ANSI.
|FAND |All 12 active WordStar preset bindings match the configured bytes/actions. Retain its additional kbd:[Ctrl] / kbd:[Shift] navigation and save macro explicitly. This is a comparison of the current map, not proof of every FAND version's requirements.
|TE |Nine of the 12 active WordStar bindings match. kbd:[Home], kbd:[End] and kbd:[Insert] differ; retain those exceptions and the four explicit kbd:[Ctrl] bindings.
|ANSI APP |The current navigation map matches `input=ansi`.
|DDT |Keep its limited explicit controls; no application preset is inferred.
|===

TE's configured kbd:[Home] is bytes `11 53`: `Ctrl-Q` then *printable* S. The generic
WordStar preset sends `11 13`: `Ctrl-Q` then `Ctrl-S`. kbd:[End] similarly differs as
`11 44` versus `11 04`. These are not interchangeable encodings. TE also explicitly
disables kbd:[Insert] while the generic preset sends `Ctrl-V`. The installed TE help
and tested keyboard behavior take precedence over a generic style name.

For example, a TE section could explicitly select the shared preset while keeping
these exceptions and the application-specific kbd:[Ctrl] bindings (other settings in
the complete section still apply):

[source,ini]
----
[bank7]
name=TE (wordstar)
input=wordstar
input_adapter=none
editing_surface=screen
home=send:\x11S
end=send:\x11D
insert=none
left_ctrl=send:\x01
right_ctrl=send:\x06
home_ctrl=send:\x11R
end_ctrl=send:\x11C
----

This is an optional equivalent key-map example, not a change to the working INI.
FAND's 12 base/history bindings could likewise come from `input=wordstar`; its
additional controls must remain explicit. The repeated ANSI modifier bindings
in BBC/COMAL/ANSI APP, and the two kbd:[Alt]-arrow fallbacks in Turbo, can come from
explicit `input=ansi` selections if that cleanup is chosen. Keep original tested
exceptions when consolidating; do not remove a line merely because its app is
called WordStar-like or ANSI.

The current bank controls and the installed guest configuration form a pair.
`console_bits=8` is needed for Turbo's private bytes above 7F; a preset does not
change that global transport setting. Test the chosen host bridge's actual
chords before treating a mapping as accepted.

[source,ini]
----
[global]
kp_decimal=send:.
f5_ctrl_shift=send:\eQ

[bank3]
f5_ctrl_shift=none
num1_shift=send:1
----

The left side is `++<key>[_ctrl][_shift][_alt]++`, with the base key first and modifier suffixes in exactly that order. Use `++f5_ctrl_shift_alt++`, not `++f5_alt_ctrl_shift++`; names are case-insensitive. `++_alt++` is intended for kbd:[Alt]. RAlt/AltGr is reserved for the Czech layout's symbol entry, and is not a separate INI modifier.

[cols="34,66",options="header"]
|===
|Key group |Available base names
|Cursor and editing |`++left++`, `++right++`, `++up++`, `++down++`, `++home++`, `++end++`, `++insert++`, `++delete++`, `++page_up++`, `++page_down++`
|Common keys |`++backspace++`, `++escape++`, `++enter++`, `++space++`, `++f1++` … `++f12++`
|Main number row |`++num0++` … `++num9++` (separate from the keypad)
|Numeric keypad |`++kp_decimal++`, `++kp_delete++` (the latter is kbd:[NumLock]-off Delete)
|Czech physical positions |`++bs2++`, `++bs1++` before kbd:[Backspace]; `++p1++`, `++p2++` after kbd:[P]; `++l1++`, `++l2++`, `++l3++` after kbd:[L]; `++z1++` before kbd:[Z]; `++m1++`, `++m2++`, `++m3++` after kbd:[M]
|Letters |`++a++` … `++z++`, only with kbd:[Ctrl] or kbd:[Alt]; plain and kbd:[Shift]-only letters remain normal typing
|===

Any subset of the three modifier words is syntactically accepted for the non-letter names. Plain and kbd:[Shift]-only `++bs1++` and `++l3++` are deliberately excluded because these are dead-accent positions on the current Czech keyboard: their normal composition must continue to work. `++num1++` … `++num0++` send ASCII digits by default even when the unshifted Czech keycap produces `+++ěščřžýáíé++`; `++kp_decimal++` sends `++.++` by default even when the host emits `++,++`. Shifted main-row digits are separate names such as `++num1_shift++`.

The Windows Mintty launcher supplies these number-row and decimal events through
its per-session physical-key helper. Rebuild the selected desktop target and
open a new mirror to load it. Keypad decimal and brightness controls have native
acceptance; the corrected plain Czech number-row detection still needs a native retest.
It recognizes the Czech number row and the kbd:[NumLock]-on decimal key without
converting ordinary commas or pasted text. See
link:05-TG-tooling-guide.adoc[Tooling Guide] for setup and the keyboard probe.
Plain/kbd:[Shift] row conversion for Linux Konsole/Kitty and Windows Mintty is
selected by `XTGV_HACK_TOPROW` in
host `tools/terminal.conf`; its default is `+ěščřžýáíé`, and empty disables it.
This host option is separate from application INI bindings and kbd:[Alt]-bank selection.
Changes apply when opening a new mirror through the project launchers; see the
Tooling Guide for configuration precedence and layout-specific limits.

The right side has five forms:

[cols="40,60",options="header"]
|===
|Value |Effect
|`++send:<bytes>++` |Send the specified bytes in ordinary routing; adapter/CCP handling follows the rules above.
|`++send_cancel:<bytes>++` |In ordinary routing, send bytes and discard the current terminal history line.
|`++history_previous++` / `++history_next++` |Browse the effective history bank.
|`++none++` |Suppress ordinary mapping/fallback. Adapter-owned editing keys follow the adapter routing described above.
|===

[[_encoded_bytes_and_control_characters]]
==== Encoded bytes and control characters

* A key binding holds up to *16 decoded bytes*.
* `\e` is Escape, `\r` Return, `\n` LF, `\t` Tab and `\\` a backslash.
  `\xNN` inserts one hexadecimal byte.
* `\^K` sends `Ctrl-K` (0B). The backslash-caret consumes exactly one character:
  `++\^K\^D++` sends two controls; `++\^K^D++` sends `Ctrl-K` then printable `^D`.
  Bare `^K` stays printable.

[cols="1,2",options="header"]
|===
|Control notation |Decoded byte
|`\^@` |00 (NUL)
|`\^A` through `\^Z` |01 through 1A; lowercase letters also accepted
|`\^[` |1B (Escape); `\e` is usually clearer
|`\^\`, `\^]`, `\^^`, `\^_` |1C, 1D, 1E, 1F respectively
|`\^?` |7F (DEL)
|===

* Invalid forms such as `\^5` are rejected.
* Put comments on separate lines beginning with `;` or `#`. After a binding
  value, comment text would instead become part of that value.
* Duplicate explicit bindings report errors; the first accepted one remains.
  The sparse override pool holds 128 entries across global/bank scopes;
  the fixed per-bank legacy key slots do not consume that pool.

The current source supports both control notation and full-byte `\xNN` values.
For example `send:\x81` encodes one byte, not a UTF-8 character. Use
`console_bits=8` for an application expecting bytes above 7F.

[[_ini_recognition_versus_host_delivery]]
==== INI recognition versus host delivery

* A valid binding does not guarantee that the host delivers its physical chord.
  A desktop shortcut can consume it first.
* Supplied Konsole/Kitty keymaps translate combinations with known safe
  fallbacks. Terminal-owned shortcuts, ambiguous kbd:[AltGr] combinations,
  unmodified dead accents and some punctuation combinations are not freely
  assignable application keys.
* Konsole's key table does not explicitly distinguish left and right kbd:[Alt].
* Ordinary unbound keys retain host output; pasted text is not remapped.

[[_reloading_and_persistence]]
==== Reloading and persistence

`++7XTGVTRM.INI++` accepts CR, LF or CR/LF lines and treats `Ctrl+Z` (0x1A)
(`++1Ah++`) as logical end of file. It can be edited with a CP/M editor and
reloaded by `++REBOOT++`. Palette and brightness selections are saved lazily;
ordinary keyboard zoom, pan and `++VTZOOM++` are temporary and do *not*
rewrite boot `++view_zoom++`. Other settings and other display sections remain
user-authored. The host transfer tool's deliberate `++--cpm-text++` option
writes CR/LF plus `Ctrl+Z` (0x1A). Do not edit checksummed history files from
CP/M. The INI cache and save transaction are described in the
link:04-TRG-technical-reference-guide.adoc#configuration-and-persistence[Technical Reference Guide].

These settings select the logical events sent by the supplied kbd:[Alt+Q] and
kbd:[Alt+Backspace] host mappings. Either event can select exit or clear; `none`
disables the corresponding policy entry. They are processed before ordinary
profile bindings, not arbitrary keyboard-chord remaps.

Legacy `lalt+ralt+escape` and `lalt+ralt+delete` remain accepted aliases for
`escape_alt` and `backspace_alt`, respectively. They do not require kbd:[AltGr];
use the new spellings in new INIs. Older firmware needs rebuilding before it
can read the new spellings. There is no implemented `boot_ansi` setting;
adding that earlier proposed name causes a load error.

After the first themed frame is drawn/flushed, `crt_rampup_ms` gradually raises
the backlight from OFF to `backlight_level` (default 16). It applies to all
palettes, not only GREEN/AMBER. For example:

[source,ini]
----
[global]
crt_rampup_ms=1500
----

* There are 32 logical states: OFF=0, intermediate levels 1..30, full ON=31.
  Full ON means the board's configured maximum, not necessarily 100% PWM duty.
* Each HAL maps levels to its own duty values. Level 1 is its intended lowest
  usable visible level, not a common brightness percentage across panels.
* The ramp traverses logical levels over the configured duration: a stepped
  effect, not a calibrated linear-light fade.

Dated visual tuning and
deployment evidence remains in
link:../docs/260925-01%20RP2_2%20backlight%20minimum%20duty%203%20trial.adoc[RP2_2 notes]
and link:../docs/260925-14%20RP2_147%20backlight%20minimum%20and%20HAL%20boot%20warning.adoc[RP2_147 notes].
The configured backlight step chords stay within 1..31; from OFF they first restore
remembered brightness. Explicit brightness controls cancel an active ramp
immediately. Transient ramp levels never overwrite the saved target.
Private `CSI >63;32v` remains a legacy alias for full ON; 33/34 still mean
increase/decrease. No new INI setting is needed for ordinary immediate startup.

[[rg-terminal-interfaces]]
== 5. Terminal interfaces

[[output-interpretation-modes]]
=== Output interpretation modes

There are two terminal-output interpretations: *ANSI/VT100* (the normal
default, including implemented xterm colour extensions) and *VT52*.

* Guest commands `VT100` / `VT52` select ANSI/VT100 / VT52 on all routes.
* In the native mirror, kbd:[Ctrl+&#93;] then kbd:[1] / kbd:[Ctrl+&#93;] then kbd:[2] are prefix alternatives.
* Native bridge options `--mode ansi` / `--mode vt52` select one at connection.
* Applications use `CSI ?2h` for ANSI, `CSI ?2l` for VT52, and VT52 `ESC <`
  to return to ANSI. These transitions do not save a new INI boot mode.

`++## RAW++` is only an input-routing state, application profiles are keyboard translation choices, and GCLS/xterm256 plot is a temporary graphics canvas; none is a third persistent terminal emulation mode. Application cursor/keypad flags are likewise negotiated submodes within ANSI/VT100, not separate terminal types.

[[implemented-escape-sequence-subset]]
=== Implemented escape-sequence subset

ANSI/VT100-style output supports CR, LF/VT/FF, BS, BEL, SI/SO and tabs at
eight-column stops; ESC H sets a stop and CSI g clears one or all stops.

* *Position and erase:* CSI A/B/C/D, E/F, G, H/f and d move/address the cursor.
  CSI J/K erase modes 0/1/2 work; CSI 3 J does not clear scrollback because
  there is none.
* *Scrolling:* ESC D/M/E index/reverse-index/next-line; CSI r sets top/bottom
  margins and CSI L/M inserts/deletes lines. Margins span complete logical
  rows, not pixel windows or left/right-bounded rectangles.
* *State:* DEC private ?6, ?7 and ?25 control origin, autowrap and cursor
  visibility. ESC 7/8 and CSI s/u save/restore the relevant cursor,
  rendition and charset state.
* *Modes and queries:* CSI ?1 and ESC =/> select cursor/keypad application
  modes. ESC #8, ESC c, CSI 5n/6n, CSI c and ESC Z have their implemented
  alignment/reset/status/identity meanings. CSI ?2 l enters VT52.

G0/G1 may designate ASCII (ESC ( B / ESC ) B) or DEC Special Graphics
(ESC ( 0 / ESC ) 0); SI/SO selects the active set. The DEC test notes below
identify approximations and unsupported control pictures. SGR supports
0, 1/22, 4/24, 5/25, 7/27, 30..37/39, 40..47/49, 90..97 and 100..107,
subject to the palette/paper mapping below. This is not full ANSI or VT100
conformance.

VT52 mode supports ESC A/B/C/D, H, I, J, K; ESC Y plus row+32 and column+32;
ESC Z identification, ESC F/G graphics/ASCII, ESC =/> keypad selection and
ESC < return to ANSI. Its graphics use the implemented DEC set, not the
original VT52 character ROM.

There is no alternate screen, scrollback, 132-column mode, double-sized
lines, mouse, UTF-8 guest input, automatic pan or binary console transport.
Unsupported CSI commands are ignored as units; string controls are consumed
without display. Bytes above 127 do not directly index the 6x10 font. The
private 7xtgv-terminal query/control protocol is catalogued in the
link:04-TRG-technical-reference-guide.adoc#private-protocol-boundaries[Technical Reference Guide].

|ANSI color |ANSI name |Normal ink slot |ALT ink slot
|0 |Black / default ink |00 |08
|1 |Red |01 |09
|2 |Green |02 |10

SGR 30..37 selects the normal set; 90..97 selects the ALT set. SGR 1 (bold)

[[xterm256-graphics]]
=== Graphics extension: xterm256 plotting

In the native mirror, kbd:[Ctrl+&#93;] then kbd:[g] or kbd:[Alt+Shift+Backspace] starts a
local GCLS graphics layer. In the browser, use the guest plotting scripts
which initialize graphics themselves; native prefix shortcuts do not apply.
The extended private form is `++CSI >4;zoom;x;y v++`.

* *Coordinates:* `zoom` is 1..4; `x,y` are physical pixels from the display's
  top-left corner, not logical cells and not multiplied by zoom. The origin
  does not move with the gutter or viewport; x=0 may cover the gutter.
* *Samples:* each source sample becomes a `zoom × zoom` RGB565 block, clipped
  at the physical client boundary. Indexed-color samples
  (`++CSI 38;5;<index>m++` plus byte values) draw on the TFT, SDL panel or browser canvas; they are not pixels in
  the native text mirror or browser screen-text snapshot.
* *Lifetime:* the cell layer remains logically present; opaque text can paint
  over the image. The first later terminal scroll retires the plot and restores
  the gutter without a full-screen clear.

The direct plot ends on SGR reset (`++CSI 0m++`). Rows used by status text and the active cursor are then repainted from terminal memory, including when the plot was launched by `++SUBMIT++`; the remaining graphics canvas stays visible. A normal `++CLS++` clears the terminal cells, while the native mirror prefix kbd:[Ctrl+&#93;] then kbd:[r] explicitly returns the screen to the normal terminal surface.

For bundled programs and launch recipes, see
<<a6-graphics-and-timing-helpers,Graphics and timing helpers>> and
<<rg-plotting-demonstrations,Plotting demonstrations>> in Appendix A.

[[cardmark-raw-sd-read-diagnostic]]
=== CARDMARK raw SD read diagnostic

`CARDMARK [CSD] [sectors [MHz [start-sector]]]` requires matching firmware
on our direct-SdFat/SPI targets: ES3_35, ES3_5, EP4_10, RP2_147, RP2_2 and
experimental EC6_147.
Desktop reports this raw-card diagnostic as unsupported. The former W535
SD_MMC alternate has been removed; all six current physical targets use SPI/SdFat.
Defaults: 1024 sectors, the configured operating SPI request, and
start sector 0. Sectors are 512 bytes; count range is 1..1048576 and requested
clock range is 1..60 MHz. Example: `CARDMARK 4096 50`.

Add `CSD` anywhere among the arguments for named CSD fields, for example
`CARDMARK 4096 50 CSD`. Matching is case-insensitive. The compact report orders
raw CID, decoded identity, raw CSD, capacity in whole MiB (rounded down, with
exact 512-byte sector count), and encoded speed. CMD6 checks High Speed support
where advertised; it does not select High Speed mode. An unsuccessful query
reports unknown support and does not prevent the raw read test.

Detailed decoding covers SD CSD v1.0 (SDSC) and v2.0 (SDHC/SDXC). CSD v3.0
(SDUC) is identified but not decoded or supported by this SdFat backend.
These are SD layouts, not MMC/eMMC layouts. See
link:../docs/261003-11%20CARDMARK%20CSD%20decoding%20and%20CMD6%20query.adoc[register decoding notes].

The native service reads reference data at requested 20 MHz and compares three
trial reads per batch at the selected clock. It reports card CID/CSD, capacity,
compared bytes and raw-read throughput, then restores the operating clock.
The ` ... ` hint appears before test reads and the result follows on that line.
kbd:[Ctrl+Alt+C] cancels in the integrated terminal build. It runs in ordinary writable
firmware too; CARDMARK itself uses only read operations. If clock restoration
fails, storage is stopped and a reset is required rather than returning to CP/M.

Clock values are requested, not measured. A PASS demonstrates read agreement
for the selected range, not write reliability or complete card qualification.
Use a backed-up/spare card for experimental clocks. Raw throughput is not the
same measurement as VTDRV's BDOS/file throughput. Detailed implementation and
results: link:../docs/261002-13%20Global%20SdFat%20SPI%20clock%20and%20CARDMARK%20preparation.adoc[CARDMARK checkpoint].

[[a7-visual-tests-and-dec-graphics]]
=== Visual tests in 7xtgv(C1) and DEC graphics

Select `7xtgv(C1)` using `C1:`, start `MBASIC`, then `RUN "VTESTS"`.
Save maintained sources with
`SAVE "VTESTS",A` (ASCII); load with ordinary `LOAD "VTESTS"`.

The maintained local source has isolated attribute comparisons in
item 3, VT52 movement/erase checks in item 5, a steady DEC frame in item 7,
and five scrolling-region checks in item 9. Item 9 requires *80x24 logical
geometry*, independently of the panel's visible viewport. Updated source
must be deployed separately; the physical card may still hold an older menu.
See link:04-TRG-technical-reference-guide.adoc#terminal-compatibility-test-notes[test scope].
`VTPAL.BAS` is also maintained in `7xtgv(C1)`; its physical-card location may differ.

VTESTS item 4 has two 40x16 pages: a continuous frame with junctions, patterns,
scanlines and G1/SO/SI selection, then all 32 DEC Special Graphics positions
0x5F..0x7E. The implementation supports G0/G1 designation and SI/SO switching;
this is not a complete VT100 conformance claim. Six control pictures (`b`,
`c`, `d`, `e`, `h`, `i`) currently fall back to question marks. TFT pi/pound
use approximate QL p/L glyphs while the PC mirror uses Unicode equivalents.
Historical W535 visual acceptance does not qualify every current board/build;
physical retesting and exhaustive protocol/glyph checks remain separate work.
See link:../docs/260924-20%20DEC%20graphics%20review%20and%20expanded%20VTESTS.adoc[the complete inventory and test scope].

[[a6-graphics-and-timing-helpers]]
=== Graphics and timing helpers in xterm256(C2)

[cols="38,62",options="header"]
|===
|Command |Purpose
|`++GCLS [zoom [x y]]++` |Arm local xterm256 plotting without clearing or redrawing the screen. `++zoom++` is 1…4; `++x,y++` are unscaled physical pixel coordinates from the display's top-left corner, independent of terminal zoom, gutter, or pan. Bare `++GCLS++` retains `++ESC[>4v++` and defaults to 1× at `++(0,0)++`. Use `++CLS++` separately when wanted.
|`++SYNC++` |Forces pending verified terminal-history and persistent settings saves immediately. Use before a long graphics stream or likely hardware reset.
|`++VTPAD [n]++` |Prints `++n++` CR/LF pairs; default is 18. It provides visible space where SUBMIT would discard empty script records.
|`++VTSTART++` / `++VTSTOP++` |Save and report elapsed RunCPM uptime around a test, using `++VTIME.DAT++` in the current DU.
|`++SUBMIT BROT_BS++` / `++SUBMIT BROT_PS++` |Time the renderer with VTSTART/SYNC/GCLS/VTSTOP. BS plots at pixel (200,50); PS first pads eight lines and plots at (400,50). Neither script clears the screen; small panels may clip these fixed origins.
|`++SUBMIT VTPARG n++` |Argument-expansion test: runs `++VTPAD n++`.
|===

* Our helper sources and retained HEX/listings live in `7xtgv(C1)`.
  Build in a disposable copy, then explicitly install tested COM files in `cpm(A0)`
  or the demo area. For our Intel 8080 `.ASM` helpers use `ASM name`, then
  `LOAD name`; our `.Z80` helpers use SLR `Z80ASM name`.
* Imported Brot sources remain in `xterm256(C2)`, with `BROTINFO.TXT` attribution.
  Their suffixes do not imply compatibility with Digital Research ASM.
* The Brot names deliberately use underscores: TE treats `-` as an editing
  command separator. Use `BROT_BS` and `BROT_PS`, not hyphenated names.
