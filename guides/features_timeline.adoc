= RunCPM 7xtgv-terminal: Features Timeline Guide
:leveloffset: +1
:source-highlighter: highlight.js

This is a compact history of the *implemented* RunCPM 7xtgv-terminal.
Each dated checkpoint is a source commit or implementation
checkpoint, not necessarily the minute a feature first worked on hardware.
Later rows can refine earlier behavior. The
link:../docs/FEATURES.adoc[feature ledger] tracks individual feature states and
test limits; the link:03-RG-reference-guide.adoc[Reference Guide] describes current
commands. Plans, imported CP/M packages, and the future native 7xtgv format
are not presented here as shipped features. This page is curated, not generated
from `++docs/features.tsv++`; update both when an implemented feature is added,
renamed, or changes behavior.

== Terminal and RunCPM foundations

Application settings now belong to complete INI bank sections. All slots share
neutral fallbacks, so renumbering does not inherit another application's adapter,
commands or prompt tracking. The working INI explicitly assigns `ccp_bank=0`;
72 missing application key bindings are now in their respective sections.
See link:../docs/261009-2026%20DONE%20INI-owned%20application%20profiles.adoc[slot independence and real TE desktop regression].

Retained history now uses 80-character records including `>`: 79 characters
of text per entry in every bank, with marker space accounted for during load.
Longer active input keeps its separate capacity; old longer entries are clipped
when loaded. See
link:../docs/261009-1843%20DONE%2080-character%20history%20records.adoc[boundary fix and host verification].
The subsequent normal EP4_10 desktop rebuild passed CTest, integrated v1/v2
history boundary/save/reload checks, browsing/startup and eight VTESTS scenarios:
link:../docs/261009-1854%20DONE%20EP4_10%20rebuild%20and%20history%20regression%20retest.adoc[rebuild and retest evidence].

Submitted filtered recalls now follow ordinary history storage again, including
completed tokens inside numbered/prefixed lines. Exact adjacent duplicates and
empty/single-character input remain excluded. Terminal/runtime and real
SDL/MBASIC save/reload tests pass; separate keyword lists remain future work.
See link:../docs/261009-0251%20DONE%20Filtered%20recall%20returns%20to%20normal%20history.adoc[history behavior and keyword boundary].

Global exit/clear INI settings now use `escape_alt` and `backspace_alt`, matching
the existing host shortcuts. Historical dual-Alt names remain aliases; no
AltGr modifier is required. See
link:../docs/261009-0218%20DONE%20Clear%20names%20for%20global%20exit%20and%20clear%20shortcuts.adoc[parser and runtime checks].

Integrated desktop browsing has checked named prompts, eleven working-card
aliases, LS/LL alongside DIR/LDIR, remembered drive selection and the existing
AUTOEXEC.TXT option for starting with 7XF. See
link:../docs/261009-0035%20DONE%207XF%20desktop%20browsing%20and%20startup%20checkpoint.adoc[browsing and startup checkpoint].

Current 7XF listings sort files by extension/name and display lowercase
`name.ext`, without renaming host files. Descriptions stay on the same row;
`LS ..` / `LL ..` lists the current
drive's areas, while `/` lists drives. See
link:../docs/261008-2212%20DONE%207XF%20sorted%20compact%20listings%20and%20parent-drive%20view.adoc[catalog listing checks].
Current-area headings omit the repeated path and start the description at
column 2. Area overviews omit empty/catalog-only areas (including host dotfile
placeholders), while direct access and aliases remain available.
Both short and long area overviews retain the whole-drive heading; only LL
includes individual area descriptions. Root drive lists retain descriptions.

Current working-card organization: `mbasic(B1)`, `bbcbasic(B2)` and `tp(B4)`
hold language packages; `comal(B3)` is reserved with placeholder files.
`fand(B5)` and `dbase(B6)` hold imported databases;
`7xtgv(C1)` owns our guest sources and visual tests, `xterm256(C2)` the
Mandelbrot demos, and `bench(C3)` the benchmarks. Shared commands remain in
`cpm(A0)`; `cpmdev(A1)` combines historical assembler and CCP/BDOS dependencies.
Older checkpoints below retain their then-current DU names. See
link:../cpmcard/README.adoc[current card layout] and
link:../docs/261008-2120%20DONE%20Working%20card%20areas%20and%20canonical%20guest%20sources.adoc[reorganization and test evidence].

The `261007-1214` test checkpoint:
link:../docs/261007-1214%20DONE%20VTESTS%20legacy%20and%20scroll%20checks.adoc[VTESTS review]
isolates blink/reverse attributes, expands VT52 movement/erase checks and adds
five DECSTBM/DECOM scrolling stages. Real MBASIC runs through the quiet SDL
firmware on disposable cards; production renderer checks cover both blink
phases and reverse pixels. This improves tests, not the terminal protocol;
updated BASIC was subsequently copied to the then-current local `cpmcard/A/7` on Petr's request
at `261007-1234`, but not to the physical card. See the
link:../docs/261007-1234%20PLAN%20Consolidate%20CP-M%20content%20into%20cpmcard.adoc[card-root migration plan].
Its current canonical location is `7xtgv(C1)`; the old location below is
historical evidence, not an instruction to create another source copy.

== Colour, transfer, boards, and storage

At `261004-1057`, EC6_147 gains an experimental source HAL and build target:
single-core FreeRTOS runtime, shared LCD/SD Arduino SPI transactions and
SRAM history. Backlight is initially capped at approximately 50%. Host checks
pass; full firmware build and hardware verification are still pending. See
link:../docs/261004-1057%20EC6_147%20experimental%20HAL%20implementation.adoc[C6 implementation checkpoint].

The first C6 build `261004-1103` linked successfully. A subsequent approved
C6-only diagnostic captures free/largest internal heap before terminal setup
and reports it with the startup snapshot through the existing banner hook.
That diagnostic is pending a new rebuild; the earlier image does not contain it.

Build `261004-1109` includes heap diagnostics and was flashed. A hardware
reset restored initially blank startup. Petr then confirms EC6_147 working:
VTCPU active/quiet 9.22/13.74 MHz, VTDRV W write/read 4.42/10.15 KiB/s with
verify PASS. These are initial measurements, not sustained qualification;
heap readings and first-upload reset behavior remain to be recorded.

At `261004-0010`, both fatal SD startup messages use the common red-paper
warning helper on every integrated module, with plain text for non-ANSI
profiles. Host tests cover both rows and attribute reset. See
link:../docs/261004-0010%20Red%20paper%20SD%20startup%20failure.adoc[SD failure styling].

At `261003-2245`, history retention is reduced from 255 to 100 entries per
bank on every module, saving 193.75 KiB per history object. Existing larger
BUF files load unchanged but retain the newest 100 entries per bank; future
saves drop older entries. Ten banks and line lengths are unchanged. Host
tests pass; RP2_2 Os build `261003-2248` is flashed and boots without the INI
cache warning, applying the configured 40 MHz SPI clock. Interactive recall
checks and other-module rebuilds remain pending. See
link:../docs/261003-22%20RP2_2%20INI%20cache%20pressure%20and%20Os%20trial.adoc[RAM investigation].

At `261003-22`, RP2_2's generic INI-cache warning is given the existing red
error-paper style and specific load-failure/byte-count diagnostics. A live
15,232-byte INI fetch and the 326,944-byte history allocation point to RAM
pressure; the actual boot failure remains to be confirmed. RP2_2 gains an
explicit Os build trial without changing history depth. See
link:../docs/261003-22%20RP2_2%20INI%20cache%20pressure%20and%20Os%20trial.adoc[cache investigation].

At `261003-20`, the manual gains a link:01-BG-build-guide.adoc[Build Guide]

End-of-day `261002` reconciliation records successful A0 CARDMARK deployment:
Petr's `CARDMARK 4096 50` compared 6 MiB and passed, reporting raw reads at

At `261002-17`, the link:../docs/261002-17%20P4%20backlight%20calibration%20preparation.adoc[P4 calibration preparation]

The fetched device INI remains unchanged. Host backlight tests pass; firmware

zeros and detaches backlight PWM and drives GPIO23 LOW before ESP.restart.

blue startup frame or occasional early boot stall. Host call-order tests pass;
firmware rebuild and hardware testing remain pending.
P4 build `261002-1932` was then built, flashed and boot-verified. Petr confirms
the blue interval is absent during reboot/reflash and accepts the brightness
curve. Other modules remain untested for this change. A separate intermittent

validation of this lower timing remains pending.

implements the P4 read-only native CARDMARK service plus 128-byte COM launcher,

P4 build `261002-1520` stages successfully with the diagnostic enabled; its
