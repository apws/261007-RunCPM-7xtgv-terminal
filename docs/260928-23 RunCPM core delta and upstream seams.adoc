The nine changed core headers are the abstraction, CCP, BDOS/BIOS, four CPU
headers, disk and globals. Petr's inventory caught these. Additional details

files, the portable file-extension repair, `++VOL++` behavior, profiling
output, and native POSIX catalog portability. The approximate source diff is
bounded, but the CCP feature itself is substantial; "small core delta" must
not be mistaken for "small feature".

== Current upstream collision map

The pinned upstream CP/M 3 work has conditional code in
`++abstraction_arduino.h++`, `++ccp.h++`, `++cpm.h++`, `++disk.h++` and
`++globals.h++`: exactly five of our nine touched core areas. Its CPU loops
do not contain `++CPM3++` conditionals, though they still need an ordinary
version comparison before any port. Upstream's `++ccp.h++` retains an
eight-byte prompt and `++VOL++` reading `++INFO.TXT++`; it has no 7XF catalog.
Its Arduino `++_sys_extendfile++` still has the reversed unsigned subtraction
`++f.size() - fpos++` after testing `++fpos > f.size()++`, so the portable
file-extension fix remains a concrete small candidate at this snapshot.
The public upstream readme says porting should normally be done through an
abstraction layer, but our named CCP and emergency COM return cannot be
claimed to fit that interface as written. These are file-level collision
indicators, *not* a completed semantic merge audit.

For a future small patch, the pinned upstream `.clang-format` specifies
four-space indentation, attached braces, no line-width limit, indented
preprocessor directives and no automatic include sorting. Its core uses
underscore-prefixed host helpers and short function-end comments. These are
starting observations, not a license to bulk-reformat local or upstream
files; inspect the exact destination file's conventions before editing it.
