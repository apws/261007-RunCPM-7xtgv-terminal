The host initially lacked MinGW-w64. An explicit

system upgrade was performed by this work.

== Changes and build result

* Desktop CMake now selects the existing Linux PTY source or an explicitly
  fixture-only Windows Serial implementation. Linux does not use a socket.
* The original headless application and SDL presenter build for Windows with
  MinGW-w64. Five portable C++ test executables also compile. POSIX Python/PTY
  integration tests remain Linux-only until a Windows harness is qualified.
* Windows build definitions select HostOS 0x00, matching the existing BDOS
  host-identity contract, and prevent Win32 min/max macros. No core edit.
* SDL uses the application's ordinary main function and SDL_SetMainReady.
  The SDL DLL is copied beside the executable; console diagnostics remain
  available to the launcher.
* The first compiler failure was the existing CPU throttle's Win32 Sleep
  declaration. Including windows.h in the desktop application wrapper fixed
  it. CPU, CCP, BDOS and common abstraction sources were not changed.
* Added an optional Linux MinGW toolchain file and
  link:../src/RunCPM_7xtgv-terminal/tools-win/README.adoc[repeatable cross-build instructions].
  No target launchers or Windows mirror have been implemented yet.

Build artifact directory:
`build/RunCPM_7xtgv-terminal/desktop-win/jc8012p4a1c/`.
It contains `xtgv_desktop.exe`, `xtgv_headless.exe`, five test EXEs, SDL2.dll
and the three compiler runtime DLLs. `build-proof.json` records SHA-256 hashes,
PE import lists and the explicit untested execution status.

Compiler: x86_64-w64-mingw32 GCC 16.2.0, POSIX thread model. The executable is
PE32+ x86-64 and imports UCRT APIs. This is a Linux cross-toolchain result,
not a native MSYS2 UCRT64 build result. The build uses real Arduino_GFX 1.6.4
and the official SDL2 2.32.10 MinGW archive, checked against its release asset
SHA-256 before extraction. Optimization is O2 with RelWithDebInfo.

  `build/RunCPM_7xtgv-terminal/desktop/linux-win-port-check/`.

  required SDL/GCC/winpthreads DLLs are staged beside them. No native Windows
  execution or Wine run was performed; Windows tests are compiled, not passed.

  are under `/tmp/xtgv-win-first/`; these are transient, not release artifacts.

tools-win README. Shared Linux build outputs used by existing sessions were
not replaced. Working card and running sessions were not launched or stopped.
Existing guide/source/card changes remain in the worktree; no commit, push,
firmware build, flash or card deployment.
