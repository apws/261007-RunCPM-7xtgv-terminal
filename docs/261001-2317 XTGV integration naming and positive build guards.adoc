== Names and ordinary functions

The Arduino abstraction's added activity/config helpers now use
`++_xtgvDiskActivity++` and `++_xtgvConfigAccess++`.
Private benchmark helpers use `++_xtgvCPUBegin++`, `++_xtgvCPUEnd++`,
`++_xtgvDRVBegin++`, `++_xtgvDRVEnd++` and `++_xtgvHardwarePrint++`.
Their constants use XTGV_CPU/DRV/TERM/REBOOT/SYNC prefixes; state uses
xtgvBenchmark, xtgvCpu, xtgvDrv, xtgvTerm and xtgvSync as agreed.
All numeric guest ports, replies and VTCPU/VTDRV printed labels are unchanged.

The optional CPU, console, disk-close and guest-idle seams now use
XTGV_ABORT_REQUESTED, XTGV_Z80RUN_ATTRIBUTES, XTGV_MODIFIED_FILE_CLOSED
and XTGV_CONFIG_GUEST_IDLE. The callable bindings name ordinary functions,
not code-body macros. CPU attributes still require a declaration macro.
Absent bindings retain the existing preprocessor exclusion; the CPU poll
counter and branch disappear when the abort hook is not configured.
The active polling interval remains 65,536 instructions.

In ccp7xf.h the external execution path now calls
`++_xtgvExternalBegin++`, Z80run, and `++_xtgvExternalEnd++`.
The latter owns the existing bounded input-cleanup wait, input discard,
SUBMIT cancellation, message and input resume. Serial mode supplies empty
ordinary functions. Stranded-SUBMIT state and the cancellation helper are
also tagged. Their deletion-failure behavior and 200 ms bound are unchanged.

Inherited RunCPM interfaces such as _HardwareIn, _HardwareOut, _getch and
_sys_readseq retain their names. The terminal namespace and public terminal
APIs remain unchanged; the catalog implementation is not mass-renamed.
RUNCPM_TARGET_* selectors remain for their separately coordinated rename.

== Positive composition

The Arduino abstraction, extended CCP, catalog width selection and terminal
runtime now use `++#if XTGV_TERMINAL++`. Serial-only behavior is the else
branch. runcpm-config.h no longer derives RUNCPM_HEADLESS; explicitly passing
that obsolete flag produces a diagnostic directing the builder to
XTGV_TERMINAL=0. Target JSON already selects the three XTGV composition
flags. Runtime tests already selected terminal mode; the catalog test now
does so explicitly too. Standalone terminal mode remains unimplemented.

== Verification and limits

* All four real CPU implementations compile and execute a HALT with abort
  hooks disabled and enabled. With the hook enabled, an INC BC / JP loop
  aborts at the first 65,536-instruction poll with BC=32768.
* Production benchmark-port code is exercised in terminal and serial modes:
  active/quiet read/write, cancellation, CPU quiet mode, capability replies
  and sync success/failure preserve their existing behavior.
* Extracted production CCP lifecycle helpers and the real forced-return
  coordinator pass normal-return, forced-return, failed batch deletion,
  acknowledged input cleanup, bounded timeout and serial-mode checks.
* Existing native runtime/render/mirror, catalog, INI runtime and disk
  indicator checks pass. The Python suite passes 96 of 97 tests, including
  target, board, file-extension, INI and the integration checks above.
* The one unrelated Python test already fails in committed b278769:
  test_helper.HelperTests.test_transfer_user_accepts_old_and_named_cd_outputs
  expects the final transfer command to be CD, while current Link.user uses
  A7:. Reproduced in a temporary git archive of that commit; left unchanged.

Host tests do not prove ESP32/RP2350 SDK compilation or hardware timing.
No firmware artifact was rebuilt or flashed. After the next requested
rebuild/reflash, check normal and forced COM return (including SUBMIT),
INI lazy save, VOL versus LS, and VTDRV W Q.
