== Decision and implementation

Following the
link:261009-0917%20DONE%20Manuals%20review%20and%20morning%20pickup.adoc[morning pickup],
Petr selected the history-length correction and revised the requested bound:
"umm, so let it be rather 80, including that >".

* Every bank now retains at most 79 text characters, making an 80-character
  saved record with its leading `>` marker, excluding the line ending.
* `line_history.h` separates retained `MaxEntry=79` from active `MaxLine=127`.
  Typed submission and imported entries share the retained bound. Existing
  minimum-length and adjacent-repeat rules apply to retained entry bytes.
* `terminal_runtime.cpp` loads the full 80-character record before removing
  its marker. This fixes the previously demonstrated missing-last-character
  bug; merely lowering the old shared limit would not have fixed it.
* Older longer v1/v2 entries are clipped in memory; excess bytes are consumed
  through the newline. A later normal save writes the shorter entries. Existing
  BUF files are not rewritten by this implementation work.
* Live input/editing retains its longer capacity and the CCP's 125-character
  submission tracking. Filtered token composition can still include surrounding
  text; the history entry stored on Return has the 79-character bound.
* Entry storage saves 48,000 bytes across ten banks of 100 entries. No history
  format version, matching rules, profile ordering or keyword subsystem change.
