= Key-first INI chord implementation
:source-highlighter: highlight.js

Implemented and given its first hardware smoke test on 260922 from the signed link:260922-13%20key-first%20INI%20chord%20names%20signed%20implementation%20plan.adoc[key-first plan]. Deeper application testing is deliberately continuing before the candidate is promoted from `+new+` to `+current+`.

== Implementation

* `+parseKeyChordName()+` now recognizes only `+<key>[_ctrl][_shift][_alt]+`. It matches the known base name first, so compound keys such as `+page_up_ctrl+` and `+kp_decimal_ctrl_alt+` are unambiguous.
* Modifier suffixes are optional but strictly ordered. Prefix form, reordered suffixes, repeated suffixes and trailing garbage are rejected.
* The duplicate `+KeyNames[]+` table was removed. Every bank setting is parsed into a `+KeyChord+` first and then routed to the existing fixed profile slot or sparse override pool. This retains input-preset precedence and duplicate detection without a second textual-key path.
* Internal enums, private host-event modifier bits, runtime lookup and storage limits are unchanged.

== Configuration migration

* The fetched local `+7XTGVTRM.INI+` was converted: 64 active and 12 commented chord names, with no section-local collision.
* The complete `+7XTGVTRM.txt+` editing template was converted: 24 active and 176 commented chord names.
* Both files retain CP/M CR/LF records and Ctrl-Z padding.
* The current manual and firmware README use key-first examples. Historical plans retain their original examples with a prominent 260922 supersession note linking to the signed plan.

The converted key-first INI was explicitly transferred to device user A0 and verified byte-for-byte before the new firmware was booted.

== Host verification

* Exhaustive name test over every `+KeyLeft+` through `+KeyZ+` base and all eight modifier bit combinations passed. Expected invalid plain/Shift-only letters and dead-key positions remained invalid.
* Explicit rejection tests passed for `+ctrl_left+`, `+shift_ctrl_a+`, reordered suffixes, repeated suffixes and trailing suffixes.
* Global-versus-bank precedence and duplicate fixed-key detection passed after removal of the textual fixed-key table.
* Sanitizer-backed terminal, keyboard, bounds/fuzz and bidirectional queue tests passed outside ptrace confinement.
* Runtime render/mirror, slow/disconnected USB, queue saturation and reconnect tests passed.
* Physical plot origin and post-plot gutter redraw tests passed.
* All 24 Python helper/transfer tests passed.
* The converted JC8048W550 fetched INI parsed as `+11246 bytes, 0 errors+`.
* The converted full template parsed as `+16642 bytes, 0 errors+`.
* An archived modifier-first INI produced 48 errors under the new parser, confirming that compatibility was not accidentally retained.
* `+git diff --check+` passed.

== Hardware checkpoint

* Target-aware firmware `+260922-1515+` was built, staged as `+new+`, and reflashed by Petr from the device.
* The converted `+A0:7XTGVTRM.INI+` was transferred separately with full read-back verification (`+11136+` CP/M-text bytes).
* Boot reported `+Terminal profile .....OK+`.
* Petr selected the TP301 profile, opened Turbo, and edited the key-first INI; representative entries such as `+insert_shift+`, `+delete_ctrl+`, and `+end_alt+` behaved normally.

The candidate remains deliberately unpromoted while Petr performs deeper application testing. Promotion is not implied by this successful smoke test.
