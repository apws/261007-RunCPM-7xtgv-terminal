= Installed application keyboard reference

== Scope and evidence

The Reference Guide now consolidates our working-card application controls:
Turbo/TINST primary command mappings, private single-byte encoding, original
Czech/core-key photographs, MBASIC/BBC BASIC quick keys and FANDINST's unresolved
Sharp-console adaptation. UG and the guide index link directly to the section.
This is documentation work; no executable, INI, BUF or runtime code changes.

The narrative distinguishes the 260919 prefix experiments, 260922 high-bit
proof and the current installed table. It does not present the early table
as current or the historical hardware test as new exhaustive acceptance.
FAND's recorded original SHARP MZ-821 preset differs from ANSI/VT52; the
Lamac/LEC connection remains a hypothesis and no custom output mode is claimed.
Only public investigation records are cited. Private FAND logs are not copied
or linked. COMAL is a placeholder; dBASE has no qualified keyboard profile.

== Current Turbo readout

Both cpm(A0) and tp(B4) TURBO.COM copies are identical, 30720 bytes.
SHA-256: `d9d649bf25958714daea7b1e792f850a8df7135e5c563f4441d3e3c5908bbc38`.
The known table for this exact binary starts at file offset `0x4185`.
Read 45 one-byte-length-prefixed entries; next offset `0x41EA` holds zero.
These offsets are evidence for this binary, not a generic Turbo installer API.
Slots follow the ordered action names in the 260911 TINST reference (display
fields 20--64 correspond to slots 1--45 below).

The guide cross-checks those bytes against the current bank-4 INI. In particular:

* Esc emits 0B 04 (End edit), while Alt+Q emits menu Q.
* Ctrl+Up/Down map to TINST's named Scroll down/up slots; labels are not swapped
  to make them sound more intuitive.
* Alt+Left/Right use ANSI fallbacks, not A1/A3; Alt+Up/Down use history.
* Experimental Z1 CF/DF bindings have no matching primary table entries.
* The two FF alternatives are Nothing; 8F extension syntax remains unimplemented.
* Block controls still mix ASCII control bytes and multi-byte commands.
* RunCPM console_bits masks output, not this high-bit input path; corrected
  an older misleading sentence in the preset discussion.

BBC control bytes were checked against the installed B2 DIST.Z80 table.
MBASIC local-composer ownership was checked in profileKey/keyboardAction.
No fresh interactive Turbo, FAND, BBC or physical-board acceptance is claimed.

== Later 261014 follow-up: RunCPM SPEED documentation

Added SPEED near the beginning of both UG and RG, including the observed
44 MHz result, and to the RG shared-command table and UG diagnostic table,
with a focused RG explanation. Source review: C1 SPEED.Z80 accepts decimal 0..65535
and calls BDOS 254; cpm.h updates cpuDelayInstructions; cpu1.h checks each
instruction group against a 10 ms interval. globals.h defaults to zero.
No core or helper implementation was changed or executed for this review.

The user reports VTCPU at about 44 MHz with SPEED 65535 on both native desktop
and web, using an i7-10710U system described as 1.1 GHz. The guide labels this
as an observed equivalent Z80 benchmark rate, not a CPU-clock calibration or
an independent agent measurement. 65535 is the fastest throttled setting;
0 is unthrottled. No-argument SPEED prints usage, not the current value.
