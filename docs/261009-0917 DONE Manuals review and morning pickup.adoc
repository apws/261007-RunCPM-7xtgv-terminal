== One newly confirmed edge case: not fixed

A separate maximum-length history probe saved a 127-character application-bank
entry and reloaded only 126 characters, losing its final sentinel. The load
buffer in `terminal_runtime.cpp` is `MaxLine` bytes, but the serialized record
also begins with `>`. This predates the filtered-recall change and is not a CRC
failure: serialization contains all 127 bytes; runtime parsing truncates one.
CCP bank 0 already has a smaller recall limit.

Reproducer: `/tmp/xtgv-history-length-probe.cpp` and executable of the same
name without `.cpp`, exercising production write/load routines via runtime
stubs. Output: `Saved 127, reloaded 126 bytes; final sentinel retained=0`.
No production parsing change was made. Next step: agree the narrow correction,
add a permanent 126/127-character round-trip regression, account for the record
marker in the load buffer, and rerun persistence/CRC tests. Do not silently
alter history format or normalize user entries.
