== Current implementation, not the old plan

Source paths below are relative to `src/7xtgv-vt100-runcpm/`.

* `src/terminal/terminal.cpp`: ESC ( 0 / ESC ) 0 designate DEC graphics
  into G0/G1; B selects ASCII. SI/SO selects G0/G1. Printable bytes 5F..7E
  retain their byte plus a per-cell Graphics flag, resolved when written.
  Later charset designation does not reinterpret existing cells. Saved cursor
  state includes designation/invocation state.
* `src/terminal/terminal_runtime.cpp`, `graphicsRow`: dedicated 6x10 masks,
  independent of QL font banks. Horizontal line is row 4 (zero-based), vertical
  stroke is column 2. Full-width masks join at cell edges; integer zoom scales
  the same raster. No new font is needed just to draw tables.
* `graphicText` in the same file maps graphics cells to Unicode for the PC
  mirror. PC font rendering is NOT proof of the TFT's bitmap shape.
* VT52 F/G currently uses this same graphics machinery; this does not establish
  faithful coverage of a separate historical VT52 character repertoire.
* Existing host tests cover designation, cell flags and frame output, but are
  not an exhaustive bitmap/edge-join certification for every glyph and zoom.

Thus 32 positions are accepted, six are missing, and two are approximations.
This inventory does not claim that every existing mask is aesthetically final.
The QL header's bit-order comment and the renderer's `0x80 >> x` consumption
also need reconciliation before importing glyph bytes; do not blindly copy a
different font's packed rows. No existing QL bank has been changed here.

== TEST 4 now prepared locally

Maintained source: `cpmdrive/A7 - MBASIC and VT tests/VTESTS.BAS`.

. Page 1 fits 40x16: a continuous three-column/two-row frame, all corner and
  tee orientations, crossings, mixed ASCII labels, explicit G1 SO/SI sample,
  checkerboard, diamond, degree, plus/minus, dot and five scanline samples.
. Page 2 fits 40x16: all 32 positions, 5F..7E, in groups of eight. Each group
  has hex codes, original ASCII bytes and corresponding DEC-rendered cells.
  Blank, missing and approximate entries are deliberately not hidden.
. Enter advances from the first page; Enter on the second returns to the menu.
  Run-all mode traverses both pages using the existing automatic pause.
. Exit restores SI and ASCII designation for both G0 and G1. Normal palette
  behavior and tests 1/2 remain unchanged; the other legacy pages retain their
  existing layouts. The old fixture under `tests/` is not the maintained A7 source.

Use MBASIC `LOAD "VTESTS"`, `RUN`, select 4 after a separately requested upload.
Save maintained edits with `SAVE "VTESTS",A`. Source remains CRLF plus Ctrl-Z,
with no source line over 80 columns. Explicit short PRINT records prevent
MBASIC's own output-width wrapping from splitting escape sequences.

Local `tools/test_vtests_basic.py` passes: five ASCII programs load, SAVE ,A
round-trip, all eight menu choices, both DEC pages, emitted row/column bounds,
continuous frame commands, G1 sample and complete 32-code chart. Linux RunCPM
checks emitted bytes, not this firmware's parser or physical renderer.
The new page has NOT been uploaded or hardware-accepted in this task.

Hardware checklist: inspect every join and chart entry on W535, compare TFT
and mirror, repeat useful integer zoom levels, return to menu and verify ASCII.
Then repeat on RP2_2 as part of the requested current-state regression. A later
protocol test should add saved-cursor/charset restoration, erase/scroll/pan
and designation changes without changing already-written cells.

== Fonts and a possible editor

Six-by-ten is supported by an established source:
https://www.cl.cam.ac.uk/~mgk25/ucs-fonts.html[Markus Kuhn's X11 fixed fonts]
lists 6x10 and DEC VT100 graphics coverage. Its page also points to gbdfed,
the bitmap editor used for those fonts. These are reference/reuse candidates,
not imported assets; inspect actual BDF metrics, packing and attribution before
reuse. Compare with Petr's forthcoming complete QL font first.

An MBASIC editor is feasible as a separate small demo: a 6x10 bit array,
cursor/toggle/clear, enlarged cells, and ten saved row values. Two text columns
per pixel give a 12x10 editing area with a near-square appearance on a 6x10
text raster. One-cell-per-pixel is simpler but visibly stretched vertically.
Start with ASCII data export, not dynamic font upload.

A real-size 6x10 preview could use the EXISTING private GCLS/xterm256 plot
transaction, which draws physical pixels. Ordinary color SGR alone only colors
text cells. The plot is transient, is not present in the PC text mirror, and
can be overwritten by text repaint. Keep the enlarged editor grid usable in
the mirror; treat pixel preview as an optional TFT-only addition. No editor or
new protocol is implemented/approved by this note.

== External tests and visual references

* https://invisible-island.net/xterm/ctlseqs/ctlseqs.html[xterm control reference]:
  designation/invocation and separate double-size line controls; useful for
  keeping DEC Special Graphics distinct from other DEC terminal features.
* https://invisible-island.net/vttest/vttest.html[VTTEST]: maintained host terminal
  tests, including character sets. Not a CP/M COM binary; many tests exceed
  our intentional subset, so do not call every unsupported test a regression.
* https://www.roysac.com/vt-100.html[VT100 animation gallery]: general inspiration,
  not verified DEC glyph coverage or verified CP/M compatibility. Its own page
  warns the JavaScript text view is not always accurate.
* https://www.youtube.com/watch?v=AVb2DMGUi1M[Petr's video reference]: retained;
  retrieval failed, so its implementation language/source availability was not verified.

No additional CP/M DEC demo binary was verified or installed. Our expanded
MBASIC page is the immediate reproducible CP/M example. CRT scanline styling,
native font memory and full terminal conformance remain separate decisions.
