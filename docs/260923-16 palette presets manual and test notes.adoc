The low three bits select hue and bit 3 selects emphasis. These are native
palette indices, not ANSI color numbers. ANSI red still uses SGR 31, yellow
33, blue 34, etc.; the decoder translates those numbers. SGR 1 adds emphasis;
SGR 90..97 selects it explicitly. Existing RGB values are preserved.

== Configuration and overrides

Palettes are sections in `A0:7XTGVTRM.INI`, not a separately loaded file.
Each of ten slots starts from built-in PAPER defaults. Entries are optional;
invalid entries are diagnosed and do not overwrite valid/default values.
Editing palette 0 does not implicitly modify slots 1..9.

`[global] mode_palette=0..9` is applied before the CP/M boot text.
Use three decimal RGB components, each 0..255. `RGB565` and symbolic color
names in the earlier brainstorming note were placeholders, not accepted syntax.

Existing explicit bank `active_line_rgb`/`cursor_rgb` settings and global
gutter settings retain precedence. Use `palette` on those keys to inherit
the currently selected palette. In particular, the existing local INI contains
explicit colors in many banks: changing only the palette will not override
those intentional settings. The initial implementation left the user INI alone;
the explicitly requested follow-up preparation is recorded below.

These are terminal UI roles, not extra native paper indices. Native text
still has four papers and sixteen inks.

== Runtime selection and saving

After deploying the new firmware and `VTPAL.COM`:

[source,text]
----
VTPAL 0
VTPAL 1
VTPAL 2
----

No argument selects 0. Only one digit 0..9 is accepted; invalid arguments
print usage and send no selection event. The helper emits `ESC[>69;n v`
(without the explanatory space before `v`) through BDOS 9. The private
command works under both ANSI and VT52 output interpretation.

The live selection preserves cells and cursor position, invalidates text/UI
rendering, and updates the RGB mirror. A real selection change is saved after
the existing 1500 ms quiet period, or by the existing forced-sync path.
Only `mode_palette`, `backlight_level` and the active HAL's `view_zoom` are
rewritten; palette definitions, unrelated sections and comments are preserved.

The normal save path uses its existing temporary-file/backup transaction.
This is not a new filesystem or write-back cache.

An active GCLS plot defers selection until plot end/abort. The subsequent
explicit full redraw replaces a retained plot image; xterm256 color conversion
itself remains untouched. Cells cannot reconstruct that direct pixel image.

Selection does not implement marker attributes. Do not add `mode_attr=markers`
yet; underline, reverse and blink keep their existing behavior.

palette parsing/defaults/errors, overrides/inheritance, ANSI/VT52 selectors,
TFT/mirror repaint, zoom preservation, plot deferral and lazy-save snapshots.
The actual sketch settings writer is tested with a memory-only File adapter

== Dark-theme ink-pair tuning, 260923

After visual testing Petr requested normal/ALT exchanges in palettes 1 and 2
for native hue indices 1, 2, 5, 6, 7: red, green, cyan, magenta, yellow.
Swapped `ink01/09`, `ink02/10`, `ink05/13`, `ink06/14`, `ink07/15` in each
of those two INI sections. Pairs 0, 3, 4, every paper/UI setting, and palette 0
are unchanged. An exact comparison confirmed only these 20 entries changed;
the production INI parser reports zero errors. This changes configuration only,
not the firmware's built-in fallback palette or the ANSI index translation.

The earlier tables/examples describe the initial palette, not these subsequent
dark-theme swaps. Optional VTPAL.INI comparison presets 3..6 still contain the
initial ink pairs: align those with the tuned base presets before deploying
them for a background-only comparison. They have not been installed on device.

For reference, conventional ANSI indices 0..7 are black, red, green, yellow,
blue, magenta, cyan, white; indices 8..15 are the corresponding bright variants.
Our internal indices 0..7 are normal ink, red, green, blue, silver, cyan,
magenta, yellow; 8..15 are their ALT partners. The ANSI decoder explicitly
maps between these orders. Palette 0 includes all four paper and sixteen ink
RGB entries explicitly, preserving the original PAPER appearance.

Transferred the tuned INI to A0: with CP/M text normalization and verified
all 13312 padded bytes by read-back. Exited VTPAL.BAS and MBASIC cleanly first;
restored the attached Konsole mirror afterward. No reboot/reflash performed;
the new definitions take effect at next configuration load (boot).

Petr reports pronounced transfer-screen blinking newly noticed after palette
support. Code review confirms VTPUT explicitly clears once per 32-byte chunk,
VTGET once per 128-byte record. CSI 2J triggers a full surface fill, followed
by dirty-cell repaint. JC8048W550 uses GFX_DEFERRED_FLUSH, not the buffered-
canvas branch, so its repaint budget is only 720 pixels per pass (12 cells
at 1x, 3 cells at 2x). These paths and budgets also exist in pre-palette HEAD
1be7630; palette work changed the fill color source and adds a full redraw on
actual palette selection, not on ordinary transfer chunks. This establishes
an inefficient redraw mechanism, but does not establish the cause of the
reported new severity. No renderer change was made during this inspection.
