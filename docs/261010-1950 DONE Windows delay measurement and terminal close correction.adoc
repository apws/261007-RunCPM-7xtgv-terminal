performance and real-mirror proofs. Evidence below is relative to

The default, software and headless logs confirm a successful 1-ms timer-resolution
request. It did not shorten standard-library sleep. SDL presentation averaged
406 microseconds in default mode, 699 in software mode and 1 headless; sleep
dominates all cases. This supports the earlier calculation: 528 ES3_5 drawing
passes at roughly 15 ms account for the reported eight-second screen refresh.
It does not establish a particular internal MinGW or VirtualBox cause.

`mirror-proofs/mirror-bysythpd/` passes quit, EXIT, REBOOT, VTLOOP, VTFLOOD
and hangup, all using a card path containing spaces and Czech characters.
The Unicode startup correction is therefore confirmed natively for card paths.
True PTY master close fails in the Python owner: stdin read raises EIO while
MSYS still reports it as a TTY. The native child nevertheless finishes normally,
PUN/history artifacts exist and the card lock is released. The subsequent
native transfer case was not reached.

== Correction

* Windows-only desktop Arduino delay functions now use a high-resolution
  waitable timer, with one scoped handle per thread. Relative one-shot waits
  avoid a busy loop. Unsupported creation or failed waits fall back to standard
  sleep; the startup log identifies the selected method and wait errors are
  logged. The scoped timer-resolution request is retained.
* Diagnostic `--coarse-timer` keeps the preceding standard-library sleep and
  suppresses the timer-resolution request, preserving a comparison baseline.
* Shared mirror stdin reading treats EIO/ENXIO as EOF at that exact boundary,
  without depending on `isatty`. Other read errors still propagate.

Implementation is confined to desktop `platform.cpp`, `platform.h`,
`application.cpp` and mirror `tools/terminal.py`, with a focused regression and
supporting documentation. No RunCPM core, terminal drawing budget, physical HAL
or INI changes. All 301 working-card file hashes match the preceding baseline;
existing sessions remain untouched.

Microsoft documents the high-resolution flag for Windows 10 1803 onward:
https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-createwaitabletimerexw[CreateWaitableTimerExW].
Relative due times use negative 100-ns intervals:
https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-setwaitabletimer[SetWaitableTimer].
These API contracts do not guarantee the VM's measured wake-up latency.
