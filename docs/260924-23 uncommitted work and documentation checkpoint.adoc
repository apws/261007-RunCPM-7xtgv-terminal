== Proposed manual structure: simple outside, explicit inside

Petr proposed this during the review; recorded as direction, not a file move:

[cols="2,5",options="header"]
|===
|Document |Owns
|User Guide |Short first start, target selection, mirror attachment, normal
keys, applications, safe transfers and simple recovery. Worked tasks with
sensible defaults; no parser or HAL internals required to get started.
|Reference Guide |Authoritative implemented commands, key chords, INI fields,
defaults/ranges, palette/ANSI mappings, compatibility and current limitations.
The present combined manual is the starting point, not a second duplicate.
|Technical Reference Guide |Architecture/data flow, HAL boundaries, rendering and
buffers, host/device protocol, current VT adaptations, build/test boundaries.
Future native 7xtgv is explicitly marked planned and linked to its own specs.
|===

Each fact should have one authoritative home. The User Guide links to exact
Reference entries; the Technical Reference Guide explains why/how rather than
copying user tables. Keep dated design/test reports as evidence, not mandatory
reading for ordinary use. Link proposed native behavior separately from shipped
VT behavior. A small entry-page index and stable section anchors are enough;
no new documentation framework is needed. Split incrementally in an explicit
documentation task, preserving links and checking them after moves.
