= BBCLOWER terminal smoke — 260917
:source-highlighter: highlight.js

This was a short live test on the ES3++_++5 device and its Konsole mirror after the legacy ANSI/VT52 work. No firmware, A1 files, or `+.TOK+` data changed. The test started at `+A0>+` and ended at `+A0>+` with reserved profile ++#++9 selected.

== What this BBC package can test

The shipped `+A1:DIST.Z80+` is BBC BASIC (Z80)'s CP/M hardware adapter. It defines character-at-a-time editing codes (`+Ctrl-G/O/J/L/F/N+`, etc.) and an 80-column default. Its native `+CLS+` and cursor-position routines are `+RET+` stubs, and cursor-position query returns `+(0,0)+`. Thus this BBC build has a useful REPL/editor input path, but its native `+cls+` is *not* a test of ANSI or VT52 screen clearing. `+PRINT CHR$(27)+` can deliberately emit terminal control bytes; the terminal's profile can also inject such a PRINT command.

== Live sequence and observations

[arabic]
. Selected reserved bank ++#++9, changed CCP from `+A0>+` to `+A1>+`, and launched `+BBCLOWER+`. Lowercase `++print 2+2++` returned `+4+`.
. `+print "before-cls"+` printed a marker. Lowercase `+cls+` left the marker visible and returned to `+>+`, consistent with the adapter's `+CLS: RET+`.
. Lowercase `+print chr$(27);"[2J";chr$(27);"[H";"bbc-ansi"+` cleared the mirror and printed `+bbc-ansi+` at its top. This validates raw ESC/ANSI output through BBCLOWER, not its stubbed native `+cls+`.
. Entered `+10 print "edit-ok"+`, then lowercase `+edit 10+`. BBCLOWER displayed an editable `+10 print "edit-ok"+` row. Enter accepted it unchanged; `+run+` printed `+edit-ok+`. Lowercase `+quit+` returned to `+A1>+`.
. Explicitly selected BBC profile ++#++5 at the CCP prompt. Its `+on_select+` sent `+A1:+` as configured. Launched `+BBCLOWER+` again. The simulated Konsole Alt{plus}Backspace event (`+CSI > 61 v+`) cleared the mirror and left a fresh `+>+` prompt. The simulated Alt{plus}Esc event (`+CSI > 60 v+`) sent the profile's lowercase `+quit+` and returned to `+A1>+`.
. Restored profile ++#++9 and `+A0>+`. No direct history recall, deletion, arrow keys, or `+.TOK+` completion was exercised. The terminal-generated clear and exit commands bypass history insertion by design in `+profileCommand+`; no BBC history file was read or rewritten by the agent.

The actual physical Alt{plus}Backspace/Alt{plus}Esc chords were not pressed. The test sent the same private CSI actions that the project's Konsole keytab maps those chords to. This verifies the firmware/profile behavior but not the physical keyboard or Konsole mapping on Petr's machine.

== Scope and next checks

This pass found no new BBCLOWER failure and made no code changes. It does not certify FAND, TP301, WordStar, or dBase screen behavior. BBC profile ++#++5's individual arrow/edit bindings and live history insertion still need a separate interactive check if desired; this pass deliberately avoided polluting Petr's BBC keyword history. `+A1:BBCBASIC.TOK+` remains an editable corpus only: loading it as a distinct completion index is the next feature described in `+docs/260915-21 history tokens and editing surfaces.adoc+`.

The console is an 8-bit byte path, not merely printable ASCII. Ordinary BBCLOWER text is mostly printable ASCII; ESC control sequences are bytes with special meaning to the configured terminal decoder. Single-byte `+0x9B+` C1 CSI is outside 7-bit ASCII and requires Console8. This pass used 7-bit ESC CSI only; the preceding MBASIC hardware tests covered C1 CSI.
