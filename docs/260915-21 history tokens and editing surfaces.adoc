= History tokens and editing surfaces — 260915
:source-highlighter: highlight.js

This note follows `+260915-19 BBC BASIC and app history handoff.adoc+`. Petr is entering BBC BASIC keywords/functions in profile ++#++5 on A1. The original 100-entry bank is circular, so the earliest `+abc+`-range entries have already been overwritten. A device snapshot can export only the currently retained entries, not those lost entries. Preserve their order, case and duplicates; do not claim the snapshot is a canonical BBC BASIC vocabulary.

== Current implementation

`+LineHistory+` now has 255 entries per bank. The bank model is in terminal RAM: Up/Down reads it directly, with no SD access per keypress. Unfiltered recall indexes the circular bank directly. Filtered recall scans matching entries in the active bank and wraps; its worst case is 255 short in-memory comparisons. At boot, the validated A0 `+7XTGVTRM.BUF+` is loaded once; changes are saved after a 2-second idle period or forced `+SYNC+`/`+REFLASH+`, using verified `+.NEW+`/`+.BAK+` rotation. On ESP32 targets the larger history object is allocated in PSRAM; other target RAM budgets need explicit hardware verification before assuming all ten full banks fit there. The pending 5-inch build is kept in staging while Petr tests the prior candidate in `+new+`.

The profile now declares `+editing_surface=line|screen+`. BBC BASIC/MBASIC/CCP default to `+line+`; TE and TURBO default to `+screen+`. This is not the existing `+screen_line+` option: `+screen_line+` means deriving an editable _line model_ from displayed cells. The new surface field is classification only; it does not yet change key handling or enable screen-editor insertion.

`+tools/history_to_tokens.py+` validates the v2 history CRC (or accepts legacy v1), extracts one `+[bank]+` section, removes each `+>+` record marker, and writes CR/LF lines plus Ctrl-Z as a CP/M-readable `+.TOK+` file. For BBC the intended snapshot is `+A1:BBCBASIC.TOK+` from bank ++#++5. Use an explicit device `+get+` into a temporary host directory, convert into the `+cpmdrive/A1 - BBC BASIC/+` source mirror, then explicit `+put+` to A1. A live transfer briefly stops the shared mirror and running CP/M app; restore user-visible `+kon.sh+` afterward. Do this when Petr finishes entering tokens, so the snapshot is not stale.

== Next design step (not implemented)

Keep tokens distinct from entered-command history. A profile may name a `+.TOK+` file; at profile selection or boot, load its plain 8.3 CP/M text lines into a separate in-memory completion index. A token may be a keyword, function name with parentheses, identifier or reusable phrase containing spaces. Define duplicate/order and completion priority rules against history before implementing. The `+.TOK+` file should be editable from CP/M, but the terminal must never re-read it on every cursor keypress.

Line-oriented REPL/editor profiles can compose a completed whole input line and use that app's `+history_clear+`/retype controls. Full-screen editors such as TE need a different cursor-local insert transport: ordinary cursor movement continues to belong to the editor, while an explicit chord such as Alt{plus}Up/Down starts completion at a tracked token boundary. That boundary must also work inside an indented or unspaced source line; it cannot be inferred reliably from arbitrary displayed output or programming-language syntax. Key chords should remain configurable and be translated to the same MCU terminal input events, whether generated by desktop Konsole or a simple UART/SPI/I2C XITU-T keypad. No USB-HID dependency is implied.

== First A1 BBC snapshot

This file is a useful initial token corpus, not a complete language specification.
