== SDL presentation

`--window-scale N` accepts integers 1 through 9, default 1. Both Linux and Windows
launchers forward it to the native process, including after guest REBOOT.
The SDL client dimensions are panel width/height multiplied by N; resizable
window flags are removed and minimum/maximum size requests are identical.
Nearest-neighbour rendering with integer scaling preserves the panel image.
The selected board geometry, guest terminal dimensions, terminal glyph zoom,
INI settings and native framebuffer snapshots are unchanged.

Examples from a chosen target's launcher directory:

[source,sh]
----
./desktop-local.sh --window-scale 3
----
[source,bat]
----
desktop-local.cmd --window-scale 3
----

Choose a factor that fits the host screen. Host compositor/DPI policy is outside
the guest framebuffer; the Windows VM still needs a visual size/resize check.
SDL startup logs the requested panel/scale/size and renderer. Brightness changes
log the board PWM duty and resulting RGB multiplier for comparison.

== Brightness and key audit

The Linux and Windows executables use the same board duty table and
`xtgvDesktopBrightness` formula. No brightness curve was changed. The apparent
platform shift is not yet explained by measurements: compare the same board,
logical level and card INI, then inspect duty/RGB logs. The portable presentation
test now prints the complete level-to-RGB table. Different VM graphics and host
display processing may affect appearance; this checkpoint does not diagnose them.

The initial Mintty profile lacked numeric brightness/OFF definitions. The
complete Konsole comparison also identified missing explicit number-row mode/RAW
and transfer-panel routes. Existing mirror Alt-character fallbacks already
provided some bank selection, so absence of a direct Mintty binding did not
mean every bank shortcut was absent.

Konsole's `tools/7xtgv-terminal.keytab` is the reference for control semantics;
Mintty's syntax and character handling differ. Special/navigation/function keys
use shared firmware key identifiers; many Konsole legacy navigation controls
and Mintty versioned events therefore differ in bytes but select corresponding
profile events. Positional Czech ordinary typing, keypad decimal identity and
arbitrary modified-letter INI bindings are not fully reproduced by Mintty.
Do not describe this as complete physical-key parity.

Mintty character KeyFunctions use unshifted layout names and can merge modifier
lookup paths. Sending a fixed OFF string for an Alt-number tag could steal
ordinary Alt+0. The new Windows-only `mintty_keys.py` instead decodes numeric
KeyFunctions actions, whose emitted sequences include the actual modifiers.
Codes 900..912 are local to this profile/helper boundary; they are not firmware
commands. A bounded incremental decoder preserves other input and times out
incomplete sequences. Shared `terminal.run` accepts this optional input decoder;
Linux calls use the unchanged default. Local runtime staging includes the helper.

[cols="2,2",options="header"]
|===
|Chord |Decoded control
|Alt+0..9 |Select bank 0..9 (`CSI >20v` through `>29v`).
|Ctrl+Shift+1..9 |Brightness levels 4,7,11,14,18,21,25,28,31.
|Ctrl+Left-Alt+Shift+0 |OFF (`CSI >63;0v`).
|Ctrl+Left-Alt+Shift+1/2 |ANSI/VT52 (`CSI >1v` / `>2v`).
|Alt+Shift+3 |RAW toggle (`CSI >15v`).
|Alt+Q |Configured application exit (`CSI >60v`).
|Ctrl+Shift+X |Host transfer panel (existing prefix m action).
|Ctrl+Left-Alt+C |Existing emergency-return key event; ordinary Ctrl+C preserved.
|===

Tests compare the decoded global controls directly with Konsole definitions and
check fragmentation, other input, modifier distinctions and ordinary Ctrl+Q/X/C.
Digit and Czech number-row tags are supplied. Mintty may protect layout-generated
control characters or decline shifted-character remaps; key-function handling of
the plus character is also a native-probe concern. The expanded keyboard probe
records both raw wire bytes and decoded controls. A correct decoder is not proof
that a physical Windows key reaches it. Existing ASCII prefix alternatives remain.

Alt+Q is now an explicit exit alias in Konsole and both Kitty configurations.
The generator excludes the previous generic Alt+Q event so regeneration cannot
replace the alias. Alt+Esc remains on Linux. Windows Alt+Esc cycles windows;
no global Windows keyboard hook or system setting was installed.

== Windows launcher logs

The three requested target wrappers remain thin. They identify a same-named
adjacent log through `XTGV_SHORTCUT_LOG`; shared Windows bootstrap/build/run
helpers own progress and logging. Logs include bootstrap selection, target,
progress/result and errors. Rebuild retains its detailed build-directory log
and includes those details in the adjacent transcript at completion/failure.
Local/card logs identify the dated session, append native startup/SDL output,
and record reboot/shutdown. The compiler transcript is not flooded onto screen.

The stale build message claiming interactive Windows launch was still pending
is removed. Local D: snapshot wrappers receive the same adjacent-log behavior.
Smoke/proof/test wrappers keep their existing evidence workflow. Each new
invocation replaces the adjacent transcript; dated per-session logs are retained.
Concurrent sessions can interleave an adjacent transcript if the same launcher
is reused for different cards; their dated logs remain the authoritative evidence.
