== Scope

Implemented the bounded ES3_35 frontend authorized by Petr after
link:261012-1347%20PLAN%20Standalone%20browser%20input%20and%20screen%20snapshots.adoc[the standalone plan].
The default `tools-web/desktop-local.sh` now opens one browser page with input,
framebuffer display, frozen text snapshots, image/text copying and card ZIP
import/export. It needs no external terminal or application bridge.

The original C/C++ RunCPM and 7xtgv-terminal still execute in Wasm, with RunCPM
on the existing pthread worker and terminal/UI work on the browser thread.
No RunCPM-derived CCP, BDOS/BIOS, CPU, disk, console or common abstraction was
changed. No MCU build/flash, card deployment, commit or push was performed.
The existing native-mirror proof remains selectable with `--native-mirror`.

This is a tested fixed ES3_35 browser implementation, not completed generic
runtime board profiles or acceptance on every browser/OS. Petr subsequently
accepted the current browser setup; see the follow-up below. Native Linux/Windows
tooling is unchanged.

== Source boundaries

[cols="2,4",options="header"]
|===

|`web/serial_link.js`
|Bounded ordered input queue, whole short frames, cancellation of wholly unsent events on blur, and fresh attachment after reboot.

|Frozen selectable text panel, refresh/copy/download. No keyboard dispatch or ANSI parser.
|`web/card.js`
|Browser ZIP validation, MEMFS installation/snapshot and export using pinned local fflate 0.8.2 (MIT).
|`web/standalone.js`, `.html`, `.css`
|Small page controller, controls, lifecycle wiring and layout. These are readable maintained sources.
|`tools-web/build_assets.py`, `browser.py`
|Build-time key-ID/config generation and card packaging; optional standard-library static server with isolation headers. No runtime input/output relay.
|`desktop/web/serial.cpp`
|Retains serial byte transport; adds atomic acceptance for browser key frames through the existing Serial FIFO.
|`src/terminal/terminal_runtime.h/.cpp`
|Adds only an `XTGV_WEB`-guarded, UI-owned, read-only text snapshot. Native builds do not include this accessor.
|`desktop/web/application.cpp`
|Copies snapshot text/geometry to JavaScript through the web export. Existing framebuffer publication and guest lifecycle remain.
|===

The six project JavaScript modules total about 434 lines at this checkpoint.
Generated Emscripten glue is separate: 92951 bytes, with a 364869-byte Wasm
module. The vendored unminified ZIP helper is 89198 bytes. These sizes exclude
card contents and are not browser process-memory figures. Initial Wasm memory
remains 128 MiB with growth enabled. No frontend framework, jterm or xterm.js
is used. The SDK remains a build dependency only.

Key IDs are generated from `src/terminal/key_chords.h`; optional number-row
configuration is read by the existing host configuration helper at packaging
time. JavaScript does not duplicate application profiles or INI interpretation.
The snapshot uses active dimensions and `terminal.index()` stride, reuses the
existing DEC graphics-to-text mapping, and never consumes mirror dirty flags.

== User interaction

Click the display to focus the keyboard; its outline turns green. kbd:[Ctrl+\]]
releases focus, and page controls remain ordinary browser controls. Use the
existing bank, zoom, backlight and application-exit chords. kbd:[Alt+Q] sends
profile exit; *Stop* ends the emulator. These are distinct operations.

Plain guest text/paste accepts ASCII, Tab and normalized newlines. Unsupported
composed text is reported; it is not silently transliterated. Existing mapped
key events retain their ordinary fallback bytes. Number-row conversion is
optional and may be changed for this page session. AltGr is not treated as a
request for Ctrl+Alt emergency exit. Browser/OS-reserved keys remain a limit.

*Screen text* takes one frozen copy of the complete logical text grid. Refresh
is explicit, so continuing guest output cannot move the user's selection.
Copy text and `.txt` download use that same snapshot. It is neither scrollback
nor a continuous transcript. The optional raw TX logger was deliberately deferred;
terminal TX is drained even though no live terminal widget consumes it.

*Copy image* and *Download PNG* capture the published framebuffer at 480x320,
including graphics and displayed brightness. Clipboard actions use browser
APIs from user clicks; selectable text/downloads are the fallback when access
is unavailable. No screen reconstruction from CSI is involved.

Display scale 1 through 9 uses whole CSS multiples and disables smoothing.
The native backing image stays 480x320. Window resizing clips/scrolls the
panel instead of stretching it. Fractional OS/browser scaling is explicitly
not compensated; Retina and fractional-DPR appearance are browser presentation
properties. Native PNG contents remain exact.

== Card and hosting

The local launcher packages a private static site under
`build/RunCPM_7xtgv-terminal/desktop-web/sessions/standalone-*/`.
It copies the source card read-only, excluding private directories, symlinks
and ownership locks. Files are imported into MEMFS; no live host directory
is mounted. The source card is not locked or written.

Stop completes guest saves. Then Download card ZIP exports directly from the
browser, with no server-side duplicate. Restart current card starts a fresh
runtime from that stopped card; Load card ZIP replaces it after stopping.
Guest REBOOT also restarts with current MEMFS contents. Closing or reloading
without downloading loses changes; the page warning is best effort only.

The ZIP helper enforces 32 MiB compressed/expanded and 10000-entry bounds,
root A/0, path validity, uniqueness and file/directory consistency. Imported
entries become regular files/directories, not host symlinks. The helper and
its license are bundled locally; no CDN fetch is needed at runtime.

The static bundle can be hosted with COOP/COEP headers and a secure context
(HTTPS or localhost). There is no requirement for Python on a deployment host;
`browser.py` is only a local convenience. `file://` is not supported by the
pthread route. Loaded input/copy/export work without a server, but a fresh
runtime/reload may fetch module assets again; no service-worker offline cache
is claimed.

== Launch and human acceptance

From `src/RunCPM_7xtgv-terminal/tools-web/`, or the ES3_35 target wrapper:

[source,bash]
----
./desktop-local.sh --window-scale 2
----

Setup/build/static-hosting details are in the
link:../src/RunCPM_7xtgv-terminal/tools-web/README.adoc[tools-web README].
The previous bridge is available as `desktop-local.sh --native-mirror`.

[loweralpha]
. On the real Czech keyboard, check ordinary row conversion, keypad decimal,
  AltGr, bank steps, glyph zoom and backlight presets/OFF. Only focused display
  input should reach the terminal.
. Open Screen text, copy some text, continue using the guest and confirm the
  frozen selection stays unchanged until Refresh. Try Copy image/Download PNG.
. Check 1x/2x/3x sizing and page/window resizing on the actual monitor. Fractional
  scaling may make pixel blocks uneven; the page should never smoothly stretch.
. Stop, download the card, load it again and verify a deliberate guest change.

This is a useful browser implementation checkpoint for review/rollback.
Other browsers/hosts, the full keyboard-layout matrix, hidden tabs and runtime
board profiles remain separate work. No commit/push is implied by these checks.

physical keyboard acceptance checklist.
