== Reader-facing changes

The repository README and Build Guide now introduce native Linux and Windows
desktop support at the beginning. Explicit host setup instructions lead to
matching `desktop-rebuild`, `desktop-local` and `desktop-card` launchers with
`.sh` and `.cmd` extensions. Linux remains the hardware build/upload workflow.
Windows uses MSYS2 UCRT64 and needs no WSL.

The Windows sequence distinguishes installing MSYS2, completing its full
update in UCRT64, running project setup from CMD/Explorer, rebuilding, and
launching. It explains C:/D: discovery and explicit installation selection,
package/dependency locations, Git versus source ZIP bootstrap, local guest
storage versus shared-folder latency, and dependency-mismatch diagnostics.
`pacman -Syu` and `-Suy` are equivalent. The update procedure follows
https://www.msys2.org/docs/updating/[the official MSYS2 instructions].

The guide index, source README, User, Reference, Technical Reference and Tooling
Guides introduce both host paths. Matching Linux and Windows SVG tooling diagrams show the launchers,
session owners, transports and separate build operations. The Windows diagram
was checked against windows.cmd, dispatch.sh and windows_run.py, including
Mintty hosting the session owner and the shared terminal.py bridge. The Linux developer desktop
README is labelled as such. Card-path differences are explicit: Linux checks
mounted roots for desktop-card and supports custom desktop-local paths;
Windows requires an explicit desktop-card path and keeps desktop-local tied
to the checkout. The obsolete resizable SDL troubleshooting advice is replaced
with the supported fixed integer window scale.

The only executable-file edit changes setup.sh's final printed instruction
from the obsolete scripted-input limitation to desktop-local.cmd after rebuild.
No installation, build, launch, firmware or card behavior changes.
