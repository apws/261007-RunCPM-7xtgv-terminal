= Terminal application profiles
:source-highlighter: highlight.js

____
INI syntax note (260922): modifier-first chord names in this historical document are superseded by the signed key-first grammar `+<key>[_ctrl][_shift][_alt]+`. See the link:260922-13%20key-first%20INI%20chord%20names%20signed%20implementation%20plan.adoc[refactoring plan].
____

The active `+#0+`–`+#9+` selection combines:

* one independent 100-line history bank;
* an application name and keyboard mapping;
* an optional byte string emitted after selection.
* optional visible-line tracking, display colors, and unified commands.

The firmware reads `+A/0/7XTGVTRM.INI+` once after mounting the SD card and before starting the CP/M command processor. The project mirror is `+cpmdrive/A0 - CP-M core/7XTGVTRM.INI+`. Compiled defaults are used when the file is absent; invalid entries are reported on the boot screen.

== Format

Each `+[bank0]+` through `+[bank9]+` section accepts:

[cols=",",options="header",]
|===
|Setting |Meaning
|`+name+` |Label shown as `+#n name+` during selection
|`+on_select+` |Bytes emitted after the one-second label delay
|`+history_clear+` |Optional app-specific bytes sent before a recalled line
|`+history_retype_delay_ms+` |Pause after clearing before retyping a recalled line (0-1000 ms)
|`+screen_line+` |Read the editable line from the cursor's framebuffer row (`+true+`/`+false+`)
|`+line_prefix+` |Optional prompt excluded from a screen-derived line, such as `+>+`
|`+trim_left+` |Remove application layout spaces before capturing a screen-derived line
|`+activate_prefix+` |Optional prompt that starts the selected app's tracked-line session
|`+escape_cancels+` |Discard the tracked edit when a literal Escape is sent
|`+active_line+` |Highlight every column of the current cursor row
|`+active_line_rgb+` |Cursor-row background as decimal `+R,G,B+`
|`+cursor_rgb+` |Blinking solid block cursor color as decimal `+R,G,B+`
|`+exit_command+`, `+clear_command+` |Profile commands used by the unified Exit/Clear keys
|`+left+`, `+right+`, `+up+`, `+down+` |Plain arrow behavior
|`+home+`, `+end+`, `+insert+`, `+delete+`, `+page_up+`, `+page_down+` |Plain six-key block
|`+ctrl_+` {plus} any name above |Ctrl-modified behavior
|`+alt_+` {plus} any name above |Alt-modified behavior
|===

A key value is `+none+`, `+history_previous+`, `+history_next+`, `+send:+`, or `+send_cancel:+` followed by bytes. `+send_cancel:+` also discards the current tracked edit, which is useful when an application's Page or Escape-like key leaves its editor. Strings recognize `+\e+`, `+\r+`, `+\n+`, `+\t+`, `+\\+`, and `+\xNN+`.

`+screen_line=true+` makes the rendered row containing the cursor authoritative. This captures lines generated by commands such as BASIC `+EDIT n+`, which never arrive as keyboard input. Trailing blanks and an optional `+line_prefix+` are excluded. Ordinary Backspace and semantic Left/Right/Home/End/Delete/Insert operations remain tracked. Screen resynchronization preserves the current history position while Up/Down browse recalled lines.

For screen-derived profiles, recalled text is sent as one replacement at a time. Further Up/Down presses immediately change the desired history position but are coalesced until the application has echoed the preceding replacement. This prevents older line editors such as BBC BASIC from interleaving several clear-and-retype byte streams.

BBC BASIC 5.00's supplied configuration uses `+Ctrl-J+`/`+Ctrl-L+` for Left/Right, `+Ctrl-F+`/`+Ctrl-N+` for Home/End, `+Ctrl-R+` for Delete, `+Ctrl-U+` to clear left of the cursor, and `+Ctrl-X+` to clear right. Whole-line replacement therefore uses `+Ctrl-F Ctrl-X+`. On the ESP32-S3 hardware these two controls may be sent together, but replacement text in the same burst can retain part of the old line. Bank 5 pauses for 50 ms after the clear sequence before retyping. BBC's `+EDIT n+` display also indents the editable program line; bank 5 enables `+trim_left+` so this presentation spacing is not stored in history.

The terminal recognizes a RunCPM prompt at the beginning of the cursor row as `+du>+` or `+duu>+` (drive plus one/two user digits). While it is present, profile and history bank `+#0+` are effective silently. The explicitly selected app bank remains remembered and becomes effective when that prompt disappears. An `+activate_prefix+` can then delay screen-line capture until the application's own prompt appears; BBC BASIC uses `+>+`.

The selected and effective banks are intentionally separate. `++Alt+Space++` always reports the remembered selection, even while a RunCPM prompt makes `+#0+` temporarily effective.

The global shortcuts are configured outside the application sections:

[source,ini]
----
[global]
exit_key=lalt+ralt+escape
clear_key=lalt+ralt+delete
----

The firmware maps either global gesture to the effective profile's `+exit_command+` or `+clear_command+`. A future local keyboard scanner can report both physical Alt keys exactly. Kitty and Konsole expose a processed modifier state rather than reliably identifying left and right Alt, so the present PC bridge uses `++Ctrl+] x/c++` as its unambiguous fallback. Mapping the gesture to Ctrl{plus}Alt{plus}Delete is deliberately avoided because a desktop may intercept it. The supplied Kitty and Konsole profiles also map `++Alt+Esc++` to Exit and `++Alt+Backspace++` to Clear. These are PC-only convenience equivalents; firmware with a local raw keyboard scanner will retain the exact dual-Alt gestures.

The current cursor row uses pale green (`+205,255,205+`) by default across all 80 columns. The blinking cursor is a solid saturated green block (`+0,255,80+`) with a black glyph. Both are renderer overlays: they do not alter the terminal's stored character attributes. Set `+active_line=false+` for a profile that should retain application backgrounds unchanged.

[source,ini]
----
[bank2]
name=TE
on_select=A0:\r
left=send:\x13
right=send:\x04
home=send:\x11S
end=send:\x11D
page_up=send:\x03
page_down=send:\x12
up=send:\x05
down=send:\x18
alt_up=history_previous
alt_down=history_next
----

Selecting another bank before the delay expires replaces the pending command; only the final bank's `+on_select+` runs. The command is unconditional, so change profiles after returning to the CP/M prompt if `+on_select+` contains a drive or program command. Use an empty `+on_select=+` to disable it for a bank.

Configuration changes take effect at the next device boot. The parser accepts normal LF or CRLF files and CP/M `++Ctrl+Z++` end-of-file padding.

`++Alt+PgUp/PgDn++` remains reserved for fast profile selection. Configured `+alt_page_up/down+` bindings use `++Shift+Alt+PgUp/PgDn++`. Viewport movement remains available through the Python helper's `++Ctrl+] a/e/h/l++` commands.

`++Alt+Space++` temporarily overlays the active `+#n name+`, then restores the exact screen row. It does not change banks, discard input, add history, or execute `+on_select+`. Bank `+#9 GENERAL+` is reserved for automated terminal commands; interactive application histories belong in banks `+#0+` through `+#8+`.

`++Alt+#++` or `++Ctrl+]++` followed by `+#+` toggles the temporary `+## RAW+` input bypass. RAW preserves the underlying bank and the normal CP/M output/display path, while ordinary input bypasses history and profile translation. Selecting any numbered bank leaves RAW. `++Alt+Space++` reports `+[## RAW / #n]+` while active. Host tools use explicit private RAW-on/off controls, avoiding keyboard-layout ambiguity.

In the Python helper, `++Ctrl+] x++` sends the effective profile's `+exit_command+` and `++Ctrl+] c++` sends its `+clear_command+`. The current edit is cleared first using `+history_clear+`; the command itself is retained in that bank's history.

== Host keyboard environment

Petr's host uses the Czech layout and the XKB options `+shift:breaks_caps,caps:none+`: pressing Shift clears CapsLock. The 7xtgv bridge passes ordinary punctuation and Shift-produced ASCII unchanged; it must not attempt global case conversion. The installed BBC BASIC (Z80) CP/M 5.00 binary requires uppercase keywords in direct/program input; the modern online manual's lower-case typography must not be taken as a test of this binary. BBC BASIC still distinguishes upper- and lower-case variable names, so a future optional adapter may only uppercase recognized keywords outside strings/comments. A strange quote or punctuation result that also occurs in non-7xtgv host applications is a desktop/XKB or input-method issue, not CP/M or the terminal profile. With the Czech `++Shift+ů++` quote key after CapsLock was active, the present workaround is to touch Shift once to release CapsLock, then press `++Shift+ů++` again to produce `+"+`. This has been observed in Kitty, Konsole and the Codex text field, confirming that it precedes the terminal bridge.
