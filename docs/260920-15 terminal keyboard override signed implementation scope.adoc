This is the implementation decision after the link:260919-19%20terminal%20keyboard%20physical%20keys%20and%20sparse%20overrides%20plan.adoc[original key plan], the link:260920-00%20terminal%20numkeys%20aliases%20and%20key-event%20plan.adoc[character-alias investigation], and the link:260920-01%20main-row%20and%20keypad%20identity%20plan.adoc[Konsole main-row/keypad probe]. == User-visible result

* Recognize the main number row as `+num1+` … `+num9+`, `+num0+`, separate from the numeric keypad. On Petr's tested Czech Konsole layout, these main-row keys send ASCII `+1+` … `+9+`, `+0+` to CP/M by default, including the physical 1 key whose unshifted character is pass:[<code>+</code>]. The implementation uses distinct host key events, not a firmware `+numkeys+` UTF-8 alias table. Pasted text remains text.
* With NumLock on, recognize the keypad decimal key as `+kp_decimal+`. It sends ASCII `+.+` by default even if the Czech host layout produces `+,+`. It may be overridden independently in `+[global]+` or a bank. NumLock-off `+kp_delete+` remains Delete by default. Other keypad digits and operators retain their behavior and are not affected by main-row `+numN+` bindings.
* Accept sparse explicit key bindings in `+[global]+` and `+[bankN]+`, with fixed `+ctrl_shift_alt_+` modifier-name order and all modifier subsets for supported non-letter keys. Add Backspace, Escape, Enter, Space, F1–F12, the main-row number keys, and the photographed punctuation-position IDs. Letters `+a+`–`+z+` are bindable only with Ctrl or Alt, possibly combined with Shift; plain and Shift-only letters remain ordinary typing. Preserve the existing navigation keys, input presets, profile/history editing, and binding actions.
* Resolve bank explicit binding before global explicit binding, then the existing input preset or new key default. `+none+` is an explicit suppress action. Keep storage bounded and report malformed/duplicate/overflow cases rather than silently discarding mappings.

== Host-input boundary and safe rollout

* Translate host key events to a non-colliding private keyboard event before the Konsole PTY byte stream loses modifier/keypad identity. Keep ordinary ANSI CSI keyboard input intact; do not apply generic CSI filtering. Test Konsole first, then the Kitty adapter separately. Keep the original output for unbound keys wherever the host can supply it. Never intercept an unbound key and make it disappear.
* Preserve existing host-owned chords such as Alt{plus}bank selection and Ctrl{plus}Shift{plus}number backlight. Remove the project-specific plain F5 mapping that emits Ctrl{plus}Q,F and the redundant Alt{plus}Shift{plus}digit backlight mappings; do not alter unrelated zoom or viewport chords.
* *Dead-accent exception signed off:* `+bs1+` and `+l3+` must preserve normal host composition when unbound. Do not intercept their unmodified presses merely to claim INI support. Full bank-dependent unmodified overrides for those dead keys are a later host-input task requiring a reliable native or enhanced-event fallback. This phase may support other proven modifier chords on them only if the fallback is safe.
* The isolated Konsole test proved the ten Czech row keys and keypad events can be distinguished on this X11 machine. Its synthetic keypad-decimal key produced `+.+`, while Petr observes `+,+` from his physical key. Test both host variants and verify the physical press during acceptance.

== Implementation and verification sequence

. Add parser/lookup tests and bounded sparse global/bank storage without changing the old preset defaults or RAW-mode behavior.
. Add private host-event transport and Konsole keytab rules for a small pilot: Czech main-row 1, keypad decimal, keypad plus, F5, Ctrl{plus}Shift{plus}A, and one ordinary punctuation position. Confirm keypad isolation and unbound-key fallback before expanding the map.
. Expand to the agreed key vocabulary and modifier combinations, leaving the signed-off dead-accent exception intact. Add Kitty parity and tests for unknown/incomplete private sequences and existing terminal shortcuts.
. Run host terminal tests, then request the usual explicit rebuild/reflash workflow for device acceptance. Check CP/M digit/dot entry, `+[global]+` and bank overrides, history/editor state, TE/TP3, RAW mode, and untouched unbound/dead keys. The native Linux RunCPM port is only an application comparison, not a test of the 7xtgv terminal input path.

Do not overwrite device `+A0:7XTGVTRM.INI+` or history BUF as part of this implementation without Petr's specific approval. The keyboard change may be built and staged only under the repository's normal explicit `+rebuild+` rule.
