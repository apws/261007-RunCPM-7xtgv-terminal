== Purpose and accepted behavior

The maintainer verified the reorganized working card and requested a durable
checkpoint, desktop browsing checks, a later smaller manuals review, and a note
about possibly implementing external 8080/Z80 catalog commands for other systems.

* 7XF is the internal `ccp7xf.h` shell integration. The `7XF` command selects
  named prompt presentation; LS, LL and CD already work from a numeric prompt.
* LS/LL file rows use lowercase display names sorted by extension then name.
  Host filenames remain unchanged. Semantic descriptions belong primarily on
  COM entries, not generic repeated explanations of source/output extensions.
* A current-area heading shows its DIR.7XF description alone at column 2.
  A drive-area overview starts with the whole-drive VOL.7XF description at
  column 2. Both short and long drive/area overviews retain descriptions.
* Empty/catalog-only areas are hidden from area overviews, not deleted.
  Direct CD still reaches COMAL's placeholder area. Zero-byte ordinary files
  count as content; hidden host placeholders do not.
* `/` is the drive overview, not a selectable root directory. CD /B selects
  B's remembered area. CD /B/MBASIC explicitly selects a named flat CP/M DU.
* DIR and LDIR continue to work under named prompts. They retain traditional
  CP/M output and do not gain LS/LL catalogs, sorting or lowercase presentation.

disposable card, excludes live INI/history and pending submit queues, supplies

renders the real Arduino_GFX framebuffer), using the PTY mirror for input and

== Startup and profile navigation

* No dedicated 7XF prompt-style INI setting exists. The compiled default is
  decimal; 7XF selects named style for the running session.
* Existing RunCPM AUTOEXEC.TXT handles one first-boot command at the card root.
  `7XF` alone enables named prompts without SUBMIT or a new firmware feature.
  Preserve any existing startup content. Pending submit work takes precedence.
  This option was tested only on a copy; not enabled on the working card.
* The maintainer renamed/reordered INI banks and uses commands such as
  `on_select=cd /b/mbasic\r`. These are user-defined navigation shortcuts at
  a live CCP prompt, not filesystem mounts, boot actions or commands sent into
  an application. Preserve those names, bindings and history.
* The inspected BBC BASIC profile still used B2:; both numeric and named
  navigation are valid. No normalization of the maintainer's INI was performed.
* FAND/dBase have moved to B5/B6. Current VOL.7XF prose still mentions databases
  on A and describes B as languages only; note this metadata follow-up without
  silently replacing the maintainer's catalogs.

== Future external 8080/Z80 tools: idea only

An external LS/LL-style catalog viewer could reuse DIR.7XF/VOL.7XF conventions
through ordinary CP/M BDOS file operations and directory searches, without
depending on Arduino storage APIs. An 8080-compatible build could be a useful
baseline, with any Z80-specific work separately justified.

* CP/M file lengths may be available only in 128-byte records; do not promise
  RunCPM host-byte precision elsewhere.
* Cross-drive/user searches must preserve the caller's state and respect the
  target system's BDOS behavior; compatibility needs explicit testing.
* An external CD-style utility and persistent named prompts are not automatically
  portable: the resident CCP may restore its own DU state, and it owns its prompt.
  A catalog viewer, selector and full CCP integration are different scopes.
* Nothing external is implemented or promised here. Native 7xtgv remains the
  primary project objective; external catalog tools are a possible later project.
