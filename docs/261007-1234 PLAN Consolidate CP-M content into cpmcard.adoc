== Read-only inventory, after the VTESTS copy

The new `tools/audit_card_migration.py` under the sketch maps descriptive
DU directory prefixes to hexadecimal card directories: `AA - ...` means
`A/A`, not `A/10`. Matching names are folded to uppercase for the *audit*
only; actual host lookup, filenames and file bytes are unchanged. Case
collisions are reported instead of selecting a winner. Symlinks are skipped.

[cols="2,1",options="header"]

|Byte-identical files at the same mapped path |154
|Differing files at the same mapped path |61
|Only in cpmdrive at that mapped path |11
|Only in cpmcard at that mapped path |123
|Case collisions |0
|===

Of the 61 differences:

* 33 have an exact common prefix and additional trailing bytes on one side.
  CP/M record padding is a likely explanation for many, but this category
  does *not* prove that truncation or those tail bytes are harmless.
* 4 have identical printable ASCII before Ctrl-Z but different tails.
* 10 agree after diagnostic-only ASCII newline/EOF normalization.
* 14 require substantive content/configuration review, listed below.
* Timestamps put `cpmdrive` later in 57 cases and `cpmcard` later in 4.
  These are *not freshness verdicts*: card files include 1980/260101 placeholder
  dates, and host copying can change timestamps without changing the payload.

The audit separately inventories 9 cpmdrive and 48 card files outside the
flat DU comparison. This includes metadata, INI history, root files and
non-DU archives. They must not vanish merely because a DU sync ignores them.

[source,bash]
----
python3 src/RunCPM_7xtgv-terminal/tools/audit_card_migration.py \
  cpmdrive cpmcard --output build/card-migration-261007-1234/inventory.json
python3 src/RunCPM_7xtgv-terminal/tests/test_card_migration_audit.py
----

The generated JSON records exact paths, sizes, hashes, UTC timestamps and
classification hints. It contains no automatic apply mode. The report path
must be outside both input trees. A fresh inventory is needed before migration;
normal desktop use can change the live card after this checkpoint.

== Implementation sequence

. *Freeze a checkpoint.* Stop applications writing the chosen roots; record
  hashes, archive both trees and retain Git history. The physical SD is an
  independent working copy, never an automatic mirror destination.
. *Reconcile by content.* Start with the known working card tree. Decide the
  listed conflicts and unique files explicitly. Preserve uppercase 8.3 guest
  names, CRLF/final Ctrl-Z for authored text, and exact bytes for executables,
  tokenized BASIC, archives and other binary files. No blanket text conversion.
. *Make fresh clones reproducible.* `cpmcard/` is currently entirely ignored
  and has no tracked files. Replace that with a reviewed allowlist/manifest of
  project-maintained guest sources and distributable seed artifacts at their
  real card paths. Keep generated scratch files, private histories and personal
  configuration ignored; supply a separate documented example configuration.
  Review third-party licensing before tracking additional imported packages.
  Required local-only programs such as MBASIC need an explicit provisioning
  step and clear missing-file diagnostics, not an undocumented workstation copy.
. *Switch all active tooling together.* Add a shared explicit card-root resolver
  using direct `A/<hex-user>/NAME` paths. Update transfer defaults and DU mapping,
  live-INI fetch/backup destinations, guest assembler/build helpers, VTESTS and
  benchmark fixtures, desktop PTY fixtures, current READMEs and repository
  guidance. Keep launch-time mounted-card selection; no mount path in board HALs.
. *Keep automation off live data.* Test/build helpers copy necessary files to
  disposable card roots. Interactive desktop uses the selected working card;
  a second instance must not write the same root. Deployment is an explicit
  reviewed file list, with extra approval for INI/BUF and no automatic deletes.
. *Prove the cutover.* Clean-clone/provision tests, uppercase DU mapping A--F,
  transfer send/receive mapping, helper builds and quiet SDL VTESTS must pass
  with `cpmdrive` unavailable. Audit current source references; historical docs
  retain old paths as provenance and should not be mass-rewritten.
. *Retire the old root only after acceptance.* Archive unmigrated historical
  assets; remove the tracked old mirror as a separate reviewed commit. Report
  exactly what is retained, moved or intentionally excluded. No permanent
  fallback to cpmdrive that could silently resurrect stale files.

== Remaining choices at implementation time

* Exact allowlist of versioned card content and licenses for third-party files.
* Which mirror-only notes/temporary VTPAL material belong in the runnable card
  versus a host source/archive directory.
* Whether generic Mandelbrot scripts should be separate named examples.
* Where private INI backup history should live outside the deployable tree.

Recommended outcome: *one actual card layout*, no second descriptive mirror,
but a clear distinction between versioned seed/source files and live personal
state. An entire working SD tree is not automatically suitable for publishing.
