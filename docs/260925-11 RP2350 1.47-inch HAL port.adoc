Petr requested the RP2350-LCD-1.47-A as a proof of porting before ESP32-C6
and ESP32-P4. The board is connected in manual BOOTSEL. This checkpoint
adds source/configuration and host tests only; no firmware build, upload,

is recommended once this new port has been tested, without inventing a

== Target and flat HAL integration

Canonical target: `rp2350-lcd-1-47-a`; display/settings ID: `RP2_147`.
The new JSON selects an explicit build define. Its separate sketch profile
pins the same Arduino-Pico 5.4.4, GFX 1.6.4, SdFat 2.3.0, ARM Cortex-M33,
150 MHz and 16 MB flash configuration as RP2_2.

New flat storage and backlight headers live under
`src/7xtgv-vt100-runcpm/hardware/arduino_7xtgv/`:

* `pico_rp2350_lcd_1_47_a_sd_spi.h`: SPI1, SCK10, MOSI11, MISO12, CS15;
  conservative 12 MHz. CP/M core owns storage exclusively.
* `pico_rp2350_lcd_1_47_a_backlight.h`: independent 32-entry trial table,
  minimum duty3, gamma2.2, OFF0/full255. Start from the accepted RP2_2 curve,
  but do not claim its visual acceptance applies to this panel.

The existing display branch uses ST7789, native 172x320, rotation3,
column offsets34, LCD DC16/CS17/SCK18/MOSI19/RST20/BL21. The installed
`Arduino_RPiPicoSPI` uses hardware SPI0, not PIO. It unconditionally calls
`gpio_set_function` on MISO; retain the prototype's otherwise unused GPIO4
instead of passing -1. The LCD schematic has no MISO connection. Do not use
GPIO4 for another peripheral without addressing that driver behavior.

The existing common backlight gate/ramp and RP2350 whole-chip reboot are
reused. Compiled firmware identity and display policy have explicit branches.
No emulator, scheduler, VT parser or renderer changes were needed.

== Geometry and shared INI

The vendor page specifies 172x320, not 170 or176. Landscape is 320x172.
Petr chose zoom1 terminal80x16 with horizontal panning. The physical view
holds52 columns; the two edge views overlap and cover all80 columns.
The terminal can support17 rows, but defaults to16. Zoom2/3/4 defaults are
40x8,26x5,20x4 respectively, all fitting vertically.

`[display:RP2_147]` is independent of `[display:RP2_2]`. When absent, HAL
defaults apply; no INI transfer is required just to try the port. Existing
application-profile geometry overrides still apply. Later INI edits must
start with the explicitly requested live fetch, not a stale host copy.

== Checks and next gate

metadata for all four targets. A dedicated host test checks the new geometry,
SD and LCD pin constants, controller offsets and display setup selection.
Both normal/inverted backlight tests pass, including endpoints, monotonic
steps, startup gate, ramp and cancellation. These do not prove real hardware
or a complete Arduino firmware build.

with its own scheduling review, not part of this ARM checkpoint.
