This is a compact history of the *implemented* 7xtgv RunCPM terminal through
`++261002++`. Each `++YYMMDD-HH++` is a source commit or dated implementation
checkpoint, not necessarily the minute a feature first worked on hardware.
Later rows can refine earlier behavior. The
link:../FEATURES.adoc[feature ledger] tracks individual feature states and
test limits; the link:reference-guide.adoc[Reference Guide] describes current
commands. Plans, imported CP/M packages, and the future native 7xtgv format
are not presented here as shipped features. This page is curated, not generated
from `++docs/features.tsv++`; update both when an implemented feature is added,
renamed, or changes behavior.

== Colour, transfer, boards, and storage

End-of-day `261002` reconciliation records successful A0 CARDMARK deployment:
Petr's `CARDMARK 4096 50` compared 6 MiB and passed, reporting raw reads at
1923.72 KiB/s and restored clock. His global INI SPI request of 40 MHz is
confirmed applied at boot. The earlier firmware-wide read-only 50 MHz trial
passed two VTDRV read checks; these are not write or electrical qualification.
Seven missing AsciiDoc opening table delimiters were repaired in the P4
optimization comparison and memory notes, with rendered structure checked.

At `261002-17`, the link:../261002-17%20P4%20backlight%20calibration%20preparation.adoc[P4 calibration preparation]
adds a diagnostic PWM ladder spanning 0 through 255, with extra near-dark steps.
The fetched device INI remains unchanged. Host backlight tests pass; firmware
rebuild is pending. Display clock/refresh visibility in boot output or VTINFO
is recorded as follow-up, not implemented.
The subsequent `261002-1732` checkpoint moves backlight OFF to
LAlt+Ctrl+Shift+0 in the host maps, retaining Ctrl+Shift+1 through 9 presets
and the existing ANSI/VT52 chords. The private device control code is unchanged.
After testing that firmware, Petr chose PWM duty 3 as the P4 minimum. The
`261002-1758` rebuild replaces the diagnostic ladder with gamma-2.2 shaping,
matching RP2_2's formula while keeping the P4 table board-local.
At `261002-1923`, after acceptance of the curve, a P4-only reboot trial explicitly
zeros and detaches backlight PWM and drives GPIO23 LOW before ESP.restart.
This addresses missing pre-reboot blanking, not a proven fix for the reported
blue startup frame or occasional early boot stall. Host call-order tests pass;
firmware rebuild and hardware testing remain pending.
P4 build `261002-1932` was then built, flashed and boot-verified. Petr confirms
the blue interval is absent during reboot/reflash and accepts the brightness
curve. Other modules remain untested for this change. A separate intermittent
CLS failure during rapid reboot testing is recorded without an established cause.

At `261002-15`, a link:../261002-15%20P4%20full-frame%20redraw%20budget%20trial.adoc[P4 redraw trial]
enables the W535-style full-frame rendering budget after reported light-blue
flashes. That initial HAL-only trial changed no DSI timing or buffering.
Subsequent hardware testing exposed a DSI framebuffer underrun, with occasional
stuck blue display despite a working mirror. At `261002-1645`, a separate trial
halves the P4 pixel-clock request from 80 to 40 MHz (calculated refresh about
34.3 Hz), retaining the full-frame budget and native resolution. Hardware
validation of this lower timing remains pending.

The `261002-13` link:../261002-13%20Global%20SdFat%20SPI%20clock%20and%20CARDMARK%20preparation.adoc[configurable SPI checkpoint]
adds `[global] sdfat_spi` to all five direct-SdFat boards: 12 MHz startup/fallback,
runtime clock selection through SdFat's external hardware-SPI driver interface,
and unchanged per-board buffer policy. Host tests pass; firmware rebuild and
board retests remain pending. CARDMARK's backend/COM launcher are not yet implemented.
The subsequent `261002-1510` checkpoint corrects startup/fallback to 20 MHz,
implements the P4 read-only native CARDMARK service plus 128-byte COM launcher,
and stages a successful P4 build. Host comparison/error/cancellation tests pass;
reflash, COM transfer and device tests are pending.
Petr then removed the CARDMARK firmware-wide read-only prerequisite. Writable
P4 build `261002-1520` stages successfully with the diagnostic enabled; its
operations remain read-only and restore the clock before normal storage resumes.
