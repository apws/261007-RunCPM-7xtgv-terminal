== Short identity intent

Petr would ultimately like one short explicit module/board identifier to be
recognizable during build selection, firmware runtime reporting and INI
configuration. Today's `++display_id++` values (`++ES3_35++`, `++ES3_5++`,
`++RP2_2++`, `++RP2_147++`) are the intended human-facing short codes; the
long `++profile++`/target names presently select host build and upload data,
artifact directories and exact firmware identity. They are currently
one-to-one, but the display/INI group could in principle be shared by more
than one physical board needing different firmware.

Do not rename profiles or redefine `++display_id++` during the mechanical
cleanup. Before unifying the names, inventory build JSON, `++XTGV_TARGET++`,
reflash identity guards, staged artifacts, display policy, runtime `++VTINFO++`
and INI section matching. Decide explicitly whether the short key denotes
an exact board or a reusable display group; retain a separate key if those
roles ever diverge. Migrate aliases deliberately so existing host commands,
artifacts and cards do not silently select another target.

Next Stage 1 work is root-sketch runtime/boot ownership, explicit build-mode
composition and the separate 7XF CCP. RunCPM-derived core hooks still require
their own seam review and Petr's direction before editing.
