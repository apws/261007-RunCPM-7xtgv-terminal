= INI-owned application profiles
:leveloffset: +2
:source-highlighter: highlight.js

== Decision and scope

Petr reproduced strange TE cursor/Backspace behavior after moving complete,
unique bank sections to match the language ordering on drive B. Source inspection
confirmed that slot 7 inherited MBASIC/VTESTS behavior, despite its TE name and
explicit WordStar keys. The earlier
link:260917-20%20profile%20bank%20coupling%20review%20note.adoc[bank coupling review]
had documented this inheritance; it is now removed.

Petr directed that application settings belong in INI and that numbered slots
remain flexible. The additional audit covers global, display and palette sections.
This follows the
link:261009-1854%20DONE%20EP4_10%20rebuild%20and%20history%20regression%20retest.adoc[desktop/history checkpoint].

== Implementation

* Removed the ten application-name/key tables and all numbered-bank application
  initialization from `history_profiles.cpp`. Every slot has a generic `Bank N`
  label, inactive navigation keys, no adapter/commands/prompt tracking and no
  history-clear/retype settings. Shared neutral member defaults remain.
* Application identity and behavior come solely from the complete `[bankN]`
  section. Names do not infer behavior. Explicit protocol presets remain
  available through `input=ansi|vt52|wordstar`; they are not assigned by slot.
* Added `[global] ccp_bank=0..9|none`. Missing means disabled. The working card
  explicitly selects 0. CCP effective-bank routing, native recall/Home/End,
  launcher-row guards, boot selection/geometry and the 125-character CCP
  submission boundary use the configured slot. Later configuration loads
  preserve the selected application. Explicit `home=none`/`end=none` remain
  inactive even at the CCP prompt.
* Migrated missing active settings into the current working INI according to
  application identity, rather than copying the old accidental slot inheritance.
  No existing active assignment was altered. The original section order,
  CRLF formatting and trailing Ctrl-Z remain. No empty/false fallback boilerplate
  was added to each bank.

== Other INI sections

* `[global]` starts with common terminal/storage/UI fallbacks, not per-slot
  application values. Bank bindings override global bindings explicitly.
* The matching `[display:HALID]` overlays the selected HAL's geometry and timing
  fallbacks; unmatched display sections are ignored. Validation retains board
  backing-store bounds. No HAL file was edited.
* All palette slots independently begin with the same PAPER theme. They do not
  inherit another numbered palette's edits or have separate slot-specific themes.

== Delivery and recovery

Pre-change source/INI/BUF copies and a complete card SHA-256 inventory are under
`/tmp/xtgv-neutral-profiles-before`. Only the authorized local INI changed on the
working card; BUF and snapshots remain untouched. Existing sessions were neither
stopped nor reloaded. The current session keeps its old in-memory settings until
restarted with the rebuilt executable. The INI's new `ccp_bank` setting requires
this updated loader.

No RunCPM CCP/BDOS/CPU, board HAL, MCU artifact, physical card, flash, commit or
push changed. COMAL installation/testing remains a separate pending card task;
callable helper binaries and richer BASIC/COMAL scripting remain hypothetical.
