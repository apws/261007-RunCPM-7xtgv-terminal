:source-highlighter: highlight.js

== Implementation

Temporary `RUNCPM_TRACE_SAVES=1` is enabled only in the RP2_147 target JSON.
Other targets compile without timing capture or output. No INI setting,
new guest command, SD log or transfer is involved. Remove the flag after
diagnosis; the instrumentation is reusable on RP2_2 if comparison is requested.

Both existing storage polls capture microsecond durations without printing
while the terminal is paused. After `terminalPause(false)` acknowledges
resume, they enqueue ordinary terminal output, visible on TFT and mirror.
The printed total excludes the reporting itself and autosave debounce delay.
It includes acquiring/releasing the pause and the storage transaction.
Unsigned subtraction handles microsecond-clock wrap for these short intervals.

Example layout (illustrative values, not device measurements):

----
SAVE CFG OK bytes=14923 total=4012ms
 wait=1 open=10 write=3800 ms
 flush=100 verify=20 ms
 replace=80 resume=1 ms
----

`CFG` is INI/settings; `HIST` is the complete retained history file.
`OK/FAIL` reports the existing save function's result, without strengthening
or weakening its checks. `SKIP` means a config save ceased being due between
the first due check and terminal pause. Bytes is the replacement file's
reported size before close, not cumulative physical sector traffic.

Stages:

* `wait`: terminal pause acquisition.
* `open`: temporary-file cleanup and opening source/destination as applicable.
* `write`: serialization or INI copy/update (including its existing source
  existence check); no altered buffering.
* `flush`: existing flush/close calls, including source close for config.
* `verify`: existing reread checks and verification-file close.
* `replace`: backup/delete/rename/rollback path; config completion bookkeeping.
* `resume`: terminal resume acknowledgement.

History completion bookkeeping and final activity pulse/report are outside
the measured interval. The two original transaction orders and file-safety
checks are preserved. Reports may move the visible prompt because they are
temporary diagnostic output; no bytes are injected into CP/M keyboard input.

== Host validation

All76 Python tests pass. The new test extracts the actual production save
poll functions, compiles them with fake storage with tracing off/on, and
checks identical storage-operation sequences for success, write failure and
config recheck/skip. Its output sink asserts the terminal is never paused
when diagnostic output is emitted. A C++ helper test verifies stage arithmetic,
clock wrap, total/format and failure output. No hardware measurement yet.

== Deployment and user test gate

Changes are not rebuilt or flashed. On a requested rebuild and separate
manual BOOTSEL flash:

. After startup, allow any initial save report to finish.
. At CCP enter one simple command, then wait several seconds without typing.
  Capture the `HIST` timing report (and any `CFG` report).
. Change backlight by one level, stop touching keys, and capture the `CFG`
  report after its pause.
. Note whether more reports/freezes recur when left completely idle.

No extra VTDRV run is necessary. Do not clear history, alter the card,
disable verification or optimize either save path before reading the results.
