= Quiet target workflows and legacy build archive
:source-highlighter: highlight.js

== User-facing launcher output

All six target launchers now suppress compiler/uploader chatter by default.
They print module, detailed-log path, build started/completed, selected firmware
directory and image, embedded build stamp when uniquely identifiable, upload
started/completed and mirror-launch status.
Failure prints the log path and last 15 lines; no success message follows a
failed step. `--verbose` restores live CLI output (the retained log then records
commands, not a duplicate transcript of that live output).

Detailed logs are under build/RunCPM_7xtgv-terminal/TARGET/logs/.
Images remain under TARGET/new/, or current/ as upload-only fallback.
Default launch builds; --build-only and --upload-only remain separate operations.
No automatic promotion. The script's mirror-launch success is not proof that
the device is responsive: verify its boot Build line or VTINFO.

C6 prints an explicit hardware RESET reminder after successful upload if the
panel remains blank. Its observed reset behavior differs from other tested
modules; the cause has not been established, and no blind retries are added.

Petr reports his launcher attempt uploaded and reopened the mirror; hardware
RESET produced a redraw, but he suspected an old build. Read-only inspection
found new C6 image stamp 261004-1849 and archived previous image 261004-1109.
The actual device stamp was not independently obtained; do not claim the
staged timestamp proves the flashed/running build.
