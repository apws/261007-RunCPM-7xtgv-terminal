= RP2_2 backlight minimum duty 3 trial
:source-highlighter: highlight.js

Follow-up to link:260925-00%20RP2_2%20INI%20initialization%20stack%20repair.adoc[the boot repair and first curve trial].

Petr reports that about level 3 on the deployed 260925-0045 curve is the lowest
usefully readable full-color setting. On that table level 3 is PWM duty 3.
Photos show VTPAL PAPER at both pan edges, at full backlight and at this low
setting. Camera ISO differs (50 versus 200), so they are not a calibrated
brightness comparison. Low settings are intended for dark surroundings.
Some light-theme color contrasts remain imperfect but are accepted for now;
no palette adjustment was requested or made.

Requested change: make logical level 1 use duty 3 and redistribute the remaining
lit levels up to full ON=255, retaining gamma 2.2 and unique ascending steps.

[source,text]
----
duty(0) = 0
duty(level) = max(level + 2,
                  3 + round(252 * ((level - 1) / 30)^2.2)), level = 1..31

0, 3, 4, 5, 6, 7, 8, 10, 13, 17, 21, 25, 31, 37, 43, 50,
58, 66, 75, 85, 95, 106, 118, 130, 143, 157, 172, 187, 203,
220, 237, 255
----

Only the RP2_2 HAL table changes. W535 retains its minimum 1 curve; W550 retains
its minimum 51 table. All values are normalized 8-bit duties before polarity,
not percentages of perceived luminance. No floating-point calculation is added
to firmware runtime. INI, palette RGB, saved logical brightness and other device
state are untouched; after flashing, the same saved level uses the new curve.

All six target/polarity host checks pass, covering endpoints, strict monotonicity,
startup hold, ramps, timer wraparound and cancellation. The updated test checks
each module's own minimum and rescaling formula. Rebuild requested; flash is a
separate manual BOOTSEL step. Visual acceptance of the recalculated curve remains
pending, especially the new level 1 and spacing through levels 2..10.
