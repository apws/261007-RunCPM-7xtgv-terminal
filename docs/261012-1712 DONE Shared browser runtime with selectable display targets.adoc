= Shared browser runtime with selectable display targets
:source-highlighter: highlight.js
:toc:

The standalone page now selects all six current display targets from one
compiled Wasm runtime. Choose *Target*, then *Switch target*. RunCPM stops
cleanly, saves its memory card and starts a fresh instance with the selected
board's identity, INI section, geometry and backlight table. Save guest work
before switching; application execution state is not migrated.

== Configuration and boundaries

The catalog compiles the data sections of the existing complete board headers
inside separate namespaces. Desktop guards suppress physical driver code.
There is no parallel JSON geometry catalog, C++ text extraction or duplicated
board policy. The page obtains its choices directly from the compiled module.

`desktop/web/board_profiles.h` derives maximum backing capacity from that
catalog (currently 213 columns by 80 rows). Terminal indexing retains this
fixed stride, while parser and renderer validation use the selected board's
logical limits. Native and Arduino builds retain board-specific allocations.
No physical board header or RunCPM CPU, CCP, BDOS or disk code changed; the
configuration guard merely permits web runtime selection without a fixed
compile-time board macro.

The descriptor is locked before startup. Web terminal defaults are rebound
before display creation, then normal INI loading applies the selected section.
The existing C++ terminal, Arduino_GFX, worker and storage code remain in use.
Browser display scale stays an explicit integer; switching does not stretch
or automatically shrink a panel. Choose 1x for the large EP4_10 display.

and stopped-card restart preserve it. The retained external-terminal proof
continues to start ES3_35; native desktop builds remain per-board.

== Keyboard focus correction (261012-1718)

Petr found that clicking the display removed the green capture outline. The
pointer handler focused the input, but the browser's default mouse action then
blurred it again. Primary display presses now prevent that default action and
retain input focus. Startup, guest REBOOT, restart and target switching also
focus the keyboard automatically; page controls and Ctrl+] still release it.

Focused Chromium checks use real pointer clicks, repeated clicks, release and
recapture, actual guest typing and all four startup paths. They pass alongside
composition/AltGr/paste and DPR 1/1.25/2 checks in
`desktop-web/sessions/browser-edges-dxwuwrn3/`. JavaScript-only correction; no
C++ rebuild. A fresh corrected page leaves older volatile sessions untouched.

Petr confirmed the keyboard-focus correction with "yes, good now :-)" and
then authorized commit/push. This confirms focus behavior in the current
interactive setup; it does not add a separate all-target manual test report.
