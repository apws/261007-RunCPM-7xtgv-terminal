== Scope and decision boundary

The maintainer requested a deep comparison of the working card with supplied
Mockba and Guido archives, motivated by confusing flat folders and scattered
project helper sources. The maintainer agrees that combining A4/A5 is sensible.
This checkpoint records evidence and a proposed layout, *not a completed move*.

* Card contents, catalogs, INI, binaries and host build scripts were not changed.
* Concurrent maintainer edits are present: new catalogs, Lua removal, dBase
  relocation from AE to AD, and other removals. These are preserved.
* Counts describe this working-tree snapshot, not HEAD or a permanent seed.
* Names below use `name (DU)`. Names are catalog aliases; the actual filesystem
  remains RunCPM's `A/0` through `A/F` layout.

== Why A4/A5 should be reunited

=== Concrete dependencies

[cols="2,3",options="header"]
|===
|Source/build script in A5 |Dependency currently elsewhere
|`ZCPR2.ASM` |`MACLIB Z2HDR`; `Z2HDR.LIB` is in A4.
|`ZCPR3.ASM` |`MACLIB Z3BASE` and `MACLIB Z3HDR`; both libraries are in A4.
|`BDOS.SUB`, `CCP.SUB`, `Z80CCP.SUB`, `ZCPR2.SUB`, `ZCPR3.SUB` |Invoke MAC and MLOAD; those COM files are in A4, not A0 or A5.
|`ABDOS.SUB` |Names `ABDOS` as the assembler input and uses MLOAD. There is no current `ABDOS.Z80`; A0 contains `.ORG`, HEX and system images.
|===

* The CCP's shared-command search checks the current area and A0; it is not
  a general search of every user area. It does not make A4's tools available
  from A5 merely because both are on drive A.
* Program lookup is separate from an assembler opening its include files.
  Ordinary MACLIB/INCLUDE references need their companion library files in
  the expected working area; a 7XF alias does not change this.
* Reuniting the package is therefore functional cleanup, not just naming.
* `CLEAN.SUB` deletes broad patterns including HEX, PRN, SYM, BAK and BIN.
  Do not run it on the mixed working card; test builds in disposable copies.
* These alternate CCP/BDOS sources are guest-side build/reference material.
  They are not the C++ `ccp7xf.h` used by the current firmware, and moving
  them does not change the selected firmware CCP.

=== Why VT100/VT52 ended up there

Commit `cf10597` (260918) added A0 executables and A5 sources under the old
`cpmdrive/A5 - CP-M sources and build files` convention. The placement was
deliberate at that time, but that broad source bucket was not maintained
consistently for later helpers.

* `VT52.Z80` emits `ESC[?2l`; `VT100.Z80` emits `ESC<`, then returns to CCP.
* They are project additions, absent from both supplied archives.
* The historical record explicitly describes their A0/A5 installation:
  link:260917-18%20terminal%20legacy%20compatibility%20implementation%20checkpoint.adoc[legacy compatibility checkpoint].

== Project sources and duplicate-version hazards

[cols="2,3",options="header"]
|===
|Current source location |Families
|A0 |CARDMARK, REFLASH, UNSUB, VTINFO, VTPAL, VTZOOM, ZOOM; also obsolete VTDRV.ASM and retained build outputs.
|A4 |Older VTDRV.Z80 and VTDRV.COM.
|A5 |VT100.Z80, VT52.Z80; local SPEED.Z80 needs its provenance/build role preserved.
|A6 |GCLS, GPIX, SYNC, VTG100, VTPAD, VTSTART, VTSTOP; third-party/adapted Brot sources must be distinguished from original project code.
|`tools/vtbench/` |REBOOT, VTCPU, VTCPU8X, VTDRV, VTDRV8X, VTTERM source files and some built COM copies.
|`tools/cpm-transfer/` |VTGET/VTPUT sources, `common.inc`, COM copies and the host protocol tool.
|===

=== VTDRV is a real conflict, not harmless duplication

* A0 `VTDRV.COM` is 1152 bytes; A4 `VTDRV.COM` is 896 bytes. They differ.
  The A4 copy can shadow the shared command when invoked from A4.
* A0 `VTDRV.ASM` describes the old cyclic MBASIC-file read test and contains
  *Z80 mnemonics despite its .ASM name*. DRI ASM is not the right assembler.
* A4 `VTDRV.Z80` describes retained-fixture RW behaviour without the current
  quiet-mode options. The current host source has W/RW/Q and capability checks.
* The checked-in host `tools/vtbench/VTDRV.COM` is yet another different binary
  (769 bytes). Source currency does not establish binary currency.
* VTDRV8X's tool/card COM copies also differ beyond simple record padding.
  Rebuild and compare in isolation before selecting deployment copies.

=== Other duplicates and missing partners

* ASM.COM is identical in A0/A4/A6; Z80ASM.COM is identical in A0/A4.
* TE.COM is identical in A0/A6; MBASIC.COM is identical in A0/A7.
* FRAROUND and the two Star Trek examples are duplicated identically in A0/A7.
* Turbo executable/message/overlay copies match between A0/A2, but
  *TINST.DTA differs*. Preserve both configurations until their purpose is known.
  Do not assume shared COM lookup also finds every application's overlays/data.
* VTGET/VTPUT and VTCPU/VTCPU8X card binaries match their host copies plus
  record padding. VTTERM matches exactly.
* A0 has ZOOM.ASM but no ZOOM.COM in this snapshot: the manual cannot assume
  that every documented helper is currently installed.
* Repeated `VTDRV.$$$` files are benchmark fixtures, not program sources.
  They are not automatically unwanted; plain read-only VTDRV uses them.

== Proposed layout, awaiting the complete move decision

Avoid renumbering the established application/test areas. Give each area one role.

[cols="1,3",options="header"]
|===
|Proposed name (DU) |Role
|`cpm (A0)` |Shared installed commands and required configuration/catalog/history state. Deploy approved helper COM outputs here; no helper source/HEX/PRN workspace.
|`cpmdev (A4)` |Combined upstream assembler/debugger/CCP/BDOS development package, including required libraries, SUB files, source and relevant reference documents.
|`xtgvsrc (A5)` |One authoritative project guest-helper source/build workspace. Gather sources, includes and build instructions; HEX/PRN/COM here are build products, not an additional public command installation.
|`xterm256 (A6)` |Runnable graphics/benchmark demonstrations, Brot sources/scripts and their specific assets. Shared project helper commands can resolve from A0 after verified deployment.
|`mbasic (A7)` |BASIC runtimes/examples and the VTESTS suite; no need to separate these familiar tests during this cleanup.
|`comal (A3)` |Reserved future demo area. Catalog must say reserved/not installed until a runtime and demo are actually supplied and tested.
|A1, A2, AD, AF |Keep BBC BASIC, Turbo Pascal, dBase and FAND in their established areas; preserve application-specific configuration/data.
|===

Names are proposals, each within the eight-character 7XF limit.
Combining upstream A4/A5 frees A5 for our sources without allocating another DU.

=== One source of truth, explicit deployment

* Prefer card A5 as the authoritative guest-source workspace, matching the
  maintainer's request. Host Python tools remain in `tools/` but read those
  sources instead of maintaining separate editable copies.
* Preserve the transfer helpers' include file and assembler dialect. A suffix
  is not enough to select arbitrary host z80asm implementations; existing
  scripts/readmes distinguish SLR, Albert Veli and z88dk usage.
* Each helper build must identify source, assembler, output and A0 destination.
  This small build/deployment list is not a new inclusion filter for the card.
* Default build/test uses a disposable card. Copy approved COM output to A0
  only with an explicit install action; physical-card transfer stays separate.
* Reconcile old variants before removal. Do not pick a winner just by mtime,
  extension or file size, and do not silently overwrite a differing binary.

== Safe implementation order

. Agree the A4/A5 roles and aliases; close desktop/card writers before moving.
. Record hashes and a recoverable snapshot outside the live card. Keep the
  two reference ZIPs out of any accidental all-card publication commit.
. Reunite upstream dependencies in A4, retaining notices and comparing any
  conflicting names rather than overwriting them.
. Gather/reconcile our sources in A5, with one maintained version and clear
  assembler instructions for each helper.
. Update builders/tests to separate source workspace, temporary build output
  and explicitly installed A0 commands. Remove implicit installation paths.
. Build/test disputed helper versions on disposable cards; compare results
  before changing the live A0 command set.
. Update current catalogs, guides, card README and third-party location notes
  together. Do not rename DUs in protocol examples where aliases are unsupported.
. Test named CD/LS, shared-command lookup, transfers, benchmark and VTESTS
  startup in desktop. Physical-card deployment/retesting is a later action.

No alternate CCP builds or guest programs were executed during this audit.
Hash/source/dependency checks do not claim that an upstream CCP currently builds
successfully or that every existing COM matches its colocated source.
