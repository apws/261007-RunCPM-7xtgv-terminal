== Implementation

* Shared `tools/terminal.py` accepts an explicit `LoopbackEndpoint` while retaining
  its Linux serial/PTY route. Keyboard, host controls, mirror and transfer panel
  are shared. The owner supplies a child-exit callback; TTY-loss cleanup still
  closes the data connection. Desktop endpoints cannot configure an uploader.
* `tools-win/windows_run.py` opens Mintty and runs an owning MSYS Python process.
  It authenticates the separate control socket, runs the mirror, requests STOP
  on close and waits for cooperative native cleanup. Guest exit 75 restarts on
  the same card in the same Mintty; explicit owner close wins. The Windows path
  does not use tmux or attach to a Linux/hardware session.
* Per-session Mintty settings derive key IDs from the shared firmware header.
  Navigation/function/special keys and established global exit/clear/view controls
  are mapped. F11 is fullscreen, Alt+F4 closes Mintty; Pause supplies the mirror
  prefix. Ordinary Windows text entry remains layout-owned. Konsole's positional
  Czech main-row/keypad remaps are not implemented by this initial profile.
  Native physical keys, AltGr and emergency-chord behavior need acceptance.
* All six source target folders now include `desktop-test.cmd`,
  `desktop-local.cmd`, `desktop-card.cmd` and `desktop-mirror-proof.cmd` alongside
  rebuild/smoke/connection-proof launchers. Test creates a complete retained copy
  of the working card. Local opens the canonical card read/write; card requires
  an explicit root. These do not rebuild, install packages or access MCU hardware.
* New Linux/Windows launches use a per-card atomic-directory lock. An existing
  participating owner blocks a second writer. Normal close releases its lock;
  an unresponsive child retains it. Older already-running sessions have no such
  lock and must be closed before sharing their card with a new writer.
* Session logs, status, emulator generations and copied cards stay below the
  target build's `sessions` directory. The transfer panel uses a separate local
  `transfers/DU` tree there, protecting the working card during acceptance.

The initial Linux mirror tests exposed two fixture assumptions: profile selection
suppresses input during the one-second notice, and the existing transfer-screen
parser expects 80x24. Tests now wait after selecting bank 9 and configure their
disposable terminal geometry. The earlier connection proof selected `CSI >33v`
(End), not bank 9; it now uses `CSI >29v` plus the notice wait. Earlier results
remain evidence of connection/storage behavior on disposable cards, not proof of
bank-9 selection. No live INI/history was changed to accommodate tests.
