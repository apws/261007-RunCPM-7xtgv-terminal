= Technical document navigation and naming
:source-highlighter: highlight.js

`docs/` contains chronological technical records alongside maintained manuals.
Historical notes describe the state at their date; they are not automatically
current implementation instructions.

== New chronological records (agreed 261006)

[cols="1,3",options="header"]
|===
|Filename |Purpose
|`YYMMDD-HHMM CHAT Title.adoc` |Discussion and rationale. Attribute each speaker; preserve Petr's comments in literal blocks. State the transcript's scope and any omissions or editorial normalization.
|`YYMMDD-HHMM PLAN Title.adoc` |Consolidated decisions, implementation sequence, boundaries and acceptance checks. Link the supporting CHAT and prior evidence.
|`YYMMDD-HHMM DONE Title.adoc` |Work actually completed and tested, artifact/recovery commands, remaining work and link to the controlling PLAN.
|===

Use the actual local creation/checkpoint time, with minutes where the sequence
matters. Same-prefix CHAT and PLAN sort in that order; subsequent DONE records
use their later timestamp. Do not label proposals DONE. A partial checkpoint
may have a DONE record only when its title/scope and outstanding work are clear.

Canonical documents remain AsciiDoc with a level-zero title and
`:source-highlighter: highlight.js`. Keep tables properly delimited and render
new or structurally changed documents before handoff. Do not mass-rename older
documents or rewrite earlier discussions to make them agree with later decisions.
Future SPEC records may capture stable specifications; none are required merely
to create a plan.
