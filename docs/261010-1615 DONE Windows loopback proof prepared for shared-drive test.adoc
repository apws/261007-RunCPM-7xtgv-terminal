== Implemented transport and proof

The new `desktop/serial_loopback.cpp` provides an optional local socket
transport on Windows and Linux. The ordinary Linux launcher still uses the
unchanged PTY route. Windows links Winsock; no RunCPM core or HAL was edited.
`--loopback-token` explicitly selects the new transport; the application emits
a JSON `LOOPBACK=` endpoint with data/control ports on standard output.

Both listeners bind to 127.0.0.1 with OS-assigned ports. The launcher supplies
a fresh 256-bit random token; each socket authenticates with a bounded
`XTGV/1 TOKEN` line before carrying data or control. The handshake expires
after five seconds. Missing initial ownership requests stop after 30 seconds.
Unauthenticated input never reaches the guest queue.

Guest data and owner control are separate streams. Only the control channel
accepts `STOP`; the same bytes on the data stream remain data. Queues retain
the existing 16384-byte input and 65536-byte output limits, with nonblocking
partial I/O and backpressure. Data disconnect clears stale queued data and
permits reconnect/snapshot while the owner remains connected. Control loss
requests cooperative stop. An observed owner stop takes precedence over a
guest reboot result. No ordinary control action kills the emulator process.

`desktop/tests/loopback_proof.py` and the transport-only `xtgv_loopback_echo`
fixture test mixed terminal/socket select and descriptor I/O, bad-token
rejection, 262149 exact bytes including NUL/high-bit values and STOP text,
fragmented transfers, real guest commands, BDOS punch output, reconnect,
idle/compute/flood stops, owner disconnect, guest EXIT and REBOOT, and history
save after shutdown. The runner also executes the five portable C++ tests.
Its forced-kill fallback applies only to a failed, owned disposable test;
normal shutdown uses the control socket.

Each target folder now has thin `desktop-rebuild.cmd`, `desktop-smoke.cmd`
and `desktop-proof.cmd` wrappers. The smoke launcher provides the short visual
boot test beside the rebuild launcher, without visiting build output.
All implementation is shared. The proof creates fresh cards beneath
the selected output's `proof-cards` directory and directs host-storage test
temporary files there too. Console/process logs, raw mirror samples and fixture
files remain available; `proof-reports` holds a ZIP of each run's evidence.
`--fixture-dir` and `--report-dir` allow explicit alternative test/report paths.
The normal interactive mirror, Mintty mappings and owning launcher are still
pending. No claim of native mixed-select support is made before the guest test.
