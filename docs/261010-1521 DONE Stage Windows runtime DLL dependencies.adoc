== Change

`tools-win/windows_build.py` now scans PE imports with the installed UCRT64
objdump after compilation. It resolves dependencies recursively from that
toolchain's bin directory, then refreshes the DLLs beside every built
`xtgv_*.exe`. System32 libraries and Windows API sets are left to Windows.
Unknown dependencies fail the rebuild rather than reporting a complete build.
Old output copies and arbitrary PATH directories do not supply dependencies.
`build.log` records the copied DLL sources and destinations.

Only the shared Windows build adapter changed; no target launcher, Linux build,
core, card or running session was changed. Rebuild does not install packages.
The Windows README now explains DLL staging and the card-free `--describe`
startup check. No global Windows PATH change or MSYS2 reinstall is required.

== Checks and remaining gate

* Eight offline tooling tests pass, including transitive dependencies, cycles,
  case-insensitive import names, stale-copy refresh, system-library exclusion
  and rejection of missing dependencies despite an old output copy.
* The actual seven EP4_10 cross-built PE executables were scanned in a temporary
  directory with the real cross-toolchain objdump. The resolver staged SDL2.dll,
  libgcc_s_seh-1.dll, libstdc++-6.dll and libwinpthread-1.dll. Windows system
  filenames were represented by fixture entries; no Windows execution occurred.
  Receipt: `/tmp/xtgv-win-first/runtime-staging.log`.
* Native MSYS staging and executable startup still need Petr's Windows check.
  Copy the updated `tools-win/windows_build.py` into the guest, rerun the same
  target rebuild, then run `xtgv_desktop.exe --describe` in its output directory.

Guest/storage/SDL execution on a disposable card remains the next runtime gate.
The interactive Windows mirror and cooperative launcher lifecycle remain
