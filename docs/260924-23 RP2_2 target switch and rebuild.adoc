== Small build-tool correction

The common dispatcher formerly rejected `bootsel-uf2` even with `--build-only`.
It now permits that offline build/stage path, using the selected Arduino
profile, preserved build flags and a fresh boot stamp. Build-only does not
resolve or open a serial port. Normal upload, build-and-upload, promotion/upload
and restore/upload remain rejected for BOOTSEL targets.

Petr confirms this module requires *manual BOOTSEL*. Do not attempt automatic
reset into it. Firmware upload remains a separately requested manual workflow;
this change does not integrate RP2350 upload into the identity guard.

== Subsequent manual flash and startup failure, 260925

On Petr's explicit reflash request, mounted the user-entered RP2350 BOOTSEL
volume, checked INFO_UF2 and the candidate hash above, stopped the shared mirror,
and copied the 601,600-byte UF2 successfully. BOOTSEL disconnected and the same
RP2350 returned as USB serial. The visible RP2_2 mirror was relaunched, but both
TFT and mirror stayed black/blank with the card inserted. No INI/history files
were uploaded or modified by the host. Previous CP/M program state was lost
on the firmware restart. Copy completion was not treated as boot acceptance.

Reseating/power-cycling did not resolve it. Petr then reports the latest firmware
boots *without* the card. This isolates the failure to a path exercised with SD,
rather than an unsuccessful UF2 copy or unconditional backlight failure.

Read-only inspection of the exact staged ELF found a definite stack-budget bug:
`HistoryProfiles::defaults(Set &set)` uses `set = Set{};`. Its ARM prologue pushes
36 bytes and subtracts 11,904 + 12 bytes: 11,952 bytes for this frame alone.
Arduino-Pico 5.4.4 allocates only 0x2000 (8,192) bytes for the separately stacked
core 1. `runCPM` calls `terminalConfigBegin` on that core when the INI exists,
which calls `beginLoad` and `defaults`. The no-card path skips this call.

This is strong source/binary evidence for the observed SD-dependent startup
failure; a repaired hardware run is still required to confirm the diagnosis.
Proposed correction: reconstruct/reset the existing configuration set in place,
preserving its default member initializers without creating the large temporary.
Then check the RP-target stack frame and parser tests before rebuilding.
No firmware fix, new rebuild, automatic reset or repeat flash was performed
as part of this diagnosis. Current-state RP2_2 hardware acceptance remains open.

Subsequent approved repair and successful SD boot are recorded separately in
link:260925-00%20RP2_2%20INI%20initialization%20stack%20repair.adoc[the stack repair report].
