== Failure and cause

Follow-up to link:260924-23%20RP2_2%20target%20switch%20and%20rebuild.adoc[the target switch and first flash].
Build 260924-2343 stayed black with SD inserted, while Petr confirmed it booted
without the card. INI loading on core 1 calls `HistoryProfiles::defaults`.
Its `set = Set{};` assignment materialized a large temporary: the staged ARM
ELF showed a 11,952-byte stack frame, exceeding Arduino-Pico's separately
allocated 8,192-byte core-1 stack before accounting for callers/callees.

== Repair and tests

Destroy/reconstruct the existing `Set` in place with placement new, rather
than constructing an assignment temporary. This retains value initialization
and all default member initializers; no palette values, HAL brightness tables,
stack allocation, SD wiring or INI syntax changed.

The new palette test dirties both configuration slots, reloads empty settings
into each, and checks restored global/profile defaults and all ten palettes.
Palette and terminal/parser/keyboard/bounds/fuzz/queue tests passed with
AddressSanitizer and UndefinedBehaviorSanitizer outside the sandbox.

Target-aware build 260925-0011 succeeded. Inspection of that exact ARM ELF
shows `defaults` now uses 36 bytes of saved registers plus 108 local bytes:
*144 bytes*, down from 11,952. This is that function's frame, not a full
call-chain stack high-water measurement.

Program storage: 279,368 bytes; static RAM: 161,324 bytes. The RP2350 profile
still uses Arduino-Pico 5.4.4, Arduino_GFX 1.6.4 and SdFat 2.3.0.

=== Backlight observation and proposed next trial

Petr reports the RP2_2 curve also needs adjustment and suggests W535's curve.
The current RP2_2 HAL still has the original ladder: level 1 is duty *51/255*,
level 30 is 253, and level 31 is 255. It has not inherited W535 tuning.
W535's accepted table starts at *1/255*, follows a gamma-2.2 approximation with
a distinct-step floor, and uses 237 at level 30 and 255 at level 31.

Recommendation: use the W535 table as an RP2_2-only trial, then confirm whether
duty 1 is actually legible on this panel and whether the steps feel even. These
are electrical duty values, not measured percentages of perceived brightness.
If minimum 1 is too dim or steps bunch up, tune the RP2_2 table independently;
do not modify the accepted W535 table or palette RGB values to compensate.
No backlight table, INI or firmware artifact was changed during this checklist
update. Applying the trial and rebuilding/flashing remain a next task.

== Petr's RP2_2 benchmark sample, 260925

Reported while 260925-0011 was still running, before the curve-trial flash:

----
VTDRV write: 32768 bytes in 2779994 us = 11.51 KiB/s
VTDRV read : 32768 bytes in 1082384 us = 29.56 KiB/s
VTDRV verify: PASS
VTCPU active: 13015509 T-states in 565913 us = 23.00 MHz
VTCPU quiet : 13015509 T-states in 565844 us = 23.00 MHz
----

MHz is effective emulated Z80 T-state throughput, not the RP2350 physical
clock. Active/quiet differ by only 69 us in this sample and round to the same
rate; it does not prove that display work is free under every workload.
VTDRV measures the 32 KiB BDOS/storage path, not raw SD bus throughput.
This is user-reported test evidence, not an agent-run repeated benchmark.
Petr recalls W535 at approximately 19 MHz for both VTCPU modes. Compared with
this RP2_2 sample's 23 MHz, that is roughly 21 percent higher effective Z80
throughput. The W535 figure is approximate and conditions were not rechecked;
this is not a controlled cross-target benchmark or a general speed guarantee.
