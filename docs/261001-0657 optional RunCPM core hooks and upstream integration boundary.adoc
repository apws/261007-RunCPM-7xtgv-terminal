The generic names are deliberately *optional hooks*, not a new upstream
interface claim. `++globals.h++` no longer includes the product abort class;
the integrated sketch includes its product hook header before core headers.
The guest-idle persistence callback still belongs to the selected
`++ccp7xf.h++` fork. The full 7XF catalog is not made portable by these hooks.
There is no guest-visible command, INI, palette or display change intended.

== Why the later CP/M 3 source is a separate port

The pinned Mockba snapshot changes `++ccp.h++`, `++cpm.h++`, `++disk.h++`,
`++globals.h++` and the Arduino abstraction for experimental CP/M 3. These
overlap our CCP, console, file-close and abstraction areas. Its CPU loops
have no `++CPM3++` conditionals, but still require an ordinary version diff
before reapplying the poll. The three console checks here match *our current
CP/M 2.2 paths only*; CP/M 3 adds other conditional console operations.
Likewise a hook at our `++_CloseFile++` location does not establish that all
CP/M 3 close paths notify the INI cache. A later port needs path-by-path
review and tests in both `++CPM3=0++` and `++CPM3=1++` configurations.
The 7XF CCP variant is still a separate product-owned copy, not a small
upstream extension or an automatically mergeable patch.

== Would upstream RunCPM fit as a Git submodule?

Technically yes for an *unmodified* upstream checkout, but not as a direct
replacement for our current `++RunCPM_7xtgv-terminal++` tree. A submodule
pins an upstream commit; it does not solve our local edits to core headers or
our full `++ccp7xf.h++` variant. Using it now would require an overlay or
ordered patch series at build time, separate Arduino include-path resolution,
and explicit conflict handling every time the pinned upstream commit moves.
That adds moving parts without removing today's semantic CP/M 3 review.

For now, retain the vendored, provenance-documented recovered-era fork and
its small optional-hook diff. Revisit a submodule, Git fork, or patch overlay
only after a clean pinned-upstream build matrix and a repeatable patch test
show which local changes remain necessary. Do not treat the ignored local
`++RunCPM_comparison++` working tree as source of truth; Petr's copied files
there are intentional comparison material.
