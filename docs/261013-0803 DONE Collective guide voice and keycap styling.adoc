emphasized keys are intended to support fast visual scanning of the guides.

== Modifier-background limitation

The standard AsciiDoc renderer emits plain `<kbd>` elements without
key-specific attributes. CSS cannot select the text labels Ctrl, Alt, Shift
or Fn. Different backgrounds for those names therefore require renderer or
JavaScript tagging first; that extension is not implemented in this CSS-only
change. The writing cheatsheet records the limitation and selector references.

== 261013-0837 follow-up: modifier tagging

We approved using the existing JavaScript helper to classify modifier keycaps.
It now toggles a `modifier` class for exact Ctrl, Alt, Shift and Fn labels,
case-insensitively after trimming whitespace. It leaves text content intact,
works for standalone keys and chords, and can run repeatedly after rendering.
The tagging also works in exported HTML when the helper is loaded there;
the existing heading adjustments remain scoped to AsciiDoc preview pages.

CSS owns the lighter background (`#737373`, versus ordinary keys' `#555`)
through `--mixworx-keycap-modifier-background`. Keycaps move exactly one CSS
pixel higher by setting the offset to `calc(-0.06em - 1px)`; size is unchanged.
This supersedes the CSS-only limitation above. Without JavaScript, the shared
stylesheet still provides uniform dark keycaps.
