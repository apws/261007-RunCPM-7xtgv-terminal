== Conversion details worth retaining

Pandoc 3.10.2 supplied the initial structural conversion. Its default output
required explicit handling for several AsciiDoc rules:

* Numeric or punctuation-leading section IDs use `[id="..."]`, preserving
  the original Markdown anchor identity without hiding the following heading.
* Literal inline code uses monospaced passthrough where required. Without this,
  AsciiDoc can interpret `+^Q^D+` as superscript or replace `+...+` with an ellipsis.
* Inline code adjacent to another word or a plus-sign substitution sometimes
  needs unconstrained delimiters. Significant trailing spaces need the longer
  passthrough form.
* Heading levels were normalized while retaining heading text and order.
  The native-specification A--F implementation stages became subsection
  headings, preserving their labels and paragraph grouping.
* Nested AsciiDoc examples in the Kate plan use distinct outer delimiters.
* Relative `link:` references target editable `.adoc` sources for the local
  browser-extension workflow. A future compiled book/site may choose `xref:`
  and a dedicated publishing configuration.

The earliest hardware brainstorm retains its original wording and line layout
in verse sections, with the memory map in a literal block. It remains historical
evidence rather than a rewritten current specification.
