== Source and optimization verification

Both desktop builds link desktop/storage.cpp, not SdFat. The Windows support
identified in the earlier portability review was the adapter's wide-path native
open, seek/tell and truncate branches. The Arduino-style SD/File facade and
RunCPM callers are shared. Actual Windows and Linux filesystem calls differ.

Sequential 128-byte writes in abstraction_arduino_7xtgv.h first call
_sys_extendfile (append open, size check, close), then open for update, seek,
write and close. Thus 32 KiB involves 512 opens/closes and 256 size queries.
Reads open/seek/read/close per record. Each adapter open resolves the path with
weakly_canonical and checks is_directory before the native open. The adapter
contains no explicit sleep or durable-media synchronization; activity indication
only updates an atomic deadline. No core/common-abstraction edits were made.

Generated ES3_5 compiler commands, including storage, confirm -O2 on both systems:
Linux has -g -std=c++17 -O2; Windows has -O2 -g -DNDEBUG -std=c++17 -O2.
Neither uses -Og. Debug symbols do not cancel optimization.

== Probe and Linux evidence

At Petr's request, tools-win/storage-profile.cmd now builds only a standalone
native diagnostic from desktop/tests/storage_profile.cpp. It includes the real
storage.cpp so the native baseline can call its exact private open/seek helpers.
No production adapter, emulator or SDL behavior changes. The executable/DLLs and
generated data run locally below D:\~tmp\260906-7xtgv; build/results remain shared
under desktop-win/storage-operation-proofs. There is no CP/M card access.

Three trials compare adapter and native-helper record operations, then the same
I/O with one handle retained; every readback verifies all 32768 bytes. Timing
columns separate open, size, seek, read, write and close. A metadata-only row
separates weakly_canonical, is_directory and file_size. The held-handle and native
baselines are diagnostics, not production caching or path-check changes.
Results are API completion times with normal host caching, not durable disk rates.

Strict -O2 Linux compilation, execution and MinGW cross-compilation pass.
Python compilation and shell syntax checks pass. Native Windows execution is
pending the user's storage-profile.cmd run.

The Linux run on the project filesystem is retained at
`build/RunCPM_7xtgv-terminal/desktop-win/storage-operation-proofs/linux-261010-2252/profile.csv`.

project-filesystem evidence. Working cards and running sessions remain intact.
