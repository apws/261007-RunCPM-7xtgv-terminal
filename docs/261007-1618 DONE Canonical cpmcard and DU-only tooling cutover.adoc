== DU-only tooling

Use `cpmcard/A/0` through `cpmcard/A/F`, etc. Hexadecimal host user-directory
names are inherited from *RunCPM*, not introduced by 7XF. `disk.h` builds
the user component with `toupper(tohex(userCode))`; both Arduino and POSIX
abstractions use that convention. CP/M itself has numeric user areas.

`tools/card_paths.py` centralizes the root and transfer mapping:

* Working root: `XTGV_CARD_ROOT`, otherwise repository `cpmcard`.
* Transfer root: `XTGV_TRANSFER_ROOT`, legacy `XTGV_XMODEM_ROOT`, then working root.
* Host selector: `AF:` and decimal alias `A15:` both select `A/F`.
* No descriptive-folder fallback, old-root fallback or implicit DU creation.
* Transfer selection rejects symlinked drive/user directories.
* Missing fixtures explain how to provision the card.

Updated active dependencies: transfer UI, INI fetch/archive helper, VTPAL and
VTINFO/VTZOOM assembly helpers, BASIC tests, VTDRV tests, SDL VTESTS and PTY
lifecycle fixtures, local desktop launcher, current manuals and repository
guidance. The transfer CLI already takes explicit paths. Mounted desktop
cards still require explicit selection. Host transfer DU selection does not
change the device DU.

Two assembler/test helpers formerly installed results unconditionally; they
now require `--install`. VTDRV installs only in A0. Its historical binary
patcher requires an explicit directory and no longer selects live binaries
by default. Tests work on disposable copies, not the working card.

Remaining old-name references are intentional: historical documentation,
the read-only migration audit and its synthetic regression fixture. The old
layout/progress JSON files have no active code consumers and are not the
current card's allocation authority.

== Versioned seed and publication boundary

link:../cpmcard/README.adoc[The new card README] documents the actual layout.
`seed-manifest.json` and `cpmcard/.gitignore` expose an explicit *200-file seed*:

* Project-maintained helpers/sources/tests and development catalogs.
* Additional bytes already present in committed repository CP/M content.
  This preserves repository provenance; it is not a new license determination
  or a grant of redistribution rights for third-party packages.

Live INI/BUF and snapshots, remembered `DRV.7XF` state, personal databases,
editor backups, generated scratch files, the root photograph and unreviewed
packages/configured variants remain intact and ignored locally. FAND-area
personal content is excluded even where an old Git version existed. No Git
history rewrite or remote-content removal was attempted.

`tools/check_card_seed.py` checks the manifest and exports only listed files
to a new disposable directory. It rejects missing/duplicate/invalid paths,
symlinks, existing destinations and exports inside the source card. It is not
a sync, physical deployment or delete tool. Do not force-add the live tree.

The isolated export tests verify the pending seed content, *not a published
fresh clone*. Commit/push and decisions about additional local packages
remain separate. Firmware builds do not install the seed onto SD.

== Catalogs and INFO.TXT

* `DIR.7XF` and `VOL.7XF` are the opinionated developer catalogs for our
  internal 7XF shell. Named paths still resolve to flat drive/user areas.
* `DRV.7XF` remembers runtime selections; it is not versioned seed content.
* Catalogs can describe applications not included in the published seed.
* `VOL` remains the RunCPM `INFO.TXT` command, not a `VOL.7XF` reader.
* `A7:CINF.BAS` prompts for a description and creates/replaces `INFO.TXT` in
  its current DU; empty input cancels. It does not load old text for editing
  or modify 7XF catalogs.
