== One card layout, shared by hardware and desktop

`cpmcard/` is the primary local working card, originally copied from Petr's
shared microSD and subsequently used by the desktop firmware. Its tested
content takes precedence over the retired descriptive `cpmdrive` mirror.
The physical card in a USB reader remains an independent copy: nothing here
automatically synchronizes it or deletes files from it.

Use only RunCPM's actual drive/user layout:

[cols="1,1,2",options="header"]
|===
|DU |Host directory |Meaning
|`A0:` |`A/0/` |Drive A, user 0
|`A7:` |`A/7/` |Drive A, user 7
|`AA:` |`A/A/` |Drive A, user 10 decimal
|`AF:` |`A/F/` |Drive A, user 15 decimal
|`B0:` |`B/0/` |Drive B, user 0
|===

Hexadecimal user-directory names are *RunCPM's convention*, inherited by
this project, not a 7XF invention. CP/M itself has numeric user areas, not
host filesystem directories. Our old `A7 - ...` host folder names are retired.
The host transfer prompt also accepts `A15:` as an alias for `AF:`.

Guest filenames should be uppercase 8.3 names. The host filesystem adapter
remains case-sensitive. Some imported archival material still has mixed-case
names; this migration does not silently rename or rewrite it.

== Current working areas

[cols="1,3",options="header"]
|===
|Name(DU) |Contents
|`cpm(A0)` |Shared installed commands, INI/history and global catalogs.
|`cpmdev(A1)` |Historical CP/M/CCP sources, assemblers and required libraries.
|`mbasic(B1)` |Microsoft BASIC versions and general examples.
|`bbcbasic(B2)` |BBC BASIC package and examples.
|`comal(B3)` |Reserved catalog/placeholder files; COMAL and its demo are not installed yet.
|`tp(B4)` |Complete Turbo Pascal package and examples.
|`7xtgv(C1)` |One canonical home for our guest sources, includes, HEX/listings
and visual BASIC tests. Includes MBASIC for convenient testing.
|`xterm256(C2)` |Mandelbrot variants, SUB scripts and their graphics/timing helpers.
|`bench(C3)` |CPU benchmarks/exercisers and the VTDRV disk fixture.
|`fand(B5)` / `dbase(B6)` |Database packages and data; subsequently moved to B by the maintainer.
|===

* `B0` and `C0` intentionally have no shared commands. Catalog-only placeholders
  are harmless; absent empty folders do not prevent using populated areas
  such as `mbasic(B1)` or `7xtgv(C1)`.
* Keep every A-drive user folder (`A/0` through `A/F`). Empty ones contain
  a `DIR.7XF` placeholder (or a host-only `.gitkeep`) so fresh clones retain
  them. Catalog-only areas are hidden from LS/LL area overviews. The supplied patched
  `SUBMIT.COM` creates its `$$$.SUB` queue on A with the current user number:
  submitting from `xterm256(C2)` therefore also needs `A/2`. A missing folder can misleadingly
  report `Directory Full`; copying SUBMIT into C0 or C2 is not the solution.
* Current CCP unqualified COM lookup is: current DU, then A0, then the
  current drive's user 0 if the original user was nonzero. For example,
  B1 -> A0 -> B0. Explicit drive qualification suppresses the fallback.
* That lookup finds the executable, not its includes, overlays or data.
  Keep complete language packages and historical build dependencies together.
  The deliberate A0 Turbo/editor installation retains its own TINST settings.
* Uppercase host folders such as `B/1` are sufficient; no disk-image format
  is needed. A named `CD /B/mbasic` additionally needs the area's `DIR.7XF` alias.
* Shared installed COM files stay in `cpm(A0)`. Build from `7xtgv(C1)` in a disposable copy,
  then explicitly install the tested result. Imported Brot sources stay with
  their demos in `xterm256(C2)`; `BROTINFO.TXT` explains the BS/PS names and original credits.
* `cpmdev(A1)` combines the former A4/A5 so ZCPR headers and MAC/MLOAD are
  together. This is not acceptance of every old build recipe. `ABDOS.SUB`
  still expects an absent `ABDOS.Z80`; `CLEAN.SUB` deletes build files.

== What Git contains

Petr's decision on 261007: *version the complete `cpmcard` tree*, not a
curated seed. All A--P drive content is included without filename or type
exclusions: applications, sources, configured binaries, catalogs, INI/BUF,
databases, backups and scratch files. The unfinished FAND area is included too.
Host-side `.7xtgvtrm-ini-history/` snapshots are also included. The unrelated
root photograph `IMG_20260908_214304.jpg` was removed on 261008.

The root `.gitignore` explicitly includes `cpmcard/` and everything below
it, overriding generic project filters there. There is no card-local ignore
file or per-file manifest to maintain. The earlier 200-file selection has
been removed. The 261007 checkpoint contained 338 files. On 261008 the
maintainer removed 54 mistakenly included files from `AB:` (Sharp-specific
NC/NU) and `AC:`/`AD:` (GEEK2350/z80pack-related examples and disk images),
leaving 284 versioned files; removing the root photograph then left 283.
These counts are observations, not limits.
This is a content cleanup, not a new ignore rule or partial-card manifest;
all remaining working-card content stays eligible for versioning. Earlier
copies of the removed packages remain in Git history.

After commit/push, a fresh clone receives the committed card files directly.
Git does not store empty directories. On an existing working copy, desktop
use can modify versioned settings/history: stop the desktop before updating,
inspect `git status`, and preserve or commit wanted changes before pulling.
Do not reset away local changes just to make a pull succeed.

This selection is not a new license grant for third-party software. Firmware
builds still do not install files automatically onto a physical card.
For attribution or inclusion concerns, see the
link:../THIRD_PARTY_NOTICES.md#historical-software-and-rights-holder-contact[historical software and rights-holder contact notice],
which directs inquiries to the repository's issue tracker.

[source,bash]
----
# From the repository root: check the complete card, or make a disposable copy.
python3 src/RunCPM_7xtgv-terminal/tools/check_card_seed.py
python3 src/RunCPM_7xtgv-terminal/tools/check_card_seed.py --export /tmp/my-cpm-test-card
----

The command retains its historical `check_card_seed.py` filename, but now
checks/copies the complete tree, including snapshots and history. Export
refuses an existing destination, a destination inside the source, symlinks
and special filesystem objects. Close writers before making a copy. This is
an offline fixture helper, not an SD deployment or synchronization command;
no automatic deletion or filename conversion is provided.

== Catalogs: our opinionated development view

The current `*.7XF` catalogs are the primary, opinionated organization used
by our internal `ccp7xf.h` shell (7XF). They give flat drive/user areas useful
names; slash-style paths do not turn CP/M into a hierarchical filesystem.

* `DIR.7XF`, per user area: area name and file descriptions, used by the
  named catalog commands (`LS`, `LL`, `CD`).
* `A0:VOL.7XF`: descriptions of drives.
* `A0:DRV.7XF`: remembered selection per drive. This mutable runtime state
  is versioned alongside the rest of the working card.
* Describe what programs do, primarily on their `.COM` entries. Do not repeat
  generic explanations of ASM/HEX/Z80 and other extensions on every file.
  Keep useful descriptions of standalone BASIC tests, live configuration or
  specific safety warnings; omit duplicate descriptions of a program's sources.
* LS/LL display filenames as lowercase `name.ext`; this does not rename the
  uppercase host files or change the case-sensitive storage policy.
* Area overviews hide empty areas and areas with only `DIR.7XF`/host dotfiles.
  Their directories and aliases remain available; no files are removed.
  An ordinary marker such as `comal.txt` counts as content and makes its area
  visible; that visibility is not proof of an installed language runtime.

Catalogs describe a developer's working collection. They may mention
applications that are absent or unfinished; they are neither a package
installer nor proof that every listed program is present or working.

This catalog preference *does not remove* RunCPM's `INFO.TXT` convention.
`VOL` still displays `INFO.TXT`; it does not read `VOL.7XF`.
The supplied `mbasic(B1)` `CINF.BAS` asks for one line of text and creates/replaces
`INFO.TXT` in the current drive/user area; empty input cancels. It does not
load an existing description for editing and does not maintain `.7XF` files.
See the link:../guides/reference-guide.adoc[Reference Guide]
for exact catalog layout and command syntax.

== Working configuration and text files

* `A0:7XTGVTRM.INI` and `7XTGVTRM.BUF` are live local settings/history.
  Hardware and desktop can update them. These are intentionally versioned;
  a clone receives the committed settings/history. Do not overwrite newer
  working state from an old mirror. Firmware defaults apply when settings
  are absent; see the manual for INI settings and profile configuration.
* `.7xtgvtrm-ini-history/` holds versioned host snapshots, outside the guest DUs.
  The explicit fetch helper archives the previous local INI before replacing
  it with the requested device copy. It never uploads history automatically.
  Do not fetch over a local INI currently owned by a running desktop instance.
* Authored guest text uses CRLF and a final Ctrl-Z. Maintain that format;
  ordinary transfers preserve bytes. MBASIC sources use `SAVE "NAME",A`.
* Never infer text format from the extension alone. Executables, tokenized
  BASIC, disk images and binary history must stay byte-exact. Existing CP/M
  record padding/tails are preserved, not blanket-normalized.
* This README is host documentation, not CP/M text.

The old `layout.json` and `progress.json` were historical reorganization and
transfer records. No active tool consumes them. Their names and old area
assignments are not current card metadata; they were archived with the retired
mirror rather than retained as current card metadata.

== Tools and tests

* Host fixture tools default to repository `cpmcard`; `XTGV_CARD_ROOT` can
  explicitly select a prepared copy. Missing fixtures produce a provisioning
  message. There is no fallback to the old mirror.
* Mirror VTPUT/VTGET use `XTGV_TRANSFER_ROOT`, then the legacy
  `XTGV_XMODEM_ROOT`, then the working card root. DU selects only the *local*
  `drive/user` directory; it does not change the device's current DU.
* Per-board `desktop-local.sh` uses the working card. `desktop-card.sh`
  requires an explicitly selected mounted card. Both are read/write sessions;
  do not point concurrent writers at one tree.
* Automated BASIC, assembler and SDL tests copy their fixtures into disposable
  cards. Assembly tests do not install their output unless `--install` is
  requested. The old VTDRV binary patcher requires an explicit directory
  containing the historical binary layout; it is not a current build step.
* Shared `VTCPU`, `VTDRV` and related helpers live in A0. Tests need not recreate
  the old A6 duplicates. `VTDRV W` writes a scratch fixture; avoid running it
  on a valuable physical card without intending that write.

Typical visual test: select `7xtgv(C1)` with `C1:`, run `MBASIC`, then
`RUN "VTESTS"`.
The current menu includes separate attribute, VT52 and scroll-region tests;
select 80x24 logical geometry for the scrolling test. Small panels may pan.

== Area reorganization checkpoint

The 261008 reorganization moves the language packages to B and separates
project work on C. Only the language-profile names and `on_select` locations
changed in the local INI; FAND and other profiles, history and physical cards
were preserved. Old commands saved inside history are not silently rewritten.

Current helper sources were consolidated from host `tools/vtbench` and
`tools/cpm-transfer` into C1; host tools/tests now use that single source home.
VTDRV was freshly assembled and tested before installing local A0/C1 copies.
The previously missing ZOOM.COM was also built from C1 and installed locally.
Other retained HEX/PRN/COM artifacts were not all rebuilt by this move.

The complete pre-change snapshot, displaced files, host helper copies and
SHA-256 migration manifests are outside the repository at
`../card-reorg-backups/261008-2102/`. They are local recovery evidence, not
files to deploy to a card. No physical SD card was modified.

The two temporary upstream comparison ZIPs at the card root were left where
the maintainer put them; this move does not approve publishing those imports.
